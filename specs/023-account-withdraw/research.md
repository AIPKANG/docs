# Research: 회원 탈퇴 (023-account-withdraw)

**Phase 0** · 2026-10-08 · 입력: [spec.md](./spec.md), [source-notes.md](./source-notes.md), `docs/13-*`, `docs/44-withdraw.md`, 001 복구 전용 세션, 017·018·022 정리 단계

사용자 지시: 질문 없이 기본값.

## R-1. 신청 (FR-001~FR-018)
- 화면: 블로그 주소, 내 글 수(휴지통 포함), 남의 글에 쓴 댓글 수, 받은 좋아요 합, 복구 기한(지금 + 30일), 잃는 것 안내. 확인 체크 + 비밀번호(이메일 가입) 또는 "탈퇴"(소셜)가 모두 있어야 버튼이 켜지고(`withdraw.js`, 기본 포커스 없음) 서버도 다시 검사.
- 순서: 로그인 401(인증 전 허용) → 관리자 409 `ADMIN_CANNOT_WITHDRAW` → 확인 체크 400 → 잠금 중 429 → 본인 확인 400(5번 실패 15분 잠금, 11 §6-2와 같은 값, `withdraw:fail|lock:{회원}`) → `status='WITHDRAWN'`, `withdrawn_at`. 사유는 묻지 않는다.
- 커밋 뒤 `MemberWithdrawalRequested` → 모든 기기 세션 끊기·접수 메일(복구 기한). 이 기기도 세션을 끝내고 `/withdrawn` 완료 화면(기한·"그동안 … 보이지 않아요"), 로그아웃과 같은 임시 글 정리 플래시.
- 숨김은 이미 있는 공용 규칙: 006 `authorWithdrawn`, 목록 공용 조건 `m.withdrawn_at IS NULL`, 블로그 주인 찾기, 017 알림(받는·하는 쪽 모두 유예면 안 만듦), 014 댓글 "탈퇴한 사용자의 댓글이에요"(행·수 유지), 좋아요 유지, 닉네임·주소는 행이 남아 다른 사람이 못 씀.

## R-2. 복구 (FR-019~FR-025)
- 001 로그인 판정이 유예 회원에게 복구 전용 세션을 준다. 복구 화면에 기한·남은 일수, [복구하기](`POST /account/restore`)를 눌러야 `ACTIVE`·`withdrawn_at=NULL`로 되돌리고 세션 표시를 지워 정상 세션이 된다. 커밋 뒤 복구 완료 메일, 홈에 "다시 오신 걸 환영해요". 비밀번호 재설정·같은 이메일 가입 안내는 001 그대로.

## R-3. 30일 뒤 정리 (FR-026~FR-037)
- `WithdrawalPurgeJob` 매일 03:00 + 004 `JobLock`, 대상 100명씩. 회원마다 `FOR UPDATE`(그사이 복구했으면 건너뜀) 후 `WithdrawalPurgeStep`을 순서대로 한 트랜잭션에서. 실패하면 그 회원만 롤백, 다음 날 다시. 확정 뒤 세션 삭제. 알림 없음.
- 단계: 10 글 전부 완전 삭제(011 `purgeLocked` — 사진 끊김 표시, 남의 댓글·좋아요·알림 CASCADE) · 20 남의 글 댓글(답글부터 삭제 → 답글 남은 최상위는 내용 비운 자리 → 나머지 삭제 → 답글이 다 사라진 자리 정리 → 댓글 수를 실제 행으로 다시 셈) · 30 좋아요(삭제 후 수 다시 셈) · 40 내가 올린 사진 끊김 표시 · 50 로그인 수단 삭제 · 60 팔로우 양방향(018) · 70 알림(017: 받은 것 삭제·묶음에서 빼고 재계산·일으킨 하나짜리 삭제) · 80 대기 신고 "대상 없음"(022) · 90 익명화(닉네임·소개·사진·닉네임 변경 시각·AI 동의·끈 알림 종류·정지 사유/기한 비움, `deleted_at`, 주소 유지).
- 주소는 행에 남아 영구 예약(본인도 재사용 불가), 같은 이메일은 로그인 수단이 지워져 새 가입 가능. 신고자로 남은 신고는 익명 회원을 가리킨다.
