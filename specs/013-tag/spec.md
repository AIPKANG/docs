# Feature Specification: 태그와 태그별 글 목록

**Feature Branch**: `013-tag`

**Created**: 2026-10-07

**Status**: Draft

**Input**: 사용자 설명: "docs/ 원문 문서에서 변환: docs/22-tag.md"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 발행할 때 태그 붙이기 (Priority: P1)

작성자는 발행 설정 창(공개 범위를 고르는 창)에서 태그를 입력한다. Enter나 쉼표로 하나씩 추가하고, 입력하자마자 정리된 모양(`Spring Boot` → `#spring-boot`)을 칩으로 본다. 같은 뜻의 입력은 하나의 태그로 합쳐지고, 입력한 순서대로 글에 표시된다. 규칙에 맞지 않는 태그가 있으면 발행되지 않고 문제가 있는 태그를 모두 알려준다.

**Why this priority**: 태그가 있어야 태그별 목록이 존재한다 (C-TAG-1, Tier B). 정리 규칙은 검색·AI 태그 추천도 그대로 쓰는 기준이다.

**Independent Test**: 여러 형태의 입력(`Spring Boot`, `#SPRING  BOOT`, 전각 문자, `C#`, `c++`, 금칙어, 이모지, 31자, 11개)으로 발행해 저장된 태그·순서·오류 목록을 확인한다.

**Acceptance Scenarios**:

1. **Given** 발행 설정 창, **When** `Spring Boot`, `spring-boot`, `#SPRING  BOOT`, `ｓｐｒｉｎｇ ｂｏｏｔ`(전각)을 입력해 발행하면, **Then** 글에는 `spring-boot` 태그 하나만 붙는다.
2. **Given** `jpa`, `spring`, `회고` 순서로 입력, **When** 발행 후 글 상세를 보면, **Then** 태그가 `#jpa #spring #회고` 순서로 보인다.
3. **Given** `🔥hot`, `a/b`, `ㅋㅋ`, 31자 태그, 금칙어 태그가 섞인 입력, **When** 발행하면, **Then** 발행되지 않고 문제 있는 태그 각각의 위치와 이유(허용되지 않는 문자 / 너무 김 / 금칙어)가 모두 반환되며, 금칙어 태그는 어떤 단어 때문인지 알려주지 않는다.
4. **Given** 중복을 지운 뒤 태그 11개, **When** 발행하면, **Then** 개수 초과로 발행되지 않는다.
5. **Given** 태그를 입력했지만 발행하지 않고 창을 닫음, **When** 다른 기기에서 그 글을 열면, **Then** 서버에는 태그가 저장되어 있지 않다.
6. **Given** 이미 발행한 글을 다시 발행, **When** 발행 설정 창을 열면, **Then** 지금 달린 태그가 순서대로 미리 채워져 있고, 태그만 바꿔 발행해도 "수정됨"이 붙는다.
7. **Given** 두 작성자가 아직 없는 같은 새 태그로 동시에 발행, **When** 둘 다 성공하면, **Then** 그 이름의 태그는 하나만 존재한다.

### User Story 2 - 태그별 글 목록 보기 (Priority: P1)

독자는 글 상세의 `#태그`를 눌러 그 태그가 붙은 공개 글을 홈 목록과 같은 카드·순서·개수로 본다. 상단에 태그 이름과 공개 글 수가 보인다.

**Why this priority**: C-TAG-1의 "태그별 글 목록" 완료 기준 그 자체다.

**Independent Test**: 공개·비공개·임시·휴지통·탈퇴 신청 작성자의 글에 같은 태그를 붙이고 태그 페이지를 열어 공개 글만 보이는지, 글 수가 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** `spring-boot` 태그가 붙은 공개 글 12개와 비공개·임시·휴지통·탈퇴 신청 작성자의 글 몇 개, **When** 태그 페이지를 열면, **Then** "#spring-boot · 공개 글 12"와 공개 글 9개가 처음 공개된 시각 최신순 카드로 보이고 [더 보기]로 나머지 3개가 이어 붙는다.
2. **Given** `c#`, `c++`, `node.js`, `.net`, `스프링-부트` 태그, **When** 각 태그 페이지 주소를 열면, **Then** 모두 정상적으로 열린다.
3. **Given** `/tags/Spring Boot`처럼 정리되지 않은 주소, **When** 접속하면, **Then** `/tags/spring-boot`로 영구 이동한다.
4. **Given** 이모지처럼 형식에 맞지 않는 태그 이름 주소, **When** 접속하면, **Then** 404다.
5. **Given** 비공개 글에만 쓰인 태그와 아무도 쓰지 않은 형식에 맞는 태그, **When** 각각의 태그 페이지를 열면, **Then** 둘 다 정상 페이지에 "아직 이 태그로 공개된 글이 없어요"로 똑같이 보인다.

### User Story 3 - 작성 중 태그 자동완성 (Priority: P2)

작성자가 태그를 입력하면 앞부분이 일치하는 태그를 최대 10개 추천받는다. 내가 쓴 태그가 먼저, 그다음 공개 글이 많은 태그 순이다. 남의 비공개 글에만 쓰인 태그는 나오지 않는다.

**Why this priority**: 같은 뜻의 태그가 여러 갈래로 흩어지는 것을 줄인다. 태그 붙이기(P1) 없이는 의미가 없다.

**Independent Test**: B의 비공개 글에만 `이직준비` 태그를 붙이고 A가 `이직`을 입력해 추천에 나오지 않는지, A 자신의 비공개 글 태그는 A에게 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 작성자가 `spr` 입력 후 0.3초 멈춤, **When** 추천이 뜨면, **Then** `spr`로 시작하는 태그가 내 태그 먼저, 이후 공개 글 수 많은 순으로 최대 10개 보이고 각 태그의 공개 글 수가 함께 보인다.
2. **Given** B의 비공개 글에만 쓰인 태그, **When** A가 그 앞부분을 입력하면, **Then** 추천에 나오지 않는다.
3. **Given** A의 비공개 글에 쓰인 태그, **When** A가 그 앞부분을 입력하면, **Then** 추천에 나온다.
4. **Given** 한글 조합 중, **When** 아직 글자가 완성되지 않았으면, **Then** 추천을 요청하지 않는다.
5. **Given** 정리하면 빈 값이 되는 입력(예: `#`), **When** 추천을 요청하면, **Then** 빈 목록이다.

---

### User Story 4 - 전체 태그 목록 보기 (Priority: P2)

독자는 전체 태그 목록에서 공개 글이 많은 태그 상위 100개를 글 수와 함께 본다.

**Why this priority**: 태그 탐색의 입구. 태그별 목록(P1)이 먼저 있어야 한다.

**Independent Test**: 공개 글 수가 다른 태그 여러 개와 비공개 글에만 쓰인 태그를 만들고 목록 순서·포함 여부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 여러 태그, **When** 전체 태그 목록을 열면, **Then** 공개 글 수 많은 순(같으면 이름 순)으로 최대 100개가 글 수와 함께 보인다.
2. **Given** 공개 글 수가 0인 태그(비공개 글에만 쓰였거나 쓰는 글이 모두 지워짐), **When** 목록을 열면, **Then** 그 태그는 보이지 않는다.
3. **Given** 새 공개 글이 발행된 직후, **When** 전체 태그 목록을 열면, **Then** 최대 10분 안에 글 수가 반영된다.

---

### User Story 5 - 블로그 안에서 태그로 거르기 (Priority: P3)

독자는 개인 블로그 상단에서 그 블로그의 태그와 글 수를 보고, 태그를 눌러 그 블로그의 해당 태그 글만 본다.

**Why this priority**: 블로그 탐색 편의 기능. 공통 범위 안이지만 다른 스토리 없이도 블로그는 동작한다.

**Independent Test**: 한 블로그에 여러 태그의 공개 글을 만들고 태그 줄과 필터 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** 블로그에 여러 태그의 공개 글, **When** 블로그를 열면, **Then** 그 블로그의 태그가 글 수 많은 순으로 처음 10개 보이고 [태그 더 보기]가 있다.
2. **Given** 블로그 태그 줄, **When** `jpa`를 누르면, **Then** 그 블로그의 `jpa` 공개 글만 블로그 목록과 같은 카드·9개·[더 보기]로 보이고 [필터 해제]가 있다.
3. **Given** 정리되지 않은 태그 값의 필터 주소, **When** 접속하면, **Then** 정리된 주소로 영구 이동한다.

---

### Edge Cases

- 맨 앞 `#`은 모두 지우지만 `c#`처럼 뒤의 `#`은 남긴다 (`##jpa` → `jpa`).
- `.net`처럼 맨 앞 `.`은 허용된다. `...`, `---`, `#`처럼 한글·영문·숫자가 하나도 없는 이름은 거부된다. 그래서 `.`·`..`만으로 된 이름은 태그가 될 수 없다.
- 완성되지 않은 한글(`ㅋㅋ`, `ㅅㅂ`)은 거부된다.
- 허용되지 않는 문자는 몰래 지우지 않고 거부한다 (사용자가 의도하지 않은 태그가 생기지 않게).
- 글자 수는 사람이 보는 글자(코드 포인트) 기준 1~30자다.
- 대소문자 변환은 언어 설정에 영향받지 않아야 한다 (터키어 `i` 문제).
- 글이 완전 삭제되어 쓰는 글이 없어도 태그 자체는 남는다. 공개 글 수가 0인 태그는 목록·자동완성에 나오지 않는다.
- 비공개로 바꾸거나 휴지통으로 보낸 글은 즉시 태그별 목록·글 수에서 빠진다.
- 친구 공개 규격을 구현한 팀원이라도 태그별 목록·전체 태그 목록에는 공개(`PUBLIC`) 글만 나온다. 블로그 안 태그 필터는 블로그 목록과 같은 조건을 쓰므로 친구가 볼 때 친구 공개 글도 포함될 수 있다.
- 목록 카드에는 태그를 보여주지 않는다 (목록 조회 비용 유지).
- 오류 칩은 빨간 테두리와 글자로 함께 표시한다 (색만으로 구분하지 않음).

## Requirements *(mandatory)*

### Functional Requirements

**정리(정규화)와 검사**

- **FR-001**: 시스템은 모든 태그 입력(발행, 자동완성 검색어, 태그 주소, 블로그 태그 필터, 그리고 검색·AI 태그 추천)을 하나의 같은 정리 규칙으로 처리해야 한다(MUST). (C-TAG-1)
- **FR-002**: 정리 규칙은 다음 순서여야 한다(MUST): ① 호환 문자 정규화(전각 → 반각) ② 보이지 않는 글자·방향 제어 문자·제어 문자 제거 ③ 앞뒤 공백 제거 ④ 맨 앞의 `#`을 모두 제거 후 다시 앞뒤 공백 제거 ⑤ 언어 설정과 무관한 소문자 변환 ⑥ 공백 묶음을 하이픈 하나로 ⑦ 연속 하이픈을 하나로, 처음·끝 하이픈 제거.
- **FR-003**: 정리된 태그는 완성된 한글·영문 소문자·숫자와 기호 5개(`-` `_` `.` `+` `#`)만 포함하고, 한글·영문·숫자가 1자 이상 있으며, 1~30자(코드 포인트)여야 한다(MUST). 위반 시 허용되지 않는 문자는 `INVALID_TAG`, 30자 초과는 `TAG_TOO_LONG`으로 거부해야 하며 문자를 몰래 지우지 않아야 한다(MUST).
- **FR-004**: 태그에는 닉네임과 같은 금칙어 필터(변형 포함)를 적용하고, 걸리면 `TAG_BANNED_WORD`로 거부하되 어떤 단어인지 알려주지 않아야 한다(MUST).
- **FR-005**: 한 글의 태그 목록은 정리 후 같은 이름이 있으면 처음 나온 것만 남기고, 남은 입력 순서를 표시 순서로 저장해야 한다(MUST).
- **FR-006**: 한 글의 태그는 중복 제거 후 0~10개여야 하며(기본 10, 설정값), 넘으면 `TOO_MANY_TAGS`로 발행을 거부해야 한다(MUST).
- **FR-007**: 태그 검사에 실패하면 발행하지 않고, 문제 있는 태그를 **모두** 각각의 위치·이유 코드·입력값과 함께 돌려줘야 한다(MUST).

**입력과 저장**

- **FR-008**: 태그 입력은 발행 설정 창에서만 받아야 하며, 태그는 발행할 때 확정되고 자동 저장 대상이 아니어야 한다(MUST). 발행하지 않고 닫으면 서버에 저장하지 않아야 한다(MUST).
- **FR-009**: 입력 칸은 Enter 또는 쉼표로 태그를 추가하고(띄어쓰기는 나누지 않고 하이픈이 됨), 정리된 모양을 즉시 칩으로 보여주며, 칩의 × 또는 빈 입력칸에서 Backspace로 삭제, 끌기 또는 키보드(초점 + `Alt` + 방향키)로 순서를 바꿀 수 있어야 한다(MUST). 화면 정리는 안내용이며 서버가 다시 검사해야 한다(MUST).
- **FR-010**: 다시 발행할 때는 지금 달린 태그를 순서대로 미리 채워야 하고, 태그만 바꿔도 다시 발행으로 처리해 "수정됨"이 붙어야 한다(MUST).
- **FR-011**: 발행 시 글의 태그는 새 목록으로 통째로 교체해야 하며, 같은 새 태그로 동시에 발행해도 태그는 하나만 생겨야 한다(MUST).
- **FR-012**: 태그 자체는 쓰는 글이 없어져도 지우지 않아야 한다(MUST).

**태그별 글 목록**

- **FR-013**: 태그별 글 목록은 그 태그가 붙은 발행·공개·휴지통 아님·작성자 탈퇴 신청 아님 글만 보여야 한다(MUST). 친구 공개 규격을 적용해도 공개 글만이어야 한다(MUST). (C-TAG-1, C-POST-4)
- **FR-014**: 태그별 글 목록은 홈 목록과 같은 카드·9개씩·[더 보기]·처음 공개된 시각 최신순(같으면 글 번호 큰 순)이어야 하고, 이어 붙여도 중복·누락이 없어야 한다(MUST). (C-READ-1)
- **FR-015**: 태그 페이지 상단에 태그 이름과 FR-013 조건의 공개 글 수를 보여야 한다(MUST).
- **FR-016**: 태그 주소는 이름을 경로 조각으로 인코딩해야 하며(`#`은 반드시 인코딩, `+`·`.`은 그대로), 허용 문자로 된 모든 태그(`c#`, `c++`, `node.js`, `.net`, `스프링-부트` 포함)는 주소로 왕복되어야 한다(MUST).
- **FR-017**: 정리되지 않은 태그 주소는 정리된 주소로 영구 이동(301)해야 하고, 형식에 맞지 않는 이름은 404여야 한다(MUST).
- **FR-018**: 형식에 맞지만 공개 글이 없는 태그(아무도 안 씀 또는 비공개 글에만 쓰임)의 페이지는 정상 페이지와 "아직 이 태그로 공개된 글이 없어요"를 보여야 하며, 두 경우가 구별되지 않아야 한다(MUST).

**전체 태그 목록**

- **FR-019**: 전체 태그 목록은 FR-013 조건의 공개 글 수 많은 순(같으면 이름 순)으로 상위 100개를 글 수와 함께 보여야 하고, 공개 글 수가 0인 태그는 제외해야 한다(MUST).
- **FR-020**: 전체 태그 목록은 최대 10분 간격으로 다시 계산해도 되며, 계산해 둔 결과가 없으면 바로 계산해야 한다(MUST).

**자동완성**

- **FR-021**: 자동완성은 로그인 회원만 쓸 수 있어야 한다(MUST). 검색어는 정리 규칙을 거친 뒤(금칙어 검사 제외) 앞부분 일치로 찾고, 정리 결과가 비면 빈 목록이어야 한다(MUST).
- **FR-022**: 자동완성 후보는 ① 내가 쓴 태그(내 모든 글, 공개 범위 무관)와 ② 공개 글 수가 1 이상인 태그만이어야 하며, 남의 비공개 글에만 쓰인 태그는 나오지 않아야 한다(MUST).
- **FR-023**: 자동완성은 내 태그 먼저, 그다음 공개 글 수 많은 순으로 최대 10개를 보여야 하며, 각 후보에 공개 글 수와 내 태그 여부를 함께 줘야 한다(MUST).
- **FR-024**: 자동완성은 입력이 0.3초 멈췄을 때 요청하고 한글 조합 중에는 요청하지 않아야 하며, 사용자당 1분에 60번으로 제한해야 한다(MUST).

**블로그 안 태그 필터와 글 상세 표시**

- **FR-025**: 개인 블로그는 그 블로그 목록과 같은 조건의 글에 쓰인 태그와 글 수를 글 수 많은 순으로 처음 10개 + [태그 더 보기]로 보여야 한다(MUST).
- **FR-026**: 블로그 태그 필터는 그 블로그의 해당 태그 글만 블로그 목록과 같은 카드·9개·[더 보기]로 보여주고 [필터 해제]를 제공해야 하며, 정리되지 않은 값은 정리된 주소로 영구 이동해야 한다(MUST).
- **FR-027**: 글 상세는 태그를 입력 순서대로 `#이름` 형식으로 보이고, 누르면 그 태그의 태그별 목록으로 이동해야 한다(MUST). 목록 카드에는 태그를 표시하지 않아야 한다(MUST).

### Key Entities

- **태그(Tag)**: 정리된 고유 이름(1~30자). 여러 글이 공유하며, 쓰는 글이 없어도 남는다.
- **글-태그 연결(Post Tag)**: 글과 태그의 다대다 연결. 글 안에서의 표시 순서(0부터)를 가지며, 한 글에 같은 태그는 한 번만.
- **공개 글 수**: 태그마다 공개·발행·휴지통 아님·작성자 탈퇴 신청 아님 조건을 만족하는 글의 수. 목록·자동완성·정렬 기준.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 원문 정리 예시 표의 모든 입력이 기대한 태그(또는 기대한 거부 이유)로 처리된다 (100% 일치).
- **SC-002**: 같은 새 태그로 동시에 10건을 발행해도 그 이름의 태그는 정확히 1개다.
- **SC-003**: 태그별 목록·전체 태그 목록·자동완성·태그 글 수에 비공개·임시·휴지통·탈퇴 신청 작성자의 글이 섞이는 경우가 0건이다.
- **SC-004**: 비공개 글에만 쓰인 태그의 페이지와 아무도 쓰지 않은 태그의 페이지 응답을 비교했을 때 차이가 0건이고, 그 태그가 남의 자동완성·전체 목록에 나오는 경우도 0건이다.
- **SC-005**: 허용 문자 태그 5종(`c#`, `c++`, `node.js`, `.net`, `스프링-부트`)의 태그 페이지가 실제 보안 설정을 거쳐 모두 정상 응답한다.
- **SC-006**: 규칙 위반 태그가 섞인 발행 시도에서 문제 태그를 하나라도 빠뜨리고 알려주는 경우가 0건이다.
- **SC-007**: 글 1만 건 기준 태그별 목록은 300ms 이내에 응답하고, 조회 횟수는 글 수에 비례해 늘지 않는다.

## Assumptions

- Tier: 태그 + 태그별 글 목록(C-TAG-1)은 **Tier B 공통 권장**이며 공통 범위에 포함하기로 했다(01 Q7 제안).
- 결정 기록(01 §4, 2026-10-02): 태그 기본 10개(설정값), 태그는 발행할 때 확정(자동 저장은 제목·본문만). 22 문서 결정 기록(2026-10-04)의 허용 문자·정리 순서·금칙어·순서·입력 위치·화면 범위를 따른다.
- 이 정리 규칙은 05 발행 문서의 태그 검증("소문자·공백 제거·중복 제거·1~30자")을 바꾸는 것이 아니라 구체화한 것이다. 오류 코드 `TAG_TOO_LONG`, `TAG_BANNED_WORD`가 추가되고 `INVALID_TAG`, `TOO_MANY_TAGS`는 그대로다.
- 태그 최대 개수(10), 전체 목록 개수(100), 재계산 간격(10분), 자동완성 개수(10)·제한(1분 60번)은 설정값으로 둔다.
- 관리자가 숨긴 글을 태그 목록·글 수에서 빼는 것은 신고·숨김(Tier C, spec 022)이 구현될 때 공용 조건에 함께 적용된다.
- 기간 기준 인기 태그("최근 많이 쓰인 태그")는 트렌딩(spec 019) 담당이며 이 명세 범위가 아니다. 전체 태그 목록은 누적 공개 글 수 기준이다.
- 검색(spec 020)과 AI 태그 추천(spec 021)은 이 정리 규칙을 그대로 쓴다. AI 추천 결과 중 규칙에 맞지 않는 것은 조용히 버리는 것은 spec 021에서 정한다.
- 글 상세에서 태그를 놓는 위치(제목 아래 또는 본문 끝)는 글 상세(spec 010)에서 정한다.
- 블로그 안 태그 필터에 친구 공개 글을 포함하는 것은 친구 공개 규격을 구현한 팀원(**개인 확장 선택 구현**)에게만 해당한다.
