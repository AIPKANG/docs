# 강성찬 개인 확장 후보 검토 (2026-10-09)

팀은 공통 최소 요구사항(Tier A·B·C, 명세 001~024)만 맞추고, 그 위에 각자 **추가만** 하기로 했다(01 §2-4, 01 원칙 2: 개인 확장을 켜도 공통 완료 기준은 그대로 지킨다).
아래는 팀 문서(docs/)에 강성찬 몫으로 적힌 것을 모은 목록이다. **원본 "블로그 플랫폼 요구사항 명세서"(64개 기능)는 이 저장소에 없어서**, 문서에 이름만 있고 내용이 없는 항목은 "정의 필요"로 두었다.

규칙: 새 기능은 새 모듈 패키지(02: `group/`·`mission/`·`streak/` 등) + 새 마이그레이션(V2 이후)으로 넣고, 공통 테이블은 CHECK 교체 같은 최소 변경만 한다(03 E-10). Spec Kit 순서로 `specs/025-…`부터.

## 추천 순서

1 친구 공개 → 4 공개 전환(응원 알림) → 11 조회수 기준 → 2 링크 공개 → 3 그룹 공개 → 5 답글 깊이 → 6 잔디·스트릭 → 7 통계. 8·9·10·12는 정의를 받은 뒤.
1이 2·3·4의 바탕이고, 이미 규격(06 §6)과 테이블이 있어 바로 명세로 옮길 수 있다.

## 넣을 때 지킬 것

- 친구·그룹·링크 글은 홈·태그·검색·트렌딩·피드·sitemap에 절대 안 나온다(06 §7 "새는 곳을 없앤다"). 공통 목록 조건은 그대로 `PUBLIC`만.
- 탈퇴 정리 단계에 친구·그룹 삭제를 끼운다(13 §3-3, 팔로우 앞).
- 신고·숨김·권한 표(42)에 새 공개 범위 칸을 더하고 테스트한다.
- 52 ERD 검토 A-1(`friendship` 삭제 제안)은 1을 하면 "유지"로 정리된다.
