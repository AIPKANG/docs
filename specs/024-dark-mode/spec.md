## User Scenarios & Testing *(mandatory)*

### User Story 1 - 처음 방문하면 기기 설정에 맞는 테마로 보임 (Priority: P1)

방문자(비회원 포함)가 처음 사이트를 열면, 기기가 다크 모드로 설정되어 있으면 다크로, 라이트면 라이트로 보인다. 다크 기기에서 페이지를 열 때 밝은 화면이 잠깐 번쩍이지 않는다. 브라우저의 스크립트가 꺼져 있어도 기기 설정을 따른다.

**Why this priority**: 아무 조작 없이 모든 방문자가 얻는 기본 가치이며, 번쩍임은 다크 모드 사용자에게 가장 눈에 띄는 문제다.

**Independent Test**: 저장된 선택이 없는 브라우저에서 기기 설정을 다크/라이트로 바꿔 가며 첫 화면 테마를 확인하고, 다크 설정에서 페이지 로드 중 밝은 화면이 보이지 않는지, 스크립트를 끈 상태에서도 테마가 맞는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 저장된 테마 선택이 없고 기기가 다크 설정, **When** 처음 방문하면, **Then** 다크 테마로 보인다.
2. **Given** 저장된 테마 선택이 없고 기기가 라이트 설정, **When** 처음 방문하면, **Then** 라이트 테마로 보인다.
3. **Given** 다크 테마가 적용될 상황, **When** 아무 페이지를 열면, **Then** 화면을 그리기 시작할 때부터 다크이며 밝은 화면이 잠깐도 보이지 않는다.
4. **Given** 브라우저 스크립트가 꺼진 상태, **When** 페이지를 열면, **Then** 기기 설정에 맞는 테마로 보이고 전환 버튼은 보이지 않는다.
5. **Given** 브라우저 저장소 접근이 막힌 환경, **When** 페이지를 열면, **Then** 오류 없이 기기 설정을 따른다.

### User Story 2 - 버튼으로 시스템·라이트·다크를 골라 고정 (Priority: P1)

사용자는 모든 페이지 헤더 맨 오른쪽의 같은 자리에 있는 전환 버튼을 눌러 시스템 설정 → 라이트 → 다크 → 시스템 … 순서로 고를 수 있다. 고른 값은 이 기기 브라우저에 저장되어 새로 고침하거나 다른 페이지로 가도 유지된다. "시스템"을 고르면 다시 기기 설정을 따른다.

**Why this priority**: 사용자가 원하는 테마로 고정하는 기능 자체이며, 1번과 함께 최소 기능을 이룬다.

**Independent Test**: 버튼을 눌러 세 상태를 순환하며 아이콘·설명·화면 테마가 바뀌는지, 새로 고침·페이지 이동 후에도 선택이 유지되는지, "시스템" 상태에서 기기 설정을 바꾸면 새로 고침 없이 따라 바뀌는지 확인한다.

**Acceptance Scenarios**:

1. **Given** "시스템" 상태, **When** 버튼을 누르면, **Then** "라이트"가 되고 즉시 라이트 테마로 바뀐다. 다시 누르면 "다크", 또 누르면 "시스템"이 된다.
2. **Given** 각 상태, **When** 버튼을 보면, **Then** 상태를 나타내는 아이콘(🖥/☀️/🌙)과 화면 읽기 프로그램·툴팁용 글자 설명이 함께 있다.
3. **Given** "다크"로 고정, **When** 새로 고치거나 다른 페이지로 이동하면, **Then** 다크가 유지된다.
4. **Given** "다크"로 고정, **When** 기기 설정을 라이트로 바꾸면, **Then** 다크 그대로다.
5. **Given** "시스템" 상태, **When** 기기 설정을 바꾸면, **Then** 새로 고치지 않아도 테마가 따라 바뀐다.
6. **Given** 테마를 고른 회원, **When** 로그아웃하면, **Then** 테마 선택은 지워지지 않고 유지된다.
7. **Given** 테마가 바뀔 때, **When** 화면이 다시 그려지면, **Then** 색이 서서히 바뀌는 애니메이션 없이 바로 바뀐다.

### User Story 3 - 다크 모드에서도 읽기 쉬운 색과 요소 (Priority: P2)

라이트·다크 모두 본문 글자와 배경의 명도 대비가 충분하고, 카드·코드 블록·썸네일 빈 영역·입력칸·상태 배지 등 모든 화면 요소가 공통 색 역할 목록의 값으로 그려진다. 사진은 색을 바꾸지 않는다.

**Why this priority**: 다크 모드가 "켜지는" 것만큼 "읽히는" 것이 중요하지만, 테마 전환 구조(P1)가 먼저 있어야 한다.

**Independent Test**: 주요 화면(홈, 글 상세, 블로그, 에디터, 설정)을 라이트·다크로 열어 자동 대비 검사 도구로 기준을 확인하고, 썸네일 없는 카드의 빈 영역 색, 코드 블록 강조 테마, 사진 원본 유지 여부를 확인한다.

**Acceptance Scenarios**:

1. **Given** 라이트·다크 각각의 주요 화면, **When** 자동 대비 검사를 돌리면, **Then** 본문 글자는 4.5 : 1 이상, 큰 글자·아이콘·입력칸 테두리는 3 : 1 이상이다.
2. **Given** 썸네일이 없는 글 카드, **When** 라이트로 보면 빈 영역이 `#F1F3F5`, **When** 다크로 보면 `#2B2F33`이다.
3. **Given** 다크 테마, **When** 본문 이미지·썸네일·프로필 사진을 보면, **Then** 색을 뒤집거나 어둡게 하지 않은 원본 그대로다.
4. **Given** 코드 블록이 있는 글, **When** 테마를 바꾸면, **Then** 코드 강조 색도 라이트용/다크용으로 함께 바뀐다.
5. **Given** 다크 테마, **When** 스크롤바·기본 입력칸 같은 브라우저 요소를 보면, **Then** 이들도 다크로 보인다.
6. **Given** 공개·비공개·수정 중 등 상태 배지, **When** 어느 테마에서 보든, **Then** 색만이 아니라 글자·아이콘으로도 구분된다.
7. **Given** 기본 프로필 아이콘(사진 없는 회원), **When** 다크로 보면, **Then** 8가지 배경색 모두 글자와 4.5 : 1 이상이다.

### Edge Cases

- 브라우저 스크립트가 꺼져 있으면 전환 버튼을 숨기고 기기 설정만 따른다.
- 브라우저 저장소 접근이 막혀 있으면(사생활 보호 모드 등) 저장 없이 기기 설정만 따르고 오류를 내지 않는다.
- 저장된 값이 알 수 없는 값이면 "시스템"으로 취급한다.
- 테마 선택은 기기·브라우저마다 따로이며, 다른 기기에서는 다시 골라야 한다.
- 에디터가 다크 테마를 지원하지 않으면 에디터 영역만 라이트로 두고 주변은 다크로 둔다.
- 링크 미리보기 이미지와 메일은 테마와 무관하게 라이트 기준이다.
- 페이지 보안 정책상 인라인 스크립트를 쓸 수 없으므로, 테마를 먼저 정하는 처리도 인라인 없이 동작해야 한다.
- 서버 렌더링 화면이든 단일 페이지 앱이든 같은 방식·같은 색 역할 이름으로 동작해야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**테마 선택과 저장**

- **FR-001**: 시스템은 테마 선택지로 "시스템 설정 / 라이트 / 다크" 3가지를 제공해야 한다(MUST).
- **FR-002**: 저장된 선택이 없으면 기본값은 "시스템 설정"이어야 하며(MUST), 기기의 라이트/다크 설정을 따라야 한다(MUST).
- **FR-003**: 테마 선택은 사용자의 브라우저에 기기별로 저장되어야 하며(MUST), 비회원도 사용할 수 있어야 한다(MUST). 서버나 회원 정보에 저장하지 않는다.
- **FR-004**: 전환 버튼은 모든 페이지 헤더 맨 오른쪽 같은 자리에 있어야 하고(MUST), 누를 때마다 시스템 → 라이트 → 다크 → 시스템 순으로 바뀌어 즉시 화면에 반영되어야 한다(MUST).
- **FR-005**: 전환 버튼은 현재 상태 아이콘과 보조 기술·툴팁용 글자 설명을 함께 가져야 한다(MUST).
- **FR-006**: 선택은 새로 고침·페이지 이동 후에도 유지되어야 한다(MUST).
- **FR-007**: "시스템"을 고른 상태에서 기기 설정이 바뀌면 새로 고침 없이 따라 바뀌어야 하고(MUST), "라이트"·"다크"로 고정한 상태에서는 기기 설정 변경을 따르지 않아야 한다(MUST).
- **FR-008**: 로그아웃할 때 테마 선택은 지우지 않아야 한다(MUST) (로그아웃 시 지우는 것은 임시 글 데이터뿐, 07 §7).

**깜빡임 방지·보안·대체 동작**

- **FR-009**: 시스템은 페이지를 그리기 전에 테마를 정해, 다크 테마에서 밝은 화면이 잠깐도 보이지 않게 해야 한다(MUST).
- **FR-010**: 테마 처리는 인라인 스크립트 없이 동작해야 하며(MUST), 페이지 보안 정책(우리 서버의 스크립트만 허용) 위반이 없어야 한다(MUST) (12 §8, 헌법 IV).
- **FR-011**: 브라우저 스크립트가 꺼져 있어도 기기 설정에 맞는 테마로 보여야 하며(MUST), 이때 전환 버튼은 숨겨야 한다(MUST).
- **FR-012**: 브라우저 저장소에 접근할 수 없으면 오류 없이 기기 설정만 따라야 한다(MUST).
- **FR-013**: 테마가 바뀔 때 색이 서서히 바뀌는 애니메이션을 넣으면 안 된다(MUST NOT).
- **FR-014**: 브라우저 기본 요소(스크롤바·기본 입력칸 등)도 현재 테마를 따르도록 페이지가 라이트·다크 지원을 선언해야 한다(MUST).

**색 역할**

- **FR-015**: 모든 화면은 공통 색 역할 목록의 이름만 써서 색을 지정해야 하며(MUST), 화면 코드에 색 값을 직접 쓰면 안 된다(MUST NOT). 색 역할 이름은 세 팀원이 같이 쓰고, 개인 서비스는 값만 바꿀 수 있다(이름은 바꾸지 않음).
- **FR-016**: 공통 색 역할과 기본값은 다음과 같아야 한다(MUST):

  | 색 역할 | 쓰는 곳 | 라이트 | 다크 |
  |---|---|---|---|
  | 페이지 배경 | 페이지 배경 | `#FFFFFF` | `#121212` |
  | 표면 | 카드·헤더·상자 | `#FFFFFF` | `#1E1E1E` |
  | 본문 글자 | 본문 글자 | `#212529` | `#E9ECEF` |
  | 보조 글자 | 날짜·보조 글자 | `#6C757D` | `#ADB5BD` |
  | 테두리 | 구분선·카드 테두리 | `#DEE2E6` | `#343A40` |
  | 브랜드 | 링크·강조 글자 | 각자 | 각자 (다크에서는 더 밝게) |
  | 브랜드 채움 | 흰 글자가 올라가는 버튼 배경 | 각자 | 각자 |
  | 위험 | 삭제·오류 | `#C92A2A` | `#FF6B6B` |
  | 썸네일 빈 영역 | 썸네일 없는 카드 | `#F1F3F5` | `#2B2F33` |
  | 코드 배경 | 코드 블록 배경 | `#F8F9FA` | `#1A1B1E` |
  | 포커스 | 키보드 포커스 테두리 | `#1C7ED6` | `#74C0FC` |

- **FR-017**: 다크 배경은 순수 검정이 아닌 `#121212`여야 한다(MUST).
- **FR-018**: 라이트·다크 모두 본문 글자 대비 4.5 : 1 이상, 큰 글자·아이콘·입력칸 테두리 대비 3 : 1 이상이어야 한다(MUST) (WCAG 2.2 AA). 각자 정하는 브랜드 색도 배경 대비 4.5 : 1, 브랜드 채움 위 흰 글자 4.5 : 1을 만족해야 한다(MUST).

**요소별 규칙**

- **FR-019**: 본문 이미지·썸네일·프로필 사진은 다크에서도 색을 뒤집거나 어둡게 하지 않아야 한다(MUST NOT).
- **FR-020**: 기본 프로필 아이콘의 8가지 배경색은 다크에서도 글자와 4.5 : 1 이상이어야 한다(MUST) (11 §4-3).
- **FR-021**: 코드 강조는 라이트용·다크용 두 가지 색 구성을 현재 테마에 맞춰 적용해야 한다(MUST).
- **FR-022**: 본문의 표·인용·체크리스트는 공통 색 역할(테두리·보조 글자)만 써야 한다(MUST).
- **FR-023**: 에디터는 다크 테마를 지원하면 같은 테마로 켜야 하고(MUST), 지원하지 않으면 에디터만 라이트로 두고 주변은 다크로 둔다.
- **FR-024**: 상태 배지(공개·비공개·수정 중 등)는 색만으로 구분하지 않고 글자·아이콘을 함께 써야 한다(MUST).
- **FR-025**: 링크 미리보기 이미지와 메일은 테마와 무관하게 라이트 기준이어야 한다(MUST).
- **FR-026**: 서버 렌더링 화면과 단일 페이지 앱 모두 같은 테마 결정 방식과 같은 색 역할 이름으로 동작해야 한다(MUST).

### Key Entities *(include if feature involves data)*

- **테마 선택**: 시스템 / 라이트 / 다크 중 하나. 기기 브라우저에만 저장되며 서버 데이터는 없다.
- **적용 테마**: 실제로 화면에 쓰는 라이트 또는 다크. 테마 선택이 "시스템"이면 기기 설정에서 정해진다.
- **색 역할 목록**: 이름 + 라이트 값 + 다크 값. 세 팀원 공통 이름, 값은 바꿀 수 있음.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 다크 테마 상태에서 주요 화면을 열 때 밝은 화면이 보이는 프레임이 0개다.
- **SC-002**: 주요 화면(홈, 글 상세, 블로그, 에디터, 설정)에서 자동 대비 검사 결과 라이트·다크 모두 대비 기준 위반이 0건이다.
- **SC-003**: 테마 처리로 인한 페이지 보안 정책 위반 보고가 0건이다.
- **SC-004**: 사용자는 버튼을 최대 2번 눌러 원하는 테마에 도달하고, 선택은 새로 고침·페이지 이동 후 100% 유지된다.
- **SC-005**: "시스템" 상태에서 기기 설정을 바꾸면 새로 고침 없이 1초 이내에 화면이 따라 바뀐다.
- **SC-006**: 스크립트가 꺼진 브라우저에서도 기기 설정과 같은 테마로 100% 보인다.
- **SC-007**: 화면 코드에서 색 역할을 거치지 않고 직접 쓴 색 값이 0건이다 (공통 색 정의 파일 제외).

## Assumptions

- Tier C 기능이다 (01 §2-3 "다크 모드": 강 P3, 나 MUST, 김 3차). 화면 요소이며 공통 데이터 구조(ERD)와 무관하다. 원문 문서 상태는 "초안 (항목 확인 중)"이다.
- 테마 선택을 계정에 저장해 기기 간 동기화하는 것은 개인 확장이다 (T-3).
- 색 기본값은 공통 기본값이며, 브랜드·브랜드 채움 색은 각자 정한다. 개인 서비스는 값만 바꾸고 이름은 바꾸지 않는다.
- 썸네일 빈 영역 라이트 색 `#F1F3F5`는 2026-10-02 결정 기록(글 카드)과 같고, 다크 값 `#2B2F33`은 10 문서 L-7을 따른다.
- 각자 쓰는 에디터의 다크 테마 지원 여부는 각자 확인한다 (45 "다른 담당자와 맞출 것"). 지원하지 않으면 FR-023의 대체 규칙을 쓴다.
- 화면 구성 방식(서버 렌더링 / 단일 페이지 앱, 01 Q2)과 무관하게 같은 방식이 동작해야 한다.
