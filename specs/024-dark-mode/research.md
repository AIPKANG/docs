# Research: 다크 모드 (024-dark-mode)

**Phase 0** · 2026-10-08 · 입력: [spec.md](./spec.md), [source-notes.md](./source-notes.md), `docs/45-*`, 12 §8 CSP

사용자 지시: 질문 없이 기본값.

## R-1. 결정과 깜빡임 (FR-001~FR-012)
- 저장: `localStorage['blog-theme']` = `light`|`dark`(없으면 시스템). 서버·회원 정보에 저장하지 않고 로그아웃 정리(임시 글)와 무관.
- `theme-init.js`를 `<head>`에서 defer 없이(외부 파일이라 CSP 위반 없음) 불러 그리기 전에 `data-theme`을 붙인다. 저장소 접근 실패는 무시(시스템).
- CSS: `:root`(라이트) / `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`(시스템 다크) / `:root[data-theme="dark"]`(고정 다크). 시스템 상태는 속성이 없어 기기 설정이 바뀌면 새로 고침 없이 따른다. `color-scheme`(메타·CSS)으로 스크롤바·입력칸도 테마를 따른다. 테마 전환 애니메이션 없음.
- 버튼은 `hidden`으로 그려 스크립트가 있을 때만 보인다. 아이콘(🖥/☀/🌙) + `aria-label`/`title` "테마: 시스템 설정/라이트/다크".

## R-2. 색 역할 (FR-015~FR-024)
- 공통 11개 역할을 45의 값 그대로(브랜드는 라이트 `#0B63C4`, 다크 `#74C0FC`, 채움 `#0B63C4`/`#1971C2` — 대비 4.5:1 이상). 화면에 필요한 나머지(옅은 브랜드·강조·경고·성공·위험 채움·오버레이·그림자·흰 글자)는 이 서비스 확장 역할로 같은 파일에.
- 기존 69개 색 값을 역할로 바꿨다(테두리 `#d0d7de`·`#eaeef2` → `--color-border`, 보조 글자 → `--color-text-muted` 등). 기본 프로필 아이콘 8색은 흰 글자와 4.5:1 이상이라 두 테마 같은 값(`--avatar-c0~7`), 스크립트도 색 대신 클래스를 쓴다.
- 이미지·썸네일·프로필 사진에 필터를 걸지 않는다. 표·인용·코드 블록은 역할 색(테두리·보조 글자·코드 배경)만.
- 코드 강조(FR-021): 지금 렌더러(007)는 `language-*` 클래스만 남기고 문법 강조를 하지 않으므로 코드 배경 역할만 테마를 따른다. 강조를 넣는 기능이 생기면 라이트·다크 두 구성을 이 파일에 더한다(U-1).
- 에디터(FR-023)는 순수 `<textarea>`라 `color-scheme`으로 같은 테마를 따른다. 메일·링크 미리보기는 테마와 무관(라이트).

## 남은 확인
- U-1: 코드 문법 강조를 도입할지(도입하면 두 색 구성).
