# Feature Specification: 접근 권한 공통 규칙 (권한 매트릭스)

**Feature Branch**: `012-access-permission`

**Created**: 2026-10-07

**Status**: Draft

**Input**: 사용자 설명: "docs/ 원문 문서에서 변환: docs/42-permission-matrix.md"

> 이 명세는 기능 하나가 아니라 **모든 기능이 따르는 횡단 규칙**이다. 행위자 구분, 판정 순서, 응답 코드, 리소스별 권한 표를 정하고, 각 기능 명세(004~024)는 이 표를 기준으로 권한을 적는다.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 남의 것은 바꿀 수 없다 (Priority: P1)

회원은 자기 글·댓글만 수정·삭제·발행·공개 범위 변경할 수 있다. 다른 사람의 것에 대한 요청은 화면을 거치지 않고 직접 보내도 서버에서 거부되고, 대상은 조금도 바뀌지 않는다. 요청에 다른 사람의 작성자 값을 넣어도 무시된다.

**Why this priority**: C-OWN-1(Tier A 공통 필수). 화면에서 버튼을 숨기는 것만으로는 주소 직접 입력·요청 조작을 막지 못한다.

**Independent Test**: 회원 A의 글·댓글에 대해 회원 B·관리자·글 주인(댓글의 경우)으로 수정·삭제·발행·공개 범위 변경 요청을 직접 보내, 모두 404이고 요청 전후 데이터(내용·상태·편집 버전·수정 시각)가 같은지 확인한다.

**Acceptance Scenarios**:

1. **Given** A의 발행 글, **When** B가 그 글의 수정·삭제·발행·공개 범위 변경을 요청하면, **Then** 404이고 글의 내용·상태·편집 버전·수정 시각이 요청 전과 같다.
2. **Given** B가 로그인한 상태, **When** 요청 본문에 작성자로 A를 넣어 새 글을 만들거나 저장하면, **Then** 그 값은 무시되고 결과는 B 자신의 글로만 처리된다.
3. **Given** A의 글에 B가 단 댓글, **When** 글 주인 A가 그 댓글을 삭제하면, **Then** 404이고 댓글은 그대로다.
4. **Given** 관리자, **When** 남의 글·댓글 내용을 수정하거나 삭제하려 하면, **Then** 404이고 내용은 그대로다.

---

### User Story 2 - 볼 수 없는 것과 없는 것은 구별되지 않는다 (Priority: P1)

남의 비공개 글, 임시글, 휴지통 글, 관리자가 숨긴 글, 탈퇴 신청한 작성자의 글, 그리고 아예 없는 글은 누구에게나 똑같은 404로 보인다. 응답 본문과 링크 미리보기로도 차이를 알 수 없다.

**Why this priority**: 존재 여부를 드러내지 않는 것은 팀 결정(01 결정 기록 "권한 없음 응답 404")이며, 모든 기능이 같은 방식이어야 한다.

**Independent Test**: 각 상태의 글과 존재하지 않는 번호에 대해 비회원·회원·관리자로 상세·댓글·좋아요 요청을 보내 응답 코드·본문이 같은지 비교한다.

**Acceptance Scenarios**:

1. **Given** A의 비공개 글과 존재하지 않는 글 번호, **When** B가 둘의 상세를 요청하면, **Then** 두 응답은 같은 404, 같은 이유 코드(`NOT_FOUND`), 같은 "볼 수 없는 페이지예요" 화면이다.
2. **Given** 임시글·휴지통 글·숨긴 글·탈퇴 유예 작성자의 글, **When** 작성자가 아닌 사람이 상세·댓글·좋아요를 요청하면, **Then** 모두 404다.
3. **Given** 일반 회원, **When** 관리자 전용 화면 주소에 접근하면, **Then** 404다.

---

### User Story 3 - 모든 기능이 같은 순서로 판정하고 같은 응답을 준다 (Priority: P1)

같은 상황에서 기능마다 다른 응답이 나오지 않도록, 모든 요청은 로그인 → 계정 상태 → 대상을 볼 수 있나 → 행동 권한 → 업무 규칙 순서로 검사하고 처음 걸린 단계의 응답을 준다.

**Why this priority**: 화면·API·테스트가 같은 기준을 써야 권한 통합 테스트를 표 하나로 만들 수 있다.

**Independent Test**: 여러 조건에 동시에 걸리는 요청(예: 인증 전 회원이 남의 비공개 글에 좋아요)을 보내 처음 단계의 응답이 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 로그인이 필요한 행동을 요청하면, **Then** 401(`LOGIN_REQUIRED`)이고, 화면이라면 로그인 화면으로 이동했다가 로그인 후 원래 페이지로 돌아온다.
2. **Given** 이메일 인증 전 회원, **When** 볼 수 없는 글에 좋아요를 누르면, **Then** 404가 아니라 403 `EMAIL_NOT_VERIFIED`다 (계정 상태가 먼저).
3. **Given** 인증 전인 작성자, **When** 자기 글을 발행하면, **Then** 403 `EMAIL_NOT_VERIFIED`다.
4. **Given** 회원, **When** 자기 글에 좋아요를 누르면, **Then** 400 `CANNOT_LIKE_OWN_POST`다.
5. **Given** 편집 버전이 어긋난 저장 요청, **When** 작성자가 저장하면, **Then** 409 상태 충돌이다.

---

### User Story 4 - 계정 상태에 따라 할 수 있는 일이 정해져 있다 (Priority: P2)

이메일 인증 전 회원은 쓰기·좋아요·신고·사진 업로드를 할 수 없지만 자기 글·댓글 삭제와 프로필 일부 수정은 할 수 있다. 탈퇴 유예 회원은 로그인해도 복구 화면만 본다. 정지 회원은 로그인 자체가 막혀 비회원과 같다.

**Why this priority**: 인증하지 않은 계정의 남용(좋아요 부풀리기·신고 남용)을 막고, 사용자가 무엇을 해야 풀리는지 알게 한다. 탈퇴·정지 화면은 Tier C지만 규칙은 지금 확정한다.

**Independent Test**: 인증 전·탈퇴 유예·정지 상태 계정으로 §권한 매트릭스의 각 행동을 요청해 표와 같은 결과가 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 인증 전 회원, **When** 글 쓰기·댓글·좋아요·신고·사진 업로드를 요청하면, **Then** 403 `EMAIL_NOT_VERIFIED`이고 화면은 인증 메일 다시 보내기를 안내한다.
2. **Given** 인증 전 회원, **When** 자기 글을 삭제·복구하거나 자기 댓글을 삭제하면, **Then** 허용된다.
3. **Given** 탈퇴 유예 회원, **When** 로그인 후 어떤 페이지든 요청하면, **Then** 복구 화면(복구하기/로그아웃)만 보이고, API 요청은 403 `ACCOUNT_WITHDRAWN`이다.
4. **Given** 회원을 정지하면, **When** 정지 직후 그 회원의 기존 세션으로 요청하면, **Then** 모든 기기에서 로그아웃되어 있고, 로그인하면 "정지된 계정이에요 (~기한, 사유)"만 보인다.
5. **Given** 정지된 회원이 쓴 글·댓글, **When** 다른 사람이 보면, **Then** 그대로 보인다.

---

### User Story 5 - 관리자도 정해진 일만 한다 (Priority: P2)

관리자는 남의 콘텐츠를 숨기거나 해제할 수 있을 뿐, 내용을 고치거나 지울 수 없고, 남의 비공개 글이나 알림도 볼 수 없다. 관리자도 자기 글에서는 일반 작성자다.

**Why this priority**: 운영자가 작성자의 콘텐츠를 바꾸지 않는다는 원칙. 신고·숨김(Tier C)이 붙을 때 권한 남용을 막는다.

**Independent Test**: 관리자 계정으로 남의 비공개 글 상세, 남의 글 수정·삭제, 남의 알림 읽음 처리, 자기 자신 정지를 요청한다.

**Acceptance Scenarios**:

1. **Given** 관리자, **When** 남의 비공개 글 상세를 요청하면, **Then** 404다.
2. **Given** 관리자, **When** 남의 알림을 읽음 처리·삭제하면, **Then** 404다.
3. **Given** 관리자, **When** 자기 자신을 정지하려 하면, **Then** 거부된다.
4. **Given** 관리자, **When** 남의 글을 숨기면, **Then** 숨김은 되지만 내용은 바뀌지 않는다.

---

### User Story 6 - 할 수 없는 행동의 버튼은 보이지 않는다 (Priority: P3)

서버 판정과 별개로, 화면은 그 사람이 할 수 없는 행동의 버튼을 보여주지 않는다 (예: 남의 글에는 [수정] [삭제]가 없고, 내 글에는 [좋아요] 버튼 대신 개수만).

**Why this priority**: 사용성 보조 장치다. 보안은 서버 판정(P1)이 보장한다.

**Independent Test**: 행위자별로 글 상세·댓글 영역을 렌더링해 보이는 버튼을 §화면 표시 표와 비교한다.

**Acceptance Scenarios**:

1. **Given** 남의 글 상세, **When** 회원이 보면, **Then** [수정] [삭제] [공개 범위]가 없고 [좋아요] [신고]가 있다.
2. **Given** 내 글 상세, **When** 작성자가 보면, **Then** [수정] [삭제] [공개 범위]가 있고 좋아요는 버튼 없이 개수만, [신고]는 없다.
3. **Given** 인증 전 회원, **When** 댓글 영역을 보면, **Then** 입력창 대신 "이메일 인증 후 댓글을 쓸 수 있어요 [인증 메일 다시 보내기]"가 보이고, 비회원에게는 "로그인하고 댓글 쓰기"가 보인다.

---

### Edge Cases

- 한 사람이 여러 행위자에 해당하면 판정 순서에서 먼저 걸리는 쪽이 적용된다 (예: 인증 전인 작성자의 발행 → 403).
- 관리자도 자기 글에서는 작성자로 판정된다.
- 정지 회원은 자기 글도 정지 기간에는 지울 수 없다 (로그인 불가의 결과). 비밀번호 재설정(로그인 전 기능)은 가능하다.
- 탈퇴 유예 회원 본인이 자기 글 주소로 들어와도 복구 화면만 본다.
- 휴지통 글은 작성자에게도 상세 404이며 휴지통 목록에서만 보인다. 휴지통 글의 저장·발행·공개 범위 변경도 작성자에게 404다.
- 숨긴 댓글은 작성자도 수정할 수 없고 아무도 답글을 달 수 없지만, 작성자의 삭제는 가능하다.
- 같은 대상을 다시 신고하면 새로 만들지 않고 성공으로 응답한다.
- 프로필 수정·내 글 관리·알림 주소에는 회원 값이 없어 "남의 것" 경로 자체가 없다.
- 남이 올린 사진을 내 프로필·글에 연결하려 하면 400이다.

## Requirements *(mandatory)*

### Functional Requirements

**행위자와 판정 원칙**

- **FR-001**: 시스템은 요청자를 비회원, 인증 전 회원, 회원(대상의 작성자가 아님), 작성자, 관리자, 정지 회원, 탈퇴 유예 회원으로 구분해 판정해야 한다(MUST). 소셜 가입 회원은 가입 시각에 인증된 것으로 본다. (C-OWN-1)
- **FR-002**: 현재 사용자는 인증 정보에서만 정해야 하며, 요청에 담긴 작성자·회원 값은 권한 판정과 저장에 쓰지 않아야 한다(MUST). (C-OWN-1)
- **FR-003**: 모든 권한 판정은 서버에서 매 요청마다 해야 하고, 화면에서 버튼을 숨기는 것은 보조 수단이어야 한다(MUST). (C-OWN-1)
- **FR-004**: 모든 기능은 다음 순서로 검사하고 처음 걸린 단계의 응답을 줘야 한다(MUST): ① 로그인 필요 → ② 계정 상태(탈퇴 유예, 인증 전 + 쓰기 행동) → ③ 대상을 볼 수 있나(없음·휴지통·숨김·작성자 탈퇴 유예·공개 범위상 볼 수 없음) → ④ 이 행동을 할 권한(소유자 전용·관리자 전용) → ⑤ 업무 규칙(자기 글 좋아요, 자기 것 신고, 상태 충돌).
- **FR-005**: 글 하나를 읽을 수 있는지는 한 곳의 공통 판정으로만 결정하고, 모든 목록은 같은 규칙의 조건을 써야 한다(MUST). (C-POST-4, C-READ-2)

**응답 코드**

- **FR-006**: 로그인이 필요한데 비회원이면 401(`LOGIN_REQUIRED`)이어야 하며, 화면 요청은 로그인 화면으로 보내고 로그인 후 원래 페이지로 돌려보내야 한다(MUST).
- **FR-007**: 403은 계정 상태 때문에 할 수 없을 때만 써야 하며 이유 코드(`EMAIL_NOT_VERIFIED`, `ACCOUNT_WITHDRAWN`)와 해결 방법(인증 메일 다시 보내기 / 복구 화면)을 함께 줘야 한다(MUST). "남의 것이라서 안 됨"에는 403을 쓰지 않아야 한다(MUST).
- **FR-008**: 대상이 없음, 볼 수 없음, 내 것이 아님, 관리자 전용인 경우는 모두 하나의 404(`NOT_FOUND`)와 같은 "볼 수 없는 페이지예요" 화면으로 응답해야 하며, 응답 본문·링크 미리보기로 이들을 구별할 수 없어야 한다(MUST). (C-READ-2, C-OWN-1)
- **FR-009**: 요청 자체가 업무 규칙에 어긋나면 400과 이유 코드(예: `CANNOT_LIKE_OWN_POST`, `CANNOT_REPORT_OWN`, `CANNOT_FOLLOW_SELF`, `REPLY_TARGET_UNAVAILABLE`)를 줘야 한다(MUST).
- **FR-010**: 상태 충돌은 409와 각 기능 문서에 정의된 이유 코드(예: `VERSION_CONFLICT`, `NICKNAME_CHANGE_TOO_SOON`, `COMMENT_HIDDEN`)를 줘야 한다(MUST).
- **FR-011**: 정지된 계정으로 로그인하면 로그인 실패로 처리하고 `ACCOUNT_SUSPENDED`와 정지 기한·사유를 로그인 화면에 안내해야 한다(MUST).

**계정 상태**

- **FR-012**: 인증 전 회원은 글 쓰기(새 글·저장·발행·변경 취소·공개 범위 변경), 댓글 쓰기·수정, 좋아요, 신고, 사진 업로드, 프로필 이미지 변경을 할 수 없어야 한다(MUST, 403 `EMAIL_NOT_VERIFIED`). 자기 글 삭제·복구·영구 삭제, 자기 댓글 삭제, 닉네임·소개 수정, 비밀번호 변경, 기본 공개 범위 설정, 회원 탈퇴, 팔로우, 내 글 관리·알림 보기는 할 수 있어야 한다(MUST).
- **FR-013**: 탈퇴 유예 회원이 로그인하면 복구 화면(복구하기/로그아웃)만 보여야 하고, 그 밖의 요청은 화면이면 복구 화면으로 보내고 API면 403 `ACCOUNT_WITHDRAWN`이어야 한다(MUST).
- **FR-014**: 회원을 정지하는 즉시 그 회원의 모든 세션을 끊어야 하고, 정지 기간에는 로그인할 수 없어야 하며, 판정에서는 비회원과 같아야 한다(MUST). 정지 회원이 이미 쓴 글·댓글은 그대로 보여야 한다(MUST).

**글 (§권한 매트릭스 표 1·2)**

- **FR-015**: 글 상세 보기는 표 1을 따라야 한다(MUST): 발행·공개 글은 누구나, 발행·비공개 글과 임시글은 작성자만(비공개는 🔒 배지, 임시글은 "임시저장" 배지), 수정 중인 글은 모두에게 마지막 발행본(작성자에게는 "수정 중" 안내 추가), 휴지통 글은 작성자 포함 모두 404, 관리자가 숨긴 글은 작성자에게 "운영 정책에 따라 숨겨진 글이에요"와 함께 보이고 그 외에는 404, 작성자가 탈퇴 유예이면 모두 404.
- **FR-016**: 글 쓰기 행동은 표 2를 따라야 한다(MUST). 남의 글에 대한 저장·발행·변경 취소·공개 범위 변경·삭제·복구·영구 삭제는 회원·관리자 모두 404이고, 복구·영구 삭제는 휴지통 글에만 가능해야 한다(아니면 404).
- **FR-017**: 관리자는 남의 글·댓글을 숨기거나 숨김 해제만 할 수 있고, 내용을 수정·삭제하거나 남의 비공개 글을 볼 수 없어야 한다(MUST). 관리자도 자기 글에서는 작성자로 판정해야 한다(MUST).

**댓글 (표 3)**

- **FR-018**: 댓글 보기는 그 글을 볼 수 있는 사람에게만 허용하고, 볼 수 없으면 404여야 한다(MUST). 댓글을 쓰려면 그 글을 볼 수 있어야 한다(MUST).
- **FR-019**: 댓글 수정·삭제는 댓글 작성자만 할 수 있어야 하며, 글 주인도 남의 댓글에 대해서는 일반 회원과 같아야 한다(MUST, 그 외 404). (C-CMT-1)
- **FR-020**: 숨긴 댓글은 작성자도 수정할 수 없고(409), 누구도 답글을 달 수 없어야 하며(400 `REPLY_TARGET_UNAVAILABLE`), 작성자의 삭제는 허용해야 한다(MUST).

**좋아요·신고·팔로우 (표 4·5·6)**

- **FR-021**: 좋아요 수는 글을 볼 수 있는 사람에게만 보여야 한다(MUST). 좋아요 누르기·취소는 회원·관리자만 가능하고, 자기 글은 400 `CANNOT_LIKE_OWN_POST`, 볼 수 없는 글은 404여야 한다(MUST). 이미 그 상태여도 성공이어야 하고, 1분에 60번을 넘으면 429여야 한다(MUST). (C-LIKE-1)
- **FR-022**: 볼 수 없게 된 글(비공개 전환·관리자 숨김)의 댓글·좋아요는 지우지 않고 함께 숨겨야 한다(MUST).
- **FR-023**: 신고는 회원·관리자가 볼 수 있는 글·댓글에만 할 수 있고, 자기 것은 400 `CANNOT_REPORT_OWN`, 같은 대상을 다시 신고하면 새로 만들지 않고 성공이어야 한다(MUST). 신고 목록 보기·처리는 관리자만 가능하고 그 외는 404여야 한다(MUST). (Tier C)
- **FR-024**: 팔로우·언팔로우는 인증 전 회원을 포함한 로그인 회원이 할 수 있고, 자기 자신은 400 `CANNOT_FOLLOW_SELF`, 없는 블로그·탈퇴 유예 블로그는 404여야 한다(MUST). 팔로워·팔로잉 수와 목록은 누구나 볼 수 있고, 탈퇴 유예 회원은 남의 목록과 수에서 빠져야 한다(MUST). (Tier C)

**프로필·계정·내 글 관리·사진·태그·알림 (표 7·8·9)**

- **FR-025**: 블로그·프로필은 누구나 볼 수 있고 탈퇴 유예·익명 처리된 주소는 404여야 한다(MUST). 프로필 수정·비밀번호 변경·기본 공개 범위·회원 탈퇴는 본인만 가능해야 하며, 이 기능들의 주소에는 회원 값이 없어야 한다(MUST). 회원 정지·해제는 관리자만(자기 자신 불가), 그 외는 404여야 한다(MUST).
- **FR-026**: 내 글 관리는 로그인 회원이 본인 글만 볼 수 있어야 하고, 관리자에게도 남의 글 관리 화면은 없어야 한다(MUST). (C-MANAGE-1)
- **FR-027**: 사진 업로드는 인증된 회원·관리자만 가능해야 하고, 남이 올린 사진을 프로필·글에 연결하면 400이어야 한다(MUST). (C-IMG-1)
- **FR-028**: 태그별 목록·전체 태그 목록은 누구나 볼 수 있고 공개·발행 글만 세어야 한다(MUST). 자동완성은 공개 글의 태그와 로그인 회원 자신의 태그만 보여야 한다(MUST). 태그 붙이기는 글 발행 권한을 따라야 한다(MUST). (C-TAG-1)
- **FR-029**: 알림 목록·안 읽은 수·읽음 처리·삭제는 받은 사람 본인만 할 수 있고, 다른 회원과 관리자는 404여야 한다(MUST). 탈퇴 유예 회원에게는 알림을 만들지 않아야 한다(MUST). (Tier C)
- **FR-030**: 관리자 전용 기능 주소에 관리자가 아닌 사람이 접근하면 404여야 한다(MUST).

**화면 표시**

- **FR-031**: 화면은 표 10의 조건을 만족할 때만 각 버튼을 보여야 한다(MUST).

**검증**

- **FR-032**: 권한 매트릭스(표 1~9)의 모든 칸(행위자 × 대상 상태 × 행동)은 자동 통합 테스트로 확인되어야 한다(MUST). (C-OWN-1)

### Key Entities

- **행위자(Actor)**: 요청자의 판정 결과. 로그인 여부, 이메일 인증 여부, 계정 상태(활동·정지·탈퇴 유예), 역할(일반·관리자), 대상과의 소유 관계로 정해진다.
- **회원 계정 상태**: 활동 / 정지(기한·사유) / 탈퇴 유예(신청 시각) / 익명 처리됨.
- **대상 리소스**: 글, 댓글, 좋아요, 신고, 팔로우, 프로필, 사진, 태그, 알림. 각각 작성자(소유자)와 가시성 상태(공개 범위·임시·휴지통·숨김·작성자 탈퇴 유예)를 가진다.
- **판정 결과**: 허용 또는 응답 코드(401/403/404/400/409)와 이유 코드.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 권한 매트릭스(표 1~9)의 모든 칸이 자동 통합 테스트로 존재하고 100% 통과한다.
- **SC-002**: 남의 글·댓글에 대한 수정·삭제·발행·공개 범위 변경 요청 100%가 404이며, 요청 전후 대상 데이터가 한 글자도 다르지 않다.
- **SC-003**: 볼 수 없는 대상(비공개·임시·휴지통·숨김·탈퇴 유예)과 존재하지 않는 대상의 응답을 비교했을 때 상태 코드·본문·링크 미리보기 차이가 0건이다.
- **SC-004**: 같은 상황에서 기능마다 다른 응답 코드가 나오는 경우가 0건이다 (판정 순서 교차 테스트).
- **SC-005**: 회원을 정지한 뒤 그 회원의 기존 세션으로 보낸 요청 중 로그인 상태로 처리되는 것이 0건이다.
- **SC-006**: 관리자 계정으로 남의 글·댓글 내용 변경, 남의 비공개 글 열람, 남의 알림 조작에 성공하는 경우가 0건이다.
- **SC-007**: 행위자별 화면 점검에서 할 수 없는 행동의 버튼이 보이는 경우가 0건이다.

## Assumptions

- Tier: 소유 권한(C-OWN-1)과 글·댓글·좋아요·태그·내 글 관리·사진 행은 **Tier A·B 공통**이다. 신고·숨김·정지(spec 022), 팔로우·피드(spec 018), 알림(spec 017), 회원 탈퇴(spec 023) 행은 **Tier C** 기능이 구현될 때 적용한다.
- 404 통일(01 결정 기록 2026-10-02 "권한 없음 응답")과 서버 권한 검사(01 §3-3)는 기존 결정을 따른다.
- 자기 글 좋아요의 응답은 이 문서의 결정(P-9)에 따라 **400 `CANNOT_LIKE_OWN_POST`**로 한다. 좋아요 원문(30 문서)은 403으로 적혀 있고 판정 순서도 "볼 수 있나"를 인증 확인보다 먼저 두었으나, 42 문서가 모든 기능의 기준이고 2026-10-06에 다시 확인되었으므로 42를 따른다 (spec 015도 같게 맞춤).
- 원문 42 §7 표의 "볼 수 없는 글 × 인증 전 = 404" 칸은 같은 문서 §3 판정 순서(계정 상태 ②가 대상 확인 ③보다 먼저)와 어긋난다. 판정 순서가 결정 기록(2026-10-03)에 있으므로 이 명세는 **403 `EMAIL_NOT_VERIFIED`**로 적었다 (표 4).
- 글 주인이 자기 글의 남의 댓글을 지우는 권한은 공통에서 **불가**(기존 결정 유지, 2026-10-06). 글 주인 삭제 권한은 **개인 확장**이다.
- 관리자 숨김 글을 공용 목록 조건에서 빼는 것은 43 문서의 기존 결정 변경안으로, 신고·숨김(Tier C)을 구현할 때 함께 적용한다.
- 공통 오류 응답 형식은 이 명세의 응답 코드 표를 팀 기준안으로 제안한 상태다. 응답 코드·이유 코드 값은 이 명세대로 쓰고, 본문 형식은 plan 단계에서 팀 공통 형식을 따른다.
- 표현 계층(화면 렌더링 또는 API)은 팀원마다 다를 수 있으나 판정 규칙과 응답 코드는 같다. 화면 요청에서 401은 로그인 화면 이동, 탈퇴 유예 403은 복구 화면 이동으로 나타난다.
