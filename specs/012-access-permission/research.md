# Research: 권한 매트릭스 (012-access-permission)

**Phase 0** · 2026-10-08 · 입력: [spec.md](./spec.md), [source-notes.md](./source-notes.md), `docs/42-permission-matrix.md`, 001~011 구현

이 명세는 **공통 규칙**이다. 판정 장치는 이미 있다: `AccountGuard`(① 로그인 ② 계정 상태, 001), `RestoreOnlySessionFilter`(탈퇴 유예, 001), `PostAccessPolicy`(③ 볼 수 있음, 006), 각 Service의 `author_id = :me` 조건(④ 소유), `GlobalExceptionHandler`(401/403/404/400/409 + 이유 코드). 사용자 지시: 질문 없이 기본값.

## R-1. 012에서 하는 일
- **Decision**: 새 장치를 만들지 않고, 지금 구현된 기능의 표 칸을 **한 곳의 매트릭스 통합 테스트**로 고정한다(FR-032): 표 1(글 상세: 발행 공개·비공개·수정 중·임시·휴지통·작성자 탈퇴 유예 × 비회원·인증 전·회원·작성자·관리자), 표 2(새 글·자동/수동 저장·발행·변경 취소·공개 범위·삭제·복구·영구 삭제 × 다섯 행위자), 표 7(프로필 수정·프로필 이미지·비밀번호·기본 공개 범위 × 비회원·인증 전·본인), 표 8(내 글 관리·사진 업로드·남의 사진 연결). 404 응답 본문은 행위자별로 "없는 글"과 같아야 한다.
- 표 3~6·9(댓글·좋아요·신고·팔로우·알림)와 표 1의 "관리자 숨김" 행은 해당 기능(014·015·022·018·017)이 같은 테스트 형식으로 **행을 추가**한다 — 각 명세 tasks에 "012 매트릭스 행 추가"를 둔다.

## R-2. 판정 순서 확인 (FR-004)
- **Decision**: 테스트에 순서 사례를 넣는다: 인증 전 회원이 남의 글을 저장 → 403(계정 상태가 대상보다 먼저), 비회원이 없는 글 → 401, 작성자가 휴지통 글 공개 범위 변경 → 404, 모르는 값으로 남의 글 공개 범위 변경 → 404(대상이 값 검사보다 먼저).

## R-3. 정지 회원 (FR-011, FR-014)
- 001 로그인 실패 처리(`ACCOUNT_SUSPENDED`)와 세션 삭제(`SessionRevoker`)가 있다. 정지 처리 화면은 022(관리자) 범위.
