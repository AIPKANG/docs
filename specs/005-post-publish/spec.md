## User Scenarios & Testing *(mandatory)*

### User Story 1 - 임시글을 발행해 누구나 읽게 한다 (Priority: P1)

작성자가 임시글의 제목·본문·태그·공개 범위를 정하고 [발행]을 누르면 글이 `/@블로그주소/posts/{글번호}`에 게시된다. 전체 공개면 로그인하지 않은 사람도 읽을 수 있다. 입력이 규칙에 맞지 않으면 발행되지 않고 칸마다 이유가 보인다.

**Why this priority**: C-POST-3(Tier A)의 첫 기준 "발행한 글은 누구나 읽는다"이며 블로그의 핵심 가치다.

**Independent Test**: 임시글 발행 → 비로그인으로 글 주소 조회 시 정상 표시 확인; 빈 제목으로 발행 → 거부 및 임시글 유지 확인.

**Acceptance Scenarios**:

1. **Given** 내용이 있는 임시글, **When** 작성자가 전체 공개로 발행하면, **Then** 글이 발행 상태가 되고 `/@블로그주소/posts/{글번호}`에서 비로그인 사용자도 읽을 수 있으며, 최초 발행 시각과 최초 공개 시각이 기록된다.
2. **Given** 제목이나 본문이 비어 있음(앞뒤 공백만 있는 경우 포함), **When** 발행하면, **Then** 거부되고 글은 임시글로 남으며 실패한 칸마다 이유(예: "제목을 입력해 주세요.")가 보인다.
3. **Given** 제목 101자 또는 본문 100,001자, **When** 발행하면, **Then** 각각 길이 초과로 거부된다.
4. **Given** 업로드가 끝나지 않은 사진 표시가 본문에 남음, **When** 발행하면, **Then** 업로드 대기 사진 오류로 거부되고 임시글로 남는다.
5. **Given** 태그 11개(기본 설정), **When** 발행하면, **Then** 태그 개수 초과로 거부된다. 대소문자·앞뒤 공백만 다른 태그는 하나로 합쳐진다.
6. **Given** 여러 칸이 동시에 규칙 위반, **When** 발행하면, **Then** 실패한 항목이 모두 한 번에 돌아온다.
7. **Given** 본문에 스크립트·이벤트 속성이 든 HTML, **When** 발행 후 글을 보면, **Then** 스크립트가 실행되지 않는다.
8. **Given** 발행한 글, **When** 목록 카드를 보면, **Then** 서버가 자동으로 만든 요약(코드 블록·이미지·표를 뺀 앞 200자)과 본문 첫 업로드 이미지의 썸네일이 쓰인다.

### User Story 2 - 발행한 글을 고쳐 다시 발행한다 (Priority: P1)

작성자가 발행한 글을 고쳐 다시 발행하면 내용이 반영되고 "수정됨 · 날짜"가 표시된다. 주소, 최초 발행일, 목록 위치, 조회수·좋아요·댓글은 그대로다. 고치는 동안 독자에게는 마지막 발행본이 보인다.

**Why this priority**: C-POST-3의 두 번째·세 번째 기준이다.

**Independent Test**: 발행 → 작업본 저장 후 비로그인 조회(이전 내용) → 다시 발행 → 내용 반영·주소·최초 발행일·반응 수 유지·"수정됨" 표시 확인.

**Acceptance Scenarios**:

1. **Given** 발행한 글과 저장된 작업본, **When** 비로그인 사용자가 조회하면, **Then** 마지막 발행본이 보인다.
2. **Given** 작업본이 있는 발행 글, **When** 작성자가 다시 발행하면, **Then** 새 내용이 보이고, 주소·최초 발행 시각·최초 공개 시각·조회수·좋아요·댓글은 그대로이며 작업본은 사라진다.
3. **Given** 다시 발행된 글, **When** 글 상세를 보면, **Then** "수정됨 · 10월 3일"처럼 마지막 다시 발행 날짜가 보인다. 최초 발행 때는 표시되지 않는다.
4. **Given** 발행 글, **When** 다시 발행하면서 공개 범위를 전체 공개 ↔ 비공개로 바꾸면, **Then** 바뀐 공개 범위로 반영된다.
5. **Given** 발행한 글, **When** 작성자가 임시글로 되돌리려 하면, **Then** 그런 기능은 없고 비공개로 바꾸는 방법만 있다.

### User Story 3 - 발행 버튼을 연달아 눌러도 한 번만 발행된다 (Priority: P1)

[발행]을 두 번 누르거나 네트워크가 요청을 다시 보내도 글은 한 번만 발행되고, 이미 성공한 발행에 대해 엉뚱한 충돌 창이 뜨지 않는다.

**Why this priority**: C-POST-3 기준 "연달아 눌러도 한 번만 발행된다"이며 헌법 원칙 V(같은 요청은 결과 한 번)다.

**Independent Test**: 같은 발행 요청 식별자로 동시 20건 → 편집 버전이 1만 증가하고 모두 같은 결과를 받는지 확인.

**Acceptance Scenarios**:

1. **Given** [발행]을 누름, **When** 응답을 기다리는 동안, **Then** 버튼이 비활성화되고 "발행 중…"이 보여 다시 누를 수 없다.
2. **Given** 같은 발행 요청 식별자로 동시에 20건, **When** 처리되면, **Then** 발행은 한 번만 일어나 편집 버전이 1만 증가한다.
3. **Given** 같은 식별자의 요청이 아직 처리 중, **When** 같은 식별자로 다시 요청하면, **Then** "처리 중" 상태 충돌을 받고 브라우저가 1초 뒤 같은 식별자로 재시도한다.
4. **Given** 같은 식별자의 발행이 이미 완료됨(10분 이내), **When** 같은 식별자로 다시 요청하면, **Then** 처음과 같은 성공 응답을 받고 추가 발행은 없다.
5. **Given** 같은 식별자로 다른 내용을 보냄, **When** 요청하면, **Then** 식별자 재사용 오류(422)로 거부된다.
6. **Given** 발행 처리 실패, **When** 같은 식별자로 다시 시도하면, **Then** 재시도가 허용된다.
7. **Given** 멱등성 기록 저장소 장애, **When** 동시에 두 번 발행하면, **Then** 글 잠금과 버전 확인으로 두 번째는 충돌이 되어 중복 발행이 없다.

### User Story 4 - 남의 글은 발행·수정할 수 없고 존재도 드러나지 않는다 (Priority: P1)

다른 회원이나 관리자가 남의 글을 발행·수정하려 하면 "없는 글"과 같은 404가 나오고 글은 바뀌지 않는다.

**Why this priority**: C-OWN-1(Tier A)과 C-POST-3 기준 5다.

**Independent Test**: 다른 회원·관리자로 발행 요청 → 404, 요청 전후 글의 모든 값이 같은지 확인.

**Acceptance Scenarios**:

1. **Given** 남의 글, **When** 회원이 발행·다시 발행을 요청하면, **Then** 404이고 내용·상태·편집 버전·수정 시각이 요청 전과 같다.
2. **Given** 남의 글, **When** 관리자가 발행·수정을 요청하면, **Then** 404다(관리자는 숨김만 가능).
3. **Given** 요청에 다른 사람의 작성자 값을 넣음, **When** 발행하면, **Then** 무시되고 로그인한 사람 기준으로만 판단한다.
4. **Given** 휴지통에 있는 자기 글, **When** 발행하면, **Then** 404다.
5. **Given** 비회원 / 이메일 인증 전 회원, **When** 발행하면, **Then** 각각 로그인 필요(401) / 이메일 미인증(403)이다.

---

### User Story 5 - 늦게 공개한 글도 공개한 시점의 위치에 나온다 (Priority: P2)

비공개로 발행했다가 나중에 전체 공개로 바꾸면, 그 글은 목록에서 처음 공개한 시점의 위치에 나온다. 공개 범위를 껐다 켜는 것만으로 글을 목록 맨 위로 끌어올릴 수는 없다.

**Why this priority**: 결정 기록("늦게 공개한 글의 목록 위치")이며 C-POST-3 기준 7이지만, 목록(C-READ-1)과 함께 완성된다.

**Independent Test**: 비공개 발행 → 다른 글들 발행 → 다시 발행으로 전체 공개 → 목록에서 공개 시점 위치 확인 → 비공개·재공개 후에도 위치가 그대로인지 확인.

**Acceptance Scenarios**:

1. **Given** 비공개로 발행한 글, **When** 나중에 전체 공개로 다시 발행하면, **Then** 최초 공개 시각이 그때 기록되고 목록에서 그 시점의 위치에 나온다.
2. **Given** 한 번 전체 공개된 적 있는 글, **When** 비공개로 바꿨다가 다시 공개하면, **Then** 최초 공개 시각은 처음 값 그대로이고 목록 위치도 그대로다.

---

### User Story 6 - 다른 곳에서 먼저 저장했으면 발행 전에 차이를 고른다 (Priority: P2)

발행 요청의 출발 버전이 현재 버전과 다르면(다른 탭·기기에서 먼저 저장) 발행하지 않고, 004 기능의 비교 창으로 사용자가 고르게 한다.

**Why this priority**: 결정 기록(여러 탭·기기 편집 충돌)의 발행 쪽 적용이다.

**Independent Test**: 탭 A에서 자동 저장 → 탭 B(옛 버전)에서 발행 → 충돌 응답과 비교 창 확인, 글은 그대로인지 확인.

**Acceptance Scenarios**:

1. **Given** 다른 탭이 더 새 버전을 저장함, **When** 옛 버전에서 출발한 탭이 발행하면, **Then** 버전 충돌(409)과 함께 서버 쪽 제목·본문·버전·저장 시각이 돌아오고 발행되지 않는다.
2. **Given** 발행이 처리되는 사이 다른 탭에서 자동 저장이 들어옴, **When** 발행이 끝나면, **Then** 그 새 자동 저장 내용은 지워지지 않는다.

---

### Edge Cases

- 제목의 보이지 않는 글자(폭 0 문자 등), 방향 뒤집기 문자, 제어 문자 → 제거한 뒤 길이를 검사한다. 분리형(NFD) 한글 제목 → NFC로 정리.
- 태그가 0개 → 허용. 각 태그 1~30자를 벗어나거나 허용 문자 외 → 태그 오류.
- 공개 범위에 정해지지 않은 값 → 공개 범위 오류(친구 공개는 구현한 팀원만 허용).
- 수정 중인 글에서 [변경 취소] → 작업본이 사라지고 발행본 그대로(004).
- 발행 직후 저장소 정리가 실패해도 발행 결과는 유지된다(정리는 커밋 이후에만).
- 발행 후 부가 처리(알림·검색 색인·sitemap 등)가 실패해도 발행은 성공한다.
- 탭 두 개에서 동시에 [발행](서로 다른 요청 식별자) → 한 요청씩 처리되어 두 번째는 버전 충돌이 된다.

## Requirements *(mandatory)*

### Functional Requirements

**상태와 전이**

- **FR-001**: System MUST 글 상태를 임시글 / 발행됨 / 수정 중(발행됨 + 작업본 있음)으로 구분하고, 임시글 → 발행됨, 발행됨 → 수정 중(저장 시), 수정 중 → 발행됨(다시 발행 또는 변경 취소) 전이만 허용해야 한다. 발행됨 → 임시글 전이는 두지 않으며, 내리고 싶으면 비공개로 바꾼다. (C-POST-3)
- **FR-002**: System MUST 임시글은 작성자에게만 보이고 독자에게는 404, 수정 중인 글은 독자에게 마지막 발행본을 보여줘야 한다. (C-POST-3, C-READ-2)

**입력 검증**

- **FR-003**: System MUST 제목을 필수로 하고, NFC 정규화 → 보이지 않는 글자·방향 제어 문자·제어 문자 제거 → 앞뒤 공백 제거 후 1~100자로 검사해야 한다(`TITLE_REQUIRED`, `TITLE_TOO_LONG`). 제목은 글자로만 표시한다. (C-POST-1)
- **FR-004**: System MUST 본문을 필수로 하고 앞뒤 공백 제거 후 1자 이상, 최대 100,000자로 검사해야 한다(`CONTENT_REQUIRED`, `CONTENT_TOO_LONG`). 본문은 Markdown 원문으로 저장한다. (C-POST-1)
- **FR-005**: System MUST 태그를 0개부터 설정된 최대 개수(기본 10개)까지 받고, 소문자로 바꾸고 앞뒤 공백을 지운 뒤 중복을 제거하며 각 1~30자로 검사해야 한다(`TOO_MANY_TAGS`, `INVALID_TAG`). 허용 문자 등 세부 정규화는 태그 기능(C-TAG-1)의 규칙을 따른다. (C-TAG-1)
- **FR-006**: System MUST 공개 범위를 `PUBLIC` / `PRIVATE`로 검사해야 한다(`INVALID_VISIBILITY`). 친구 공개(`FRIENDS`)는 구현한 경우에만 허용한다. (C-POST-4)
- **FR-007**: System MUST 본문에 업로드가 끝나지 않은 사진 표시(`local:` 주소)가 있으면 `PENDING_IMAGES`로 발행을 거부해야 한다. (C-IMG-1)
- **FR-008**: System MUST 검증 실패 시 실패한 항목을 모두 담아 돌려주고(항목·코드·문구), 글은 그대로(임시글이면 임시글로) 남겨야 한다.

**발행 처리**

- **FR-009**: System MUST 발행 시 본문을 안전한 HTML로 렌더링·정화해 저장하고(스크립트 미실행), 요약(정화된 결과에서 코드 블록·이미지·표를 뺀 글자 앞 200자)과 썸네일(본문 첫 업로드 이미지의 640px 썸네일)을 자동으로 만들어야 한다. 렌더링 세부는 콘텐츠 정화 기능(12)을 따른다. (C-POST-1)
- **FR-010**: System MUST 발행 요청의 출발 버전이 현재 편집 버전(서버 자동 저장·작업본·글 중 가장 높은 버전)과 다르면 발행하지 않고 버전 충돌(409)과 서버 쪽 제목·본문·버전·저장 시각을 돌려줘야 한다. (C-POST-2, C-POST-3)
- **FR-011**: System MUST 작성자 확인·버전 확인·태그 확정·사진 연결 갱신·글 반영·작업본 삭제를 하나의 원자적 작업으로 처리하고, 같은 글에 대한 동시 발행은 한 요청씩 처리해야 한다.
- **FR-012**: System MUST 발행 성공 시 상태를 발행됨으로 하고 편집 버전을 1 올리며, 최초 발행이면 최초 발행 시각을 한 번만 기록해야 한다.
- **FR-013**: System MUST 글이 처음으로 "발행됨 + 전체 공개"가 되는 순간에만 최초 공개 시각을 기록하고, 이후 공개 범위를 바꿔도 처음 값을 유지해야 한다. 공개 범위만 바꾸는 기능도 같은 규칙을 따른다. 홈·블로그 목록은 이 값으로 정렬한다. (C-POST-3, C-READ-1)
- **FR-014**: System MUST 다시 발행할 때마다 "수정됨" 시각을 기록하고 글 상세에 "수정됨 · 날짜"로 보여줘야 한다. 최초 발행과 자동 저장 반영은 이 시각을 바꾸지 않는다. (C-POST-3)
- **FR-015**: System MUST 다시 발행해도 글 주소(`/@블로그주소/posts/{글번호}`), 최초 발행 시각, 최초 공개 시각, 조회수·좋아요·댓글을 유지해야 한다. 다시 발행하면서 공개 범위는 바꿀 수 있다. (C-POST-3)
- **FR-016**: System MUST 발행이 확정(커밋)된 뒤에만 서버 자동 저장 버퍼를 지워야 하며, 발행 때 확인한 버전 이하인 경우에만 지워 그 사이 들어온 새 자동 저장을 보존해야 한다.
- **FR-017**: System MUST 발행 확정 후 최초 발행이면 "글 발행됨", 다시 발행이면 "글 수정됨" 사건을 알려, 알림·검색 색인·sitemap 등 부가 기능이 기존 기능을 고치지 않고 붙을 수 있게 해야 하며, 부가 기능 실패가 발행 결과를 바꾸지 않아야 한다.

**연타·재전송 방지**

- **FR-018**: System MUST [발행]을 누르면 응답을 받을 때까지 버튼을 비활성화하고 "발행 중…"을 보여줘야 한다.
- **FR-019**: System MUST 발행 요청마다 브라우저가 만든 고유 요청 식별자를 받아 10분 동안 기억하고: 처음이면 처리, 처리 중이면 "처리 중" 충돌(409, 브라우저는 1초 뒤 같은 식별자로 재시도), 완료됐으면 저장된 응답을 그대로 돌려주고(발행은 한 번), 같은 식별자로 다른 내용이면 422로 거부해야 한다. 처리 실패 시에는 같은 식별자로 다시 시도할 수 있게 해야 한다. (C-POST-3)
- **FR-020**: System MUST 요청 식별자 저장소가 장애여도 글 잠금과 버전 확인으로 중복 발행을 막아야 한다.

**권한**

- **FR-021**: System MUST 발행·다시 발행을 글 작성자만 할 수 있게 하고, 없는 글·남의 글·휴지통 글은 404로 응답하며 글을 바꾸지 않아야 한다. 관리자도 남의 글 내용을 발행·수정할 수 없다. 작성자는 요청 값이 아닌 로그인 정보로만 판단한다. (C-OWN-1, C-POST-3)
- **FR-022**: System MUST 비회원의 발행은 로그인 필요(401, 서버 렌더링 화면은 로그인 화면으로 이동), 이메일 인증 전 회원은 이메일 미인증(403)으로 거부해야 한다. 판정은 로그인 → 계정 상태 → 대상 볼 수 있음 → 행동 권한 → 업무 규칙 순서다. (42 §3)
- **FR-023**: System MUST 화면에서 글 상세의 [수정] 버튼을 작성자에게만 보여줘야 한다(서버 검사와 별도). (C-OWN-1)

### Key Entities *(include if feature involves data)*

- **글(Post)**: 작성자, 제목, 본문 원문, 정화된 HTML, 요약, 썸네일 주소, 공개 범위, 상태(임시/발행), 편집 버전, 시각들 — 만든 시각, 마지막 수정 시각(자동 저장 반영 포함), 최초 발행 시각(불변), 최초 공개 시각(불변, 목록 정렬 기준), 수정됨 시각(다시 발행 때만), 조회수·좋아요 수·댓글 수.
- **작업본(Post Draft)**: 발행 글의 고치는 중인 내용. 다시 발행하면 사라진다(004).
- **태그·글-태그 연결**: 발행할 때 확정되는 글의 태그 목록(C-TAG-1).
- **글-사진 연결**: 발행할 때 본문에서 찾은 사진과의 연결. 빠진 사진은 연결 해제 시각이 기록된다(008).
- **발행 요청 기록**: 회원별 발행 요청 식별자, 요청 내용 요약, 처리 상태·응답. 10분 보관.
- **발행 사건**: "글 발행됨"(최초), "글 수정됨"(다시 발행). 부가 기능이 구독한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 전체 공개로 발행한 글은 발행 직후 비로그인 사용자가 글 주소로 100% 열람할 수 있다.
- **SC-002**: 다시 발행 전후로 주소·최초 발행 시각·최초 공개 시각·조회수·좋아요·댓글 값이 다른 경우가 0건이다.
- **SC-003**: 작업본 저장 상태에서 비로그인 사용자가 본 내용은 100% 마지막 발행본과 같다.
- **SC-004**: 같은 요청 식별자로 동시 20건을 보내도 편집 버전은 정확히 1 증가한다.
- **SC-005**: 남의 글에 대한 발행·수정 요청은 100% 404이고 요청 전후 글 값이 같다.
- **SC-006**: 제목·본문이 비었거나 업로드 미완료 사진이 있는 발행 요청은 100% 거부되고 글은 임시글로 남는다.
- **SC-007**: 비공개로 발행했다가 공개한 글은 목록에서 공개한 시점의 위치에 나오고, 공개 범위를 껐다 켜도 위치가 바뀌지 않는다.
- **SC-008**: XSS 공격 문자열 목록을 본문·제목에 넣어 발행해도 브라우저에서 스크립트가 실행되는 경우가 0건이다.
- **SC-009**: 부가 기능(알림·색인 등)이 실패해도 발행 성공률은 영향을 받지 않는다.

## Assumptions

- Tier A(공통 필수): C-POST-3, C-POST-1(발행 시 렌더링·정화 연결). 결정 기록 2026-10-02의 "발행 → 임시글 되돌리기 없음", "'수정됨' 표시", "늦게 공개한 글의 목록 위치", "발행 연타 방지", "태그·본문 제한(태그 기본 10개, 본문 100,000자)", "글 제목 정리" 결정을 따른다.
- 태그 최대 개수는 설정값(기본 10)이다. 강성찬은 5개로 설정할 수 있다.
- 발행 이력·되돌리기는 김민서 개인 확장이며 공통에서는 이력을 남기지 않는다. 글 slug 주소는 개인 확장(01 Q4)이고 공통은 글 번호 주소다.
- 화면 구성은 팀원마다 다를 수 있다(REST 또는 서버 렌더링 폼). 서버 렌더링이면 결과에 따라 글 상세로 이동하거나 에디터를 다시 보여준다.
- 공개 범위만 바꾸는 기능(C-POST-4), 목록 정렬·표시(C-READ-1), 렌더링·정화 세부(12), 태그 세부(22), 사진 연결(008)은 각 기능 명세의 범위다. 이 명세는 발행 시점의 연결 규칙만 정한다.
- 수치(제목·본문 길이, 태그 수·길이, 요약 길이, 요청 식별자 보관 10분, 재시도 1초)는 설정값이다.
