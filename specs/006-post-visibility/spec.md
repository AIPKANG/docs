# Feature Specification: 글 공개 범위 (Post Visibility)

**Feature Branch**: `006-post-visibility`

**Created**: 2026-10-07

**Status**: Draft

**Input**: docs/ 원문 문서에서 변환: docs/06-visibility.md (연관: docs/01-common-requirements.md §2·§4, docs/05-publish.md §3, docs/42-permission-matrix.md §3·§5, docs/43-report-hide.md §4)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 나만 보기 글이 밖으로 새지 않는다 (Priority: P1)

작성자는 글을 `PRIVATE`(나만 보기)로 발행해 자신만 읽을 수 있게 한다. 작성자가 아닌 사람(비회원, 다른 회원, 관리자)은 그 글이 있다는 사실조차 알 수 없다. 상세 화면은 없는 글과 똑같은 404이고, 홈·개인 블로그·태그·검색·sitemap 등 어떤 목록에도 나오지 않으며 글 수에도 세지 않는다.

**Why this priority**: 이 기능의 핵심 목표("친구나 나만 보려고 쓴 글이 밖으로 새지 않는다")이며 공통 필수(Tier A) 완료 기준이다. 이것이 깨지면 다른 공개 범위 기능은 의미가 없다.

**Independent Test**: `PUBLIC`/`PRIVATE` 글을 하나씩 만들고, 공개 범위 × 보는 사람(비회원/다른 회원/작성자/관리자) × 노출 위치(상세/홈/블로그 목록/블로그 글 수/태그/검색/sitemap/댓글) 모든 조합을 자동 테스트로 확인한다.

**Acceptance Scenarios**:

1. **Given** 작성자 A의 발행된 `PRIVATE` 글, **When** 비회원·다른 회원·관리자가 상세 주소를 열면, **Then** 404 응답과 공통 "볼 수 없는 글" 화면이 보인다.
2. **Given** 작성자 A의 발행된 `PRIVATE` 글, **When** A가 상세 주소를 열면, **Then** 글이 보인다.
3. **Given** `PRIVATE` 글과 존재하지 않는 글 번호, **When** 권한 없는 사람이 각각 열면, **Then** 상태 코드·본문·링크 미리보기 문구가 완전히 같다.
4. **Given** `PRIVATE` 글, **When** 홈·개인 블로그(작성자 본인이 볼 때 포함)·태그별 목록·검색·sitemap·RSS를 조회하면, **Then** 그 글은 어디에도 나오지 않고 블로그 글 수·태그 글 수에도 세지 않는다.
5. **Given** `PRIVATE` 글에 달린 기존 댓글·좋아요, **When** 다른 사람이 댓글·좋아요를 보거나 쓰려 하면, **Then** 글과 똑같이 404로 숨겨진다.

### User Story 2 - 발행 후 공개 범위 바로 바꾸기 (Priority: P1)

작성자는 다시 발행하지 않고 공개 범위를 즉시 바꿀 수 있다. 바꿔도 "수정됨" 표시, 수정 중인 작업본, 댓글·좋아요는 그대로 남고, 공개 범위를 껐다 켜는 것으로 글을 목록 맨 위로 끌어올릴 수 없다.

**Why this priority**: 공개 범위는 언제든 다시 바꿀 수 있어야 하며, 변경이 다른 데이터를 훼손하지 않아야 Tier A 완료 기준(#4~#6)을 만족한다.

**Independent Test**: 발행 글의 공개 범위를 `PUBLIC → PRIVATE → PUBLIC`으로 바꾸며 수정됨 표시, 작업본, 댓글·좋아요 수, 최초 공개 시각, 목록 위치를 전후 비교한다.

**Acceptance Scenarios**:

1. **Given** 발행된 `PUBLIC` 글, **When** 작성자가 `PRIVATE`로 바꾸면, **Then** 다시 발행 없이 즉시 적용되고 "수정됨" 표시 시각은 바뀌지 않는다.
2. **Given** 수정 중인 작업본이 있는 발행 글, **When** 작성자가 공개 범위를 바꾸면, **Then** 작업본과 편집 버전은 그대로이고 변경은 성공한다.
3. **Given** 처음 공개된 시각이 기록된 글, **When** 공개 → 비공개 → 공개로 바꾸면, **Then** 처음 공개된 시각은 최초 값 그대로이고 목록 위치도 그대로다.
4. **Given** `PRIVATE`로 발행했던 글(최초 공개 시각 없음), **When** 처음으로 `PUBLIC`으로 바꾸면, **Then** 그 순간이 최초 공개 시각이 되어 전체 목록 맨 위에 나온다.
5. **Given** 댓글 3개·좋아요 5개가 있는 글, **When** 비공개로 바꿨다가 다시 공개하면, **Then** 댓글·좋아요가 삭제되지 않고 그대로 다시 보인다.
6. **Given** 남의 글, 휴지통 글, 없는 글, **When** 공개 범위 변경을 요청하면, **Then** 404이고 글은 바뀌지 않는다.
7. **Given** 현재 값과 같은 공개 범위, **When** 다시 요청하면, **Then** 아무것도 바뀌지 않고 성공으로 응답한다.

### User Story 3 - 새 글의 기본 공개 범위 설정 (Priority: P2)

회원은 설정 화면에서 "새 글 기본 공개 범위"를 정하고, [새 글]로 만든 임시글은 그 값으로 시작한다. 발행 설정에서 글마다 바꿀 수 있다.

**Why this priority**: 사용 편의 기능이며, 기본값이 `PUBLIC`이라 없어도 핵심 흐름은 동작한다. 단 Tier A 완료 기준 #7에 포함된다.

**Independent Test**: 기본 공개 범위를 `PRIVATE`로 바꾼 뒤 새 글을 만들어 초기 공개 범위를 확인한다.

**Acceptance Scenarios**:

1. **Given** 새로 가입한 회원, **When** 새 글을 만들면, **Then** 공개 범위는 `PUBLIC`으로 시작한다.
2. **Given** 기본 공개 범위를 `PRIVATE`로 바꾼 회원, **When** 새 글을 만들면, **Then** 공개 범위는 `PRIVATE`로 시작하고 발행 설정에서 바꿀 수 있다.
3. **Given** 임시글, **When** 작성자가 공개 범위를 바꾸면, **Then** "발행할 때 쓸 공개 범위" 값만 저장되고 임시글은 여전히 작성자만 본다.

### User Story 4 - 친구 공개 (선택 구현 규격) (Priority: P3)

친구 공개(`FRIENDS`)를 구현하기로 한 팀원은 공통 규격을 그대로 따른다. 회원은 상대 블로그에서 친구 요청을 보내고, 상대가 수락하면 서로의 `FRIENDS` 글을 볼 수 있다. 거절·취소·끊기는 상대에게 알리지 않는다.

**Why this priority**: 공통 구현 범위는 `PUBLIC`/`PRIVATE`이고 `FRIENDS`는 선택 구현이다. 구현하는 사람끼리 규칙을 같게 맞추기 위해 명세에 둔다.

**Independent Test**: 두 회원 간 요청 → 수락 후 `FRIENDS` 글 상세·블로그 목록 노출을 확인하고, 친구를 끊은 직후 404·목록 제외를 확인한다.

**Acceptance Scenarios**:

1. **Given** A와 B가 수락된 친구, **When** B가 A의 `FRIENDS` 글을 열면, **Then** 글이 보이고 A의 블로그 목록에도 그 글이 포함된다.
2. **Given** 친구가 아닌 회원 C, **When** A의 `FRIENDS` 글을 열면, **Then** 404이고 검색 엔진용 `noindex`가 적용된다.
3. **Given** A와 B가 동시에 서로에게 친구 요청, **When** 두 요청이 처리되면, **Then** 친구 관계는 하나만 생기고, 상대가 이미 보낸 요청이 있으면 바로 수락된다.
4. **Given** A가 B와 친구를 끊음, **When** B가 A의 `FRIENDS` 글을 열면, **Then** 그 순간부터 404이고 목록에서도 사라진다.
5. **Given** `FRIENDS` 글, **When** 홈·태그·검색·sitemap·RSS를 조회하면, **Then** 친구가 보더라도 나오지 않는다.
6. **Given** 친구가 없는데 기본 공개 범위가 `FRIENDS`인 작성자, **When** 발행 설정을 열면, **Then** "아직 친구가 없어서 지금은 나만 볼 수 있어요. [친구 초대] [전체 공개로 바꾸기]" 안내가 보인다.
7. **Given** `FRIENDS` 규격을 적용하지 않은 환경, **When** 공개 범위로 `FRIENDS`를 보내면, **Then** 잘못된 공개 범위 오류(400)로 거부된다.

---

### Edge Cases

- 임시글의 공개 범위 값은 읽기 권한에 영향이 없다. 임시글은 공개 범위와 상관없이 작성자만 본다.
- 휴지통(삭제된) 글은 공개 범위와 상관없이 아무에게도 보이지 않는다(작성자도 상세 404, 휴지통 목록에서만).
- 탈퇴를 신청한(유예 중) 작성자의 글은 공개 범위와 상관없이 모든 목록·상세에서 제외된다.
- 관리자도 남의 `PRIVATE`·`FRIENDS` 글은 볼 수 없다.
- 관리자가 숨긴 글은 작성자 외에게 비공개 글과 똑같이 취급된다(Tier C, 43 문서).
- 작성자 본인이 자기 블로그 페이지를 볼 때도 `PRIVATE` 글은 표시되지 않는다(내 글 관리에서만 보임).
- 이미 화면에 떠 있던 목록 카드의 글이 비공개로 바뀐 뒤 누르면 404다.
- 사진은 공개 범위와 상관없이 주소를 알면 볼 수 있다(결정 사항, 이미지 기능 참고).
- 공개 범위를 모르는 값으로 보내면 400으로 거부된다.
- 동시에 같은 글의 공개 범위를 바꾸는 요청이 와도 최초 공개 시각 규칙이 깨지지 않아야 한다.

## Requirements *(mandatory)*

### Functional Requirements

**공개 범위 값과 읽기 판정**

- **FR-001**: 시스템은 글의 공개 범위로 `PUBLIC`(누구나, 비회원 포함)과 `PRIVATE`(작성자만)를 MUST 지원한다. `FRIENDS`(작성자 + 수락된 친구)는 선택 구현 규격이다. 값 이름으로 `PROTECTED`는 쓰지 않는다. (C-POST-4)
- **FR-002**: 공개 범위는 발행된 글에만 읽기 권한으로 작용해야 MUST 한다. 임시글은 공개 범위와 상관없이 작성자만 보며, 임시글의 값은 "발행할 때 쓸 공개 범위"로만 저장된다. (C-POST-4)
- **FR-003**: 글 하나를 읽을 수 있는지에 대한 판단은 시스템 안의 단일 접근 정책 한곳에서만 MUST 이뤄져야 하며, 판정 순서는 권한 매트릭스(42 §3)의 순서(로그인 → 계정 상태 → 대상 볼 수 있음 → 행동 권한 → 업무 규칙)를 따른다. (C-POST-4, C-OWN-1)
- **FR-004**: 읽기 판정과 모든 목록 조건은 휴지통 글 제외와 탈퇴 유예 작성자의 글 제외를 공개 범위 판단보다 먼저 MUST 적용해야 한다. (C-POST-4, C-POST-5)
- **FR-005**: 관리자를 포함해 작성자가 아닌 사람은 남의 `PRIVATE` 글(및 친구가 아닌 경우 `FRIENDS` 글)을 MUST NOT 볼 수 있어야 한다. (C-POST-4, C-OWN-1)

**404와 존재 은닉**

- **FR-006**: 볼 수 없는 글을 열면 시스템은 404를 MUST 응답해야 하며, "없는 글"과 "권한 없는 글"을 구분하는 상태 코드·응답 본문·사용자 대상 메시지를 MUST NOT 보내야 한다. (C-POST-4, C-READ-2)
- **FR-007**: 볼 수 없는 글과 없는 글의 화면은 공통 안내 페이지와 공통 링크 미리보기 문구(제목 "볼 수 없는 글이에요", 설명 "친구 공개·비공개 글이거나 삭제된 글입니다.")와 검색 엔진 비수집 지시를 똑같이 MUST 사용해야 한다. (C-POST-4)
- **FR-008**: `PUBLIC`이 아닌 글의 응답은 공유 캐시(CDN 등)에 MUST NOT 저장되어야 한다(개인용·저장 금지 캐시 지시). (C-POST-4)

**노출 규칙**

- **FR-009**: `PUBLIC`이 아닌 글은 홈(최신·인기), 개인 블로그 목록(남이 볼 때, `FRIENDS`는 친구가 볼 때 예외), 태그별 목록·태그 글 수·인기 태그, 검색, AI 추천, 관련 글, sitemap, RSS 어디에도 MUST NOT 나와야 하며 블로그 글 수에도 MUST NOT 세져야 한다. (C-POST-4, C-READ-1, C-BLOG-1)
- **FR-010**: 작성자 본인이 보는 개인 블로그 페이지에도 `PRIVATE` 글은 MUST NOT 표시되어야 하며, 비공개 글은 내 글 관리에서만 공개 범위 배지(🌐 / 👥 / 🔒)와 함께 보여야 한다. (C-BLOG-1, C-MANAGE-1)
- **FR-011**: 모든 목록 조회는 공개 범위·삭제·탈퇴 조건이 포함된 공용 목록 조건만 MUST 사용해야 하며, 목록마다 조건을 따로 작성해서는 안 된다. (C-POST-4)
- **FR-012**: 댓글·좋아요를 보거나 쓰는 것은 그 글을 읽을 수 있는 사람에게만 MUST 허용되어야 한다. (C-POST-4)
- **FR-013**: 공개 범위별 읽기 판정과 목록 조건은 기존 규칙을 고치지 않고 새 규칙을 추가하는 방식으로 MUST 확장 가능해야 한다(예: `FRIENDS`, 개인 확장의 그룹 공개·링크 공개). (C-POST-4)

**공개 범위 변경**

- **FR-014**: 작성자는 다시 발행하지 않고 발행 글의 공개 범위를 즉시 MUST 바꿀 수 있어야 하며, 수정 중인 작업본과 편집 버전에 영향을 주지 않아야 한다. (C-POST-4)
- **FR-015**: 공개 범위를 바꿔도 "수정됨" 시각은 MUST NOT 바뀌어야 한다. (C-POST-4)
- **FR-016**: 최초 공개 시각은 글이 처음으로 "발행됨 + `PUBLIC`"이 되는 순간에만 MUST 기록되고 이후 유지되어야 한다. 공개 → 비공개 → 공개로 바꿔도 처음 값이 유지된다. (C-POST-4, C-POST-3)
- **FR-017**: 비공개로 바꿔도 댓글·좋아요는 MUST NOT 삭제되어야 하며, 글을 읽을 수 없게 된 사람에게는 함께 숨겨지고 다시 공개하면 돌아와야 한다. (C-POST-4)
- **FR-018**: 남의 글, 휴지통 글, 없는 글에 대한 공개 범위 변경은 404로 MUST 거부되고 글은 바뀌지 않아야 한다. 비회원은 401, 이메일 인증 전·탈퇴 유예 회원은 403(이유 코드 포함)이다. (C-OWN-1)
- **FR-019**: 현재와 같은 값으로 변경을 요청하면 아무것도 바뀌지 않고 성공으로 MUST 응답해야 한다. 모르는 값이나 규격 미적용 환경의 `FRIENDS`는 400(잘못된 공개 범위)으로 거부한다.
- **FR-020**: 같은 글에 대한 공개 범위 변경이 동시에 들어와도 한 번에 하나씩 처리되어 최초 공개 시각 규칙이 MUST 깨지지 않아야 한다.
- **FR-021**: 공개 범위 변경이 확정된 뒤 시스템은 "공개 범위 바뀜(글, 이전 값, 새 값)" 사건을 MUST 알려야 하며, 검색 색인·sitemap 갱신과 알림 등 부가 기능은 이 사건을 구독해 붙는다. 부가 기능의 실패가 변경을 실패시켜서는 안 된다.

**기본 공개 범위**

- **FR-022**: 회원마다 "새 글 기본 공개 범위"가 MUST 있어야 하고 기본값은 `PUBLIC`이다. 본인만 설정 화면에서 바꿀 수 있다. (C-POST-4)
- **FR-023**: [새 글]로 만든 임시글의 공개 범위 초기값은 작성자의 기본 공개 범위여야 MUST 하며, 발행 설정에서 글마다 바꿀 수 있어야 한다. (C-POST-4)

**친구 공개 규격 (선택 구현, 구현 시 MUST)**

- **FR-024**: 친구 관계는 상호 친구(요청 → 수락)이며, 두 회원 사이에는 관계가 최대 하나만 MUST 존재해야 한다. 동시에 서로 요청해도 중복이 생기지 않고, 상대가 이미 보낸 요청이 있으면 바로 수락된다.
- **FR-025**: 자기 자신에게는 친구 요청을 할 수 없고, 이미 친구거나 요청 중이면 아무것도 바뀌지 않아야 MUST 한다.
- **FR-026**: 받은 요청은 설정의 "받은 친구 요청"에서 수락·거절할 수 있어야 하며, 거절·요청 취소·친구 끊기는 관계를 삭제하고 상대에게 MUST NOT 알려야 한다. 친구 목록은 본인만 볼 수 있다.
- **FR-027**: 친구를 끊는 순간부터 상대는 내 `FRIENDS` 글을 MUST NOT 볼 수 있어야 한다(상세 404, 목록에서 사라짐).
- **FR-028**: 친구가 보는 개인 블로그 목록은 `PUBLIC`과 `FRIENDS` 글을 포함하고 발행 시각 최신순으로 정렬해야 MUST 하며, 그 밖의 모든 공개 목록은 `PUBLIC`만, 최초 공개 시각 순이다. `FRIENDS → PUBLIC` 전환 시 그 순간이 최초 공개 시각이 된다.
- **FR-029**: 친구가 없는데 기본 공개 범위가 `FRIENDS`인 작성자에게 발행 설정에서 "아직 친구가 없어서 지금은 나만 볼 수 있어요. [친구 초대] [전체 공개로 바꾸기]" 안내를 MUST 보여야 한다.

### Key Entities *(include if feature involves data)*

- **글(Post)의 공개 범위**: 글마다 하나의 공개 범위 값(`PUBLIC` / `PRIVATE`, 규격 적용 시 `FRIENDS`). 글 상태(임시/발행), 삭제 여부, 최초 공개 시각, 발행 시각, "수정됨" 시각과 함께 읽기 판정에 쓰인다.
- **회원의 기본 공개 범위**: 회원마다 하나, 새 글의 초기 공개 범위. 기본값 `PUBLIC`.
- **친구 관계(Friendship, 선택 구현)**: 두 회원 쌍에 하나. 요청한 사람, 상태(요청 중 / 수락됨), 요청 시각, 수락 시각을 가진다. 수락됨이면 수락 시각이 반드시 있다.
- **공개 범위 규칙**: 공개 범위 값마다 "읽을 수 있는가"와 "목록에 포함되는 조건"을 정의하는 규칙 단위. 새 공개 범위는 규칙을 추가해 확장한다.
- **공개 범위 바뀜 사건**: 글, 이전 값, 새 값. 변경 확정 후 부가 기능에 전달된다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 공개 범위 × 보는 사람(비회원/다른 회원/친구/작성자/관리자) × 노출 위치(상세/홈/블로그 목록/블로그 글 수/태그/검색/sitemap/댓글) 매트릭스의 모든 조합에서 비공개 글 노출이 0건이다.
- **SC-002**: 볼 수 없는 글과 없는 글의 응답(상태 코드·본문·미리보기 문구)을 비교했을 때 차이가 0건이다.
- **SC-003**: 공개 범위를 공개 → 비공개 → 공개로 바꾼 모든 테스트 글에서 최초 공개 시각·"수정됨" 시각·작업본·댓글 수·좋아요 수 변화가 0건이다.
- **SC-004**: 작성자는 공개 범위를 한 번의 동작(다시 발행 없이)으로 바꿀 수 있고, 바뀐 결과는 바로 다음 조회부터 모든 노출 위치에 반영된다.
- **SC-005**: 새 글의 100%가 작성자의 기본 공개 범위로 시작한다.
- **SC-006**: (규격 적용자) 친구를 끊은 직후 상대의 `FRIENDS` 글 상세 요청 100%가 404다.

## Assumptions

- **Tier**: C-POST-4는 Tier A(공통 필수). 공통 구현 범위는 `PUBLIC`·`PRIVATE`이고, `FRIENDS`는 공통 규격만 정의한 선택 구현이다(결정 기록 2026-10-02 "친구 공개"). User Story 4와 FR-024~FR-029는 친구 공개를 구현하는 사람에게만 적용된다.
- **결정 기록에서 가져온 사항**: 값 이름 `PUBLIC`/`FRIENDS`/`PRIVATE`, 기본 공개 범위 `PUBLIC`, 권한 없음 응답 404(존재 은닉, 미리보기까지 동일), 공개 범위 변경은 다시 발행 없이 즉시·"수정됨" 유지·댓글·좋아요는 숨김만, 내 블로그에 내 비공개 글 미표시, 늦게 공개한 글은 최초 공개 시각으로 정렬(2026-10-02).
- **개인 확장**: 여러 글 공개 범위 한 번에 바꾸기, 그룹 공개·링크 공개(강성찬)는 개인 확장이며 공개 범위 규칙 추가로 붙인다. 강성찬의 "첫 공개 응원" 알림은 공개 범위 바뀜 사건의 구독자로 붙는다.
- **관리자 숨김(Tier C)**: 43 문서가 공용 목록 조건과 읽기 판정에 "숨김 제외(작성자 제외)"를 추가한다. 이 명세는 그 확장을 막지 않으며, 숨김 자체의 규칙은 신고·숨김 기능 명세에서 다룬다.
- **사진 접근**: 비공개 글의 사진은 주소를 알면 볼 수 있다(결정 기록 2026-10-02 Q10). 친구 공개를 공통에 넣으면 재검토한다.
- **신고 처리 화면**에서 관리자가 비공개 글을 어떻게 보는지는 Tier C에서 따로 정한다(이 명세 범위 밖).
- 검색·sitemap·RSS·태그·인기 글 기능 자체는 각자의 명세에서 다루며, 이 명세는 그 기능들이 따라야 할 공개 범위 조건만 정한다.
