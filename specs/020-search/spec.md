## User Scenarios & Testing *(mandatory)*

### User Story 1 - 공개 글 검색 (Priority: P1)

방문자(비회원 포함)는 검색어를 입력해 제목·태그·본문에 그 단어가 들어간 공개 글을 홈과 같은 카드로 9개씩 찾는다. 한글 단어의 일부(예: "트랜잭")로도 찾을 수 있고, 띄어쓰기로 여러 단어를 넣으면 모든 단어가 들어간 글만 나온다. 비공개·삭제된 글은 절대 나오지 않는다.

**Why this priority**: 검색의 핵심 가치이며 공개 범위 규칙(404 원칙)과 직결된다.

**Independent Test**: 공개·비공개·친구 공개·휴지통·탈퇴 유예 작성자 글에 같은 단어를 넣고 검색해 공개 글만 나오는지, "트랜잭"으로 "트랜잭션" 글을 찾는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 단어를 가진 공개 글, 비공개 글, 친구 공개 글, 휴지통 글, 탈퇴 유예 작성자의 글, 관리자가 숨긴 글, **When** 그 단어로 검색한다, **Then** 공개·발행 글만 나온다.
2. **Given** 본문에 "트랜잭션"이 있는 공개 글, **When** "트랜잭"(3글자 이상)으로 검색한다, **Then** 그 글이 나온다.
3. **Given** "트랜잭션 정리"를 입력, **When** 검색한다, **Then** 두 단어가 모두 들어간 글만 나온다.
4. **Given** 대문자로 쓴 "REQUIRES_NEW"와 소문자 검색어, **When** 검색한다, **Then** 대소문자 구분 없이 찾는다.
5. **Given** "100% 할인", "snake_case"로 검색, **When** 결과를 본다, **Then** 그 글자 그대로 들어간 글만 나온다(`%`·`_`가 "아무 글자"로 해석되지 않음).
6. **Given** 결과가 없음, **When** "롬복"으로 검색한다, **Then** "'롬복'에 대한 글이 없어요"가 보인다.

---

### User Story 2 - 짧은 검색어 규칙 (Priority: P1)

1글자 단어는 무시하고, 2글자 단어는 제목·태그에서만 찾으며 그 사실을 안내한다. 3글자 이상만 본문까지 찾는다. 단어가 하나도 남지 않으면 두 글자 이상 입력하라고 안내한다.

**Why this priority**: 응답 속도를 지키기 위한 규칙이자 사용자가 결과를 이해하는 데 필요한 안내다(완료 기준 3).

**Independent Test**: 본문에만 "롬복"이 있는 글과 제목·태그에 "롬복"이 있는 글을 만들고 "롬복"으로 검색해 제목·태그 글만 나오고 안내가 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 제목에 "롬복"이 있는 글 3개, 태그가 `롬복`인 글 3개, 본문에만 있는 글 3개, **When** "롬복"으로 검색한다, **Then** 제목 글 3개 → 태그 글 3개 순으로 나오고 본문에만 있는 글은 나오지 않으며, 결과 위에 "두 글자 단어는 제목·태그에서만 찾았어요"가 보인다.
2. **Given** "  트랜잭션  정리 a  " 입력, **When** 검색한다, **Then** "a"는 무시되고 "트랜잭션"은 제목·태그·본문에서, "정리"는 제목·태그에서 찾는다.
3. **Given** "a" 또는 공백만 입력, **When** 검색한다, **Then** "두 글자 이상 입력해 주세요"가 보인다.
4. **Given** 6단어 이상 또는 50자 넘는 입력, **When** 검색한다, **Then** 50자로 자르고 최대 5단어만 쓴다.

### User Story 3 - 관련도순·최신순 정렬과 넘기기 (Priority: P2)

기본 정렬(관련도순)은 제목에 모두 있는 글 → 제목·태그에 모두 있는 글 → 본문까지 포함해 모두 있는 글 단계로 보여주고, 단계 안에서는 최신순이다. 최신순을 고르면 조건에 맞는 글을 최신순으로 보여준다. [더 보기]로 넘겨도 중복·누락이 없다.

**Why this priority**: 검색 결과의 쓸모를 높이지만, 결과가 나오는 것(US1·US2)이 먼저다.

**Independent Test**: "희귀어사전"이 제목에 1개, 본문에 20개 있는 상태에서 관련도순으로 3페이지를 넘겨 제목 글이 먼저, 이후 본문 글이 최신순으로 중복 없이 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 제목 1개·본문 20개에 단어가 있음, **When** 관련도순으로 [더 보기]를 끝까지 누른다, **Then** 제목 글이 먼저, 이어서 본문 글이 최신순으로 3페이지에 걸쳐 중복 0으로 나온다.
2. **Given** 한 단계가 9개를 채우지 못함, **When** 페이지를 만든다, **Then** 같은 페이지에서 다음 단계 글로 이어 9개를 채운다.
3. **Given** 최신순 선택, **When** 검색한다, **Then** 모든 단어가 어딘가에 있는 글이 최초 공개 시각 최신순(같으면 ID 큰 순)으로 나온다.

### User Story 4 - 검색어가 강조된 결과 카드 (Priority: P2)

결과 카드는 홈 카드와 같지만, 미리보기 자리에 검색어가 처음 나온 곳의 앞뒤 문장이 나오고 검색어가 강조된다. 본문에 들어 있는 HTML은 절대 실행되지 않는다.

**Why this priority**: 결과를 고르는 데 도움이 되고, 강조 처리에 XSS 위험이 있어 반드시 지켜야 한다.

**Independent Test**: 본문에 `<script>`와 `<img onerror>`가 글자로 들어 있는 글을 검색해 결과에 강조 외 태그가 없고 스크립트가 글자로 보이는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 본문에 검색어가 있는 글, **When** 결과를 본다, **Then** 미리보기 자리에 처음 나온 곳의 앞뒤 40자가 보이고, 앞뒤가 잘리면 `…`가 붙고, 검색어가 강조되어 있다.
2. **Given** 본문에 `<script>`, `<img onerror>` 글자가 있는 글, **When** 검색 결과를 본다, **Then** 그 글자는 글자로만 보이고 강조 외의 어떤 HTML도 실행·표시되지 않는다.
3. **Given** 본문에 검색어가 없고 제목에만 있는 글, **When** 결과를 본다, **Then** 제목에서 주변 문장을 만든다.

---

### User Story 5 - 사람 검색 (Priority: P2)

검색 화면의 [사람] 탭에서 닉네임이나 `@블로그주소`로 회원을 찾는다. 정확히 일치하는 사람이 먼저 나온다.

**Why this priority**: 회원 = 블로그라서 블로그 찾기를 대신하지만, 글 검색보다 덜 쓰인다.

**Independent Test**: "김민서"로 검색해 활동 중인 같은 닉네임 회원이 먼저 나오고 탈퇴 유예 회원은 빠지는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 닉네임 "김민서"인 회원과 "김민서2"인 회원, **When** 사람 탭에서 "김민서"를 검색한다, **Then** 정확히 일치하는 회원이 먼저, 부분 일치 회원이 뒤에 나온다.
2. **Given** "kim7550", **When** 검색한다, **Then** 블로그 주소에 그 글자가 있는 회원이 나온다.
3. **Given** 탈퇴 유예 회원, **When** 검색한다, **Then** 나오지 않는다.
4. **Given** 결과, **When** 본다, **Then** 프로필 이미지·닉네임·`@주소`·소개 첫 줄이 보이고 최대 20명이다.

---

### User Story 6 - 블로그 안 검색 (Priority: P3)

방문자는 특정 블로그 안에서만 그 작성자의 공개 글을 검색한다.

**Why this priority**: 전체 검색에 조건 하나를 더한 것으로 우선순위가 낮다.

**Independent Test**: 블로그 A에서 검색해 A의 공개 글만 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 같은 단어를 가진 A·B의 공개 글, **When** A의 블로그 안에서 검색한다, **Then** A의 공개 글만 나온다.

---

### Edge Cases

- 같은 방문자가 1분에 30번을 넘게 검색하면 "요청이 너무 많음"(429)으로 거절한다.
- 검색 결과 페이지는 검색 엔진에 색인되지 않는다.
- 코드 블록 안의 글자도 본문 검색 대상이다(개발 글).
- 보는 도중 이미 화면에 있는 카드의 글이 비공개·삭제되면 누르면 404다.
- 검색어 앞의 `#`(예: `#spring`)을 어떻게 다룰지는 태그 쪽 결정에 따른다(FR-020).
- 친구 공개 규격을 적용해도 친구 공개 글은 검색에 나오지 않는다.

## Requirements *(mandatory)*

### Functional Requirements

**대상과 공개 범위**

- **FR-001**: 검색 결과에는 공개 목록 공용 조건(공개·발행·휴지통 아님·작성자 탈퇴 유예 아님·관리자 숨김 아님)을 만족하는 글만 나와야 한다(MUST). 비공개·친구 공개·임시·휴지통 글은 나오지 않는다. (C-POST-4)
- **FR-002**: 검색은 비회원도 할 수 있어야 한다(MUST).

**검색어 처리**

- **FR-003**: 검색어는 유니코드 정규화(NFC), 앞뒤 공백 제거 후 50자로 자르고, 띄어쓰기로 나눠 최대 5단어를 써야 한다(MUST).
- **FR-004**: 1글자 단어는 무시하고, 2글자 단어는 제목·태그에서만, 3글자 이상 단어는 제목·태그·본문에서 찾아야 한다(MUST).
- **FR-005**: 남은 모든 단어가 들어 있는 글만 결과가 되어야 한다(MUST, AND).
- **FR-006**: 대소문자를 구분하지 않고 부분 일치로 찾아야 하며(MUST), 한글 일부(3글자 이상)로도 찾을 수 있어야 한다.
- **FR-007**: `%`, `_`, `\`는 글자 그대로 찾아야 한다(MUST).
- **FR-008**: 태그는 검색어를 태그 정규화 규칙과 같은 방식(소문자화 등)으로 정리해 태그 이름과 부분 일치로 비교해야 한다(MUST). (C-TAG-1)
- **FR-009**: 본문 검색은 사용자가 쓴 Markdown 원문을 대상으로 하며 코드 블록 안 글자도 포함해야 한다(MUST).
- **FR-010**: 단어가 하나도 남지 않으면 "두 글자 이상 입력해 주세요", 2글자 단어가 있으면 결과 위에 "두 글자 단어는 제목·태그에서만 찾았어요", 결과가 없으면 "'검색어'에 대한 글이 없어요"(2글자 안내 포함)를 보여줘야 한다(MUST).

**정렬과 넘기기**

- **FR-011**: 관련도순(기본)은 ① 모든 단어가 제목에 있음 → ② ①이 아니고 모든 단어가 제목 또는 태그에 있음 → ③ ①②가 아니고 모든 단어가 제목·태그·본문(3글자 이상만) 어딘가에 있음의 단계 순서여야 하며(MUST), 단계 안은 최초 공개 시각 최신 → ID 큰 순이다. 점수는 매기지 않는다.
- **FR-012**: 최신순을 고르면 모든 단어가 어딘가에 있는 글을 최초 공개 시각 최신순(같으면 ID 큰 순)으로 보여줘야 한다(MUST).
- **FR-013**: 결과는 9개씩 [더 보기]로 이어지고, 한 단계가 끝나면 같은 페이지에서 다음 단계로 이어 9개를 채우며, 넘겨도 중복·누락이 없어야 한다(MUST).

**결과 표시**

- **FR-014**: 글 결과 카드는 전체 글 목록 카드와 같고, 미리보기 3줄 자리에 본문(없으면 제목)에서 검색어가 처음 나온 곳의 앞뒤 40자를 보여줘야 하며(MUST), 잘리면 `…`를 붙인다.
- **FR-015**: 검색어 강조는 반드시 "문장 전체를 HTML 이스케이프 → 이스케이프된 검색어에 강조 표시" 순서로 해야 하며(MUST), 결과에는 강조 외 어떤 HTML 태그도 나오지 않는다. (C-POST-1 안전 원칙)
- **FR-016**: [사람] 탭은 닉네임·블로그 주소로 회원을 찾아 프로필 이미지·닉네임·`@주소`·소개 첫 줄을 최대 20명 보여주고, 닉네임·주소가 정확히 일치하는 회원을 먼저 보여주며, 탈퇴 유예 회원은 빼야 한다(MUST).
- **FR-017**: 블로그 안 검색은 그 블로그 주인의 공개 글로만 범위를 좁혀 같은 규칙으로 검색해야 한다(MUST).

**보호와 개인정보**

- **FR-018**: 같은 방문자(조회수와 같은 방문자 구분)는 1분에 30번까지 검색할 수 있고, 넘으면 429로 거절해야 한다(MUST). 검색 결과 페이지는 검색 엔진 색인 금지 표시를 달아야 한다.
- **FR-019**: 검색어를 회원 정보와 함께 저장하지 않아야 하며(MUST), 운영 기록에는 검색어 길이와 걸린 시간만 남긴다.
- **FR-020**: 검색창에 `#`으로 시작하는 입력(예: `#spring`)을 받으면 정해진 방식으로 처리해야 한다(MUST): [NEEDS CLARIFICATION: 33은 "`#spring` 입력 시 태그 페이지로 보낼지는 태그 담당이 결정"으로 남겨 둠 — 태그 페이지로 보낼 것인가, `#`을 지우고 일반 검색할 것인가?]

**성능**

- **FR-021**: 글 10만 개 기준 검색 응답의 95%가 500ms 이하여야 한다(MUST). 최신 글부터 찾아 9개를 채우면 멈추는 방식처럼, 흔한 단어 검색이 전체 결과를 모아 정렬하지 않아야 한다.

### Key Entities *(include if feature involves data)*

- **검색어**: 정규화·자르기·단어 나누기를 거친 최대 5단어. 단어마다 길이에 따라 찾는 곳(제목·태그 / 제목·태그·본문)이 정해진다. 저장하지 않는다.
- **검색 결과 항목(글)**: 전체 글 목록 카드 + 검색어 주변 문장(강조 포함).
- **검색 결과 항목(사람)**: 프로필 이미지, 닉네임, 블로그 주소, 소개 첫 줄.
- **넘기기 위치**: 관련도 단계(최신순은 0) + 최초 공개 시각 + 글 ID.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검색 결과에 비공개·친구 공개·휴지통·탈퇴 유예 작성자·관리자 숨김 글이 나오는 경우가 0건이다.
- **SC-002**: 3글자 이상 한글 일부로 그 단어를 포함한 공개 글을 100% 찾는다.
- **SC-003**: 2글자 검색에서 본문에만 단어가 있는 글이 나오는 경우가 0건이고, 그때마다 안내가 보인다.
- **SC-004**: [더 보기]를 끝까지 넘겼을 때 중복·누락이 0건이다.
- **SC-005**: `%`·`_`가 들어간 검색어가 정확히 그 글자를 포함한 글만 찾는다.
- **SC-006**: 본문에 HTML·스크립트가 있는 글을 검색해도 결과에서 실행되는 스크립트가 0건이다.
- **SC-007**: 글 10만 개 기준 검색 응답의 95%가 500ms 안에 끝난다.

## Assumptions

- Tier C(공통 2차 후보) "검색 (제목·본문, 공개 글만)"을 공통 범위로 정의한다. 블로그 안 검색도 공통에 포함한다.
- 회원 = 블로그라서 나민서의 "블로그 검색"은 [사람] 탭으로 대신한다.
- 개인 확장(공통에서 제외): 기간·주제 조건, 의미·하이브리드 검색, 자동 완성, 인기 검색어, 별도 검색 엔진 도입.
- 최근 글 우선 탐색 범위(기본 3,000개)는 설정값이며 실제 데이터가 쌓이면 다시 측정해 조정한다. 성능 수치는 반복 문장 테스트 데이터로 잰 것이라 구현 후 실제와 비슷한 데이터로 다시 잰다.
- 같은 방문자 구분은 016-view-count의 방문자 구분을 재사용한다. 태그 정규화는 태그 기능(22)의 규칙을 쓴다.
- 관리자 숨김 글 제외는 신고·숨김 기능(43)이 공개 목록 공용 조건에 숨김 조건을 추가하는 것에 의존한다.
- 배포 환경에서 검색에 필요한 데이터베이스 확장 기능을 설치할 권한이 있는지 팀이 확인해야 한다.
