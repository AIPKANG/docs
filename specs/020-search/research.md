# Research: 검색 (020-search)

**Phase 0** · 2026-10-08 · 입력: [spec.md](./spec.md), [source-notes.md](./source-notes.md), `docs/33-search.md`, 013 태그 정규화, 016 방문자 구분

사용자 지시: 질문 없이 기본값.

## R-1. 검색어 (FR-003~FR-010)
- `SearchTerms.parse`: NFC → strip → 50자(코드 포인트) → 공백 분리 → 2글자 미만 버림 → 중복 제거 → 5단어. `likePattern`이 `\ % _`를 이스케이프하고 SQL은 `ILIKE ? ESCAPE '\'`. 태그 비교는 소문자로 바꾼 단어(013 정규화의 소문자화)와 부분 일치.
- 안내: 단어 없음 "두 글자 이상 입력해 주세요", 2글자 단어 있으면 `notice: TWO_CHAR_TITLE_TAG_ONLY`와 문구, 결과 없음 "'검색어'에 대한 글이 없어요".

## R-2. 단계와 실행 (FR-011~FR-013, FR-021)
- 단계 조건: ① 모든 단어 제목 ② ①아님 + 모든 단어 제목∨태그 ③ ①②아님 + 모든 단어 제목∨태그∨본문(3글자 이상만). 최신순은 단계 0(어딘가에 모두). 커서 `{단계}:{ISO 공개 시각}:{id}`, 한 단계가 끝나면 같은 페이지에서 다음 단계 처음부터 10개(9 + 다음 확인)까지 채운다.
- 실행(33 §4): 최근창(`recent-window` 3,000, 커서 이후 최신 N개) 안에서 단계 조건 → 모자라고 창이 꽉 찼으면 가장 긴 단어로 `title`/태그/`content_md`(3글자 이상, 단계 0·3만) 후보 UNION을 만든 뒤 전체 조건 확인. 인덱스 단계 결과는 최근창 결과를 포함하므로 그대로 쓴다.
- 대상: 006 공용 조건 + `hidden_at IS NULL`(022가 공용 조건에 넣기 전까지 여기서 명시), 블로그 안 검색은 `author_id`만 더함.

## R-3. 미리보기·화면 (FR-014~FR-017)
- `SearchSnippet`: 본문(공백 정리)에서 단어가 처음 나온 곳(없으면 제목) 앞뒤 40자 + `…`, HTML은 전체 `htmlEscape` 뒤 이스케이프된 단어들(긴 것부터)을 대소문자 무시로 `<mark>`로 감싼다. 스크립트용 `snippetParts`(글자·강조 여부)도 함께 줘서 `list-more.js`는 `textContent`와 `<mark>` 요소로만 그린다.
- 사람: 닉네임 `ILIKE`·주소 `LIKE`(소문자), 정확히 일치 먼저, 탈퇴 유예 제외, 20명, 소개 첫 줄.
- `/search?q=&tab=posts|people&sort=relevance|latest`, `/@주소?q=`(블로그 안), 머리말 검색창. `#태그`: 정규화한 태그가 있으면 303 `/tags/{이름}`, 없으면 `#` 뺀 검색.

## R-4. 제한·기록 (FR-018, FR-019)
- 016 방문자 키를 `VisitorKeys`로 분리해 함께 쓴다. 1분 30번 → 429. 결과 화면 `pageNoindex`. 로그에는 검색어 길이와 걸린 시간만.

## 구현 메모 (2026-10-08)
- `SearchIT` 5개(단계·최신순·AND·한글 일부·2글자·`% _`, 공개 조건·블로그 범위·색인 금지, 단계 넘김 커서·인덱스 단계(최근창 3으로 시험), 이스케이프·강조·40자, 사람·`#태그`·빈 상태·429), `SearchTermsTest`. 처음에 `…`까지 HTML 이스케이프해 `&hellip;`가 되던 것을 그대로 두도록 고쳤다. MockMvc 주소 문자열의 `%23`이 다시 인코딩돼 `param()`으로 바꿨다(테스트만).
