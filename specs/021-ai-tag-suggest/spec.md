## User Scenarios & Testing *(mandatory)*

### User Story 1 - 버튼을 눌러 태그 추천을 받고 골라서 붙이기 (Priority: P1)

글을 쓰는 작성자가 [AI 태그 추천] 버튼을 누르면, 지금 에디터에 있는 제목과 본문 앞부분을 바탕으로 최대 5개의 태그 후보가 나온다. 작성자는 원하는 후보를 눌러야만 태그에 추가된다. AI는 제안만 하고 어떤 것도 자동으로 반영하지 않는다.

**Why this priority**: 이 기능의 핵심 가치(태그 고르는 수고 줄이기)이며, 다른 이야기(동의, 공급자 전환, 재사용)는 모두 이 흐름 위에 얹힌다.

**Independent Test**: 동의를 마친 작성자가 100자 이상인 글에서 버튼을 눌러 후보를 받고, 후보 하나를 눌러 태그에 추가되는지, 누르지 않은 후보는 추가되지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 동의를 마친 작성자가 정리 후 100자 이상인 글을 쓰는 중, **When** [AI 태그 추천]을 누르면, **Then** 최대 5개 후보와 "본문 앞부분을 보고 추천했어요 · AI 제안이에요" 안내, 오늘 남은 횟수가 보인다.
2. **Given** 후보가 보이는 상태, **When** 작성자가 후보 하나를 누르면, **Then** 그 태그만 태그 목록에 추가되고 나머지 후보는 추가되지 않는다.
3. **Given** 작성자가 버튼을 누르지 않은 상태, **When** 글을 쓰거나 자동 저장·발행하면, **Then** 추천은 한 번도 요청되지 않는다.
4. **Given** 글에 이미 `spring` 태그가 있고 글당 상한까지 2자리만 남은 상태, **When** 추천을 받으면, **Then** `spring`은 후보에 나오지 않고 후보는 최대 2개만 보인다.
5. **Given** 정리 후 본문이 100자 미만인 글, **When** 버튼을 누르면, **Then** AI를 부르지 않고 "글을 조금 더 쓴 뒤 추천받아 보세요"가 보이며 하루 횟수가 줄지 않는다.

### User Story 2 - 처음 사용할 때 외부 전송 동의 (Priority: P1)

작성자가 처음 [AI 태그 추천]을 누르면, 글 제목과 본문 앞부분이 외부 AI 서비스(무료 등급)로 전송되고 그 서비스가 내용을 서비스 개선에 쓰거나 사람이 검토할 수 있다는 안내를 보고 동의해야 한다. 동의하지 않으면 아무것도 전송되지 않는다. 동의는 설정에서 철회할 수 있다.

**Why this priority**: 동의 없이 글 내용이 외부로 나가면 안 되므로, 추천 기능을 열기 전에 반드시 있어야 한다.

**Independent Test**: 동의하지 않은 작성자가 버튼을 누르면 동의 창이 뜨고, [취소]를 누르면 어떤 외부 전송도 일어나지 않는지 확인한다. 동의 후에는 추천이 진행되고, 설정에서 철회하면 다시 동의 창이 뜨는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 아직 동의하지 않은 작성자, **When** 버튼을 누르면, **Then** 외부 AI 전송·무료 등급의 데이터 사용 방식·자체 AI 대체 처리·민감 정보 주의 문구가 담긴 동의 창이 뜨고, 이 시점까지 아무 내용도 전송되지 않는다.
2. **Given** 동의 창, **When** [취소]를 누르면, **Then** 아무것도 전송되지 않고 동의 기록도 남지 않는다.
3. **Given** 동의 창, **When** [동의하고 추천받기]를 누르면, **Then** 동의 시각이 기록되고 추천이 이어서 진행된다.
4. **Given** 동의한 작성자, **When** 설정에서 동의를 취소한 뒤 버튼을 누르면, **Then** 다시 동의 창이 뜬다.

### User Story 3 - 외부 AI 한도가 다 되거나 실패해도 계속 쓸 수 있음 (Priority: P2)

외부 AI(무료 등급)의 하루·분당 한도가 다 되거나 일시 장애가 나면, 같은 요청을 우리 서버의 자체 AI로 처리한다. 두 공급자가 모두 실패해도 "지금은 추천할 수 없어요"만 보이고 글쓰기·자동 저장·발행은 그대로 된다.

**Why this priority**: 무료 등급 한도는 자주 바뀌고 작아서, 전환이 없으면 기능이 쉽게 멈춘다. 다만 기본 추천 흐름(P1) 없이는 의미가 없다.

**Independent Test**: 외부 AI의 하루 한도를 소진시킨(또는 한도 초과 응답을 흉내 낸) 상태에서 추천을 요청해 자체 AI로 처리되는지, 두 공급자를 모두 끈 상태에서 추천은 실패 안내만 보이고 발행은 성공하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 오늘 외부 AI 호출 수가 설정된 하루 한도에 도달, **When** 추천을 요청하면, **Then** 외부 AI를 부르지 않고 자체 AI로 처리하며, 한도가 초기화될 때까지 자체 AI를 쓴다.
2. **Given** 외부 AI가 하루 한도 초과로 거절, **When** 같은 요청이 처리되면, **Then** 그 요청은 바로 자체 AI로 처리되고 이후 한도 초기화 시각까지 자체 AI가 쓰인다.
3. **Given** 외부 AI가 분당 한도 초과로 거절, **When** 같은 요청이 처리되면, **Then** 그 요청은 자체 AI로 처리되고 60초 동안 외부 AI를 부르지 않는다.
4. **Given** 외부 AI가 10초 안에 응답하지 않거나 서버 오류, **When** 요청이 끝나면, **Then** 그 요청은 "지금은 추천할 수 없어요"로 끝나고(자체 AI까지 기다리게 하지 않음) 60초 동안 외부 AI를 쉬게 한다.
5. **Given** 자체 AI로 처리 중, **When** 결과를 기다리는 동안, **Then** "자체 AI로 추천 중이라 조금 걸려요"가 보인다.
6. **Given** 두 공급자가 모두 실패, **When** 작성자가 이어서 자동 저장·발행하면, **Then** 저장·발행은 정상적으로 성공한다.

### User Story 4 - 같은 내용으로 다시 누르면 저장된 결과를 재사용 (Priority: P2)

같은 글에서 버튼을 여러 번 누르거나, 태그를 하나 붙인 뒤 다시 누르거나, 오타 몇 개만 고친 뒤 다시 누르면 AI를 다시 부르지 않고 저장해 둔 추천을 보여준다. 이때는 하루 사용 횟수가 줄지 않는다. [다시 추천]을 누르면 비슷한 내용 재사용을 건너뛰고 새로 묻는다.

**Why this priority**: 무료 한도와 하루 20회 한도를 아끼는 핵심 수단이지만, 기본 흐름이 먼저 있어야 한다.

**Independent Test**: 같은 내용으로 두 번 요청해 두 번째 응답이 "재사용됨"으로 표시되고 남은 횟수가 그대로인지, 오타 2개만 고친 뒤에도 재사용되는지, [다시 추천]을 누르면 새로 요청되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 한 번 추천을 받은 글, **When** 내용을 바꾸지 않고 다시 누르면, **Then** AI를 부르지 않고 같은 추천이 나오며 하루 남은 횟수가 줄지 않는다.
2. **Given** 추천 후 태그 하나를 붙인 상태, **When** 다시 누르면, **Then** AI를 부르지 않고 붙인 태그만 뺀 추천이 나온다.
3. **Given** 공백·줄바꿈만 다르거나 이미지 주소만 바뀐 내용, **When** 다시 누르면, **Then** 같은 내용으로 보고 저장된 추천을 재사용한다.
4. **Given** 같은 글에서 오타 몇 개를 고쳐 지난번 정리된 입력과의 유사도가 0.9 이상, **When** 다시 누르면, **Then** 저장된 추천을 재사용한다.
5. **Given** 같은 글의 비슷한 내용이 저장된 상태, **When** [다시 추천]을 누르면, **Then** 비슷한 내용 재사용을 건너뛰고 새로 추천받는다. 완전히 같은 내용의 저장 결과가 자체 AI가 만든 것이고 지금 외부 AI를 쓸 수 있으면 외부 AI로 다시 만든다.

---

### User Story 5 - 사용 한도와 잘못된 추천 거르기 (Priority: P3)

사용자 한 명은 하루 20번까지 AI를 부를 수 있다(재사용 응답은 세지 않음). 추천 결과는 서버가 태그 규칙과 금칙어로 다시 걸러서, 규칙에 맞지 않거나 금칙어인 태그는 보이지 않는다.

**Why this priority**: 남용과 품질 문제를 막는 보호 장치로, 기본 흐름이 동작한 뒤 더해도 된다.

**Independent Test**: 하루 20번 AI 호출 후 21번째 요청이 한도 초과 안내로 끝나는지, 모델이 금칙어·규칙 위반 태그를 돌려줘도 화면에 나오지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 오늘 AI를 20번 부른 사용자, **When** 새 내용으로 추천을 요청하면, **Then** 하루 한도 초과 안내가 보이고 AI는 불리지 않는다.
2. **Given** 오늘 20번을 다 쓴 사용자, **When** 이미 저장된 같은 내용으로 요청하면, **Then** 재사용 응답은 한도와 무관하게 보인다.
3. **Given** AI가 `JPA`, `batch size`, 금칙어, 허용되지 않는 문자가 든 태그를 돌려줌, **When** 결과를 보여줄 때, **Then** 태그 규칙에 따라 정규화된 것(`jpa`, `batch-size`)만 남고 금칙어·규칙 위반 태그는 빠진다.
4. **Given** 거른 뒤 남은 후보가 0개, **When** 결과를 보여줄 때, **Then** "추천할 태그를 찾지 못했어요"가 보인다.

### Edge Cases

- 남의 글에 대해 추천을 요청하면 그 글이 있는지조차 알 수 없게 "없음"과 같은 응답을 준다 (42 §4 원칙).
- 이메일 인증 전 회원이 요청하면 계정 상태 이유와 함께 거부된다.
- 기능 스위치가 꺼져 있으면 버튼이 보이지 않고, 직접 요청해도 "지금은 추천할 수 없어요"로 끝난다.
- 자체 AI가 동시에 처리할 수 있는 수(기본 1)를 넘으면 "잠시 후 다시 시도해 주세요"로 끝난다.
- 외부 AI가 종류를 알 수 없는 한도 초과로 같은 날 3번 연속 거절하면 그날 하루 한도 소진으로 본다.
- AI 응답이 정해진 형식(태그 목록)이 아니면 실패로 처리하고 저장하지 않는다.
- 실패·빈 결과·검증에서 모두 걸러진 결과는 재사용 대상으로 저장하지 않는다.
- 다른 사용자가 완전히 같은 내용을 올리면(복사한 글) 그 사람의 저장된 추천을 재사용할 수 있지만, 저장 키에는 내용 자체가 남지 않는다.
- 이미 붙인 태그만으로 글당 상한이 찬 경우 보여줄 후보 자리가 없다.
- 회원이 탈퇴 후 익명 처리되면 AI 전송 동의 기록도 지워진다 (023 회원 탈퇴와 연동).
- 비공개·친구 공개 글은 외부 AI로 보내지 않고 태그 추천을 제공하지 않는다 (FR-021, 2026-10-07 확정).

## Requirements *(mandatory)*

### Functional Requirements

**호출과 반영**

- **FR-001**: 시스템은 작성자가 [AI 태그 추천] 또는 [다시 추천] 버튼을 누를 때만 추천을 요청해야 한다(MUST). 글쓰기·자동 저장·발행 중에 자동으로 요청하면 안 된다(MUST NOT).
- **FR-002**: 시스템은 추천 후보를 최대 5개까지, 글당 태그 상한(C-TAG-1, 기본 10개 설정값)에서 이미 붙인 태그 수를 뺀 남은 자리만큼만 보여줘야 한다(MUST).
- **FR-003**: 추천 후보는 작성자가 눌러야만 태그에 추가되어야 한다(MUST). 시스템은 추천을 자동으로 태그에 반영하면 안 된다(MUST NOT).
- **FR-004**: 추천 범위는 태그 추천뿐이어야 한다(MUST). 주제·제목·요약 추천, 관련 글, 티저 등은 이 기능에 포함하지 않는다.
- **FR-005**: 화면은 추천 결과와 함께 "본문 앞부분을 보고 추천했어요 · AI 제안이에요" 안내, 입력이 잘렸는지 여부, 오늘 남은 사용 횟수를 보여줘야 한다(MUST).

**권한·동의**

- **FR-006**: 시스템은 자기 글에 대해서만 추천을 허용해야 한다(MUST). 남의 글에 대한 요청은 없는 글과 구별되지 않는 "찾을 수 없음"으로 거부해야 한다(MUST) (C-OWN-1, 42 P-4).
- **FR-007**: 시스템은 이메일 인증 전 회원의 요청을 계정 상태 이유와 함께 거부해야 한다(MUST) (42 §3 ②).
- **FR-008**: 시스템은 AI 전송 동의를 하지 않은 사용자의 요청에 대해 어떤 내용도 외부로 보내지 않고 동의가 필요하다는 응답을 줘야 한다(MUST).
- **FR-009**: 동의 창은 다음을 모두 알려야 한다(MUST): 글 제목과 본문 앞부분이 외부 AI 서비스(무료 등급)로 전송됨, 그 서비스가 내용을 서비스 개선에 사용하고 사람이 검토할 수 있음, 외부 AI를 쓸 수 없을 때는 우리 서버의 자체 AI로 처리하며 이때는 외부로 전송되지 않음, 개인정보·비밀번호·회사 기밀이 든 글에는 쓰지 말 것.
- **FR-010**: 시스템은 동의 시각을 회원 정보에 기록해야 하고(MUST), 사용자가 설정 화면에서 동의를 철회하면 기록을 지워 다음 사용 때 다시 물어야 한다(MUST).
- **FR-011**: 시스템은 다른 사람의 글이나 이메일·닉네임 등 회원 정보를 AI에 보내면 안 된다(MUST NOT).

**입력 정리**

- **FR-012**: 시스템은 AI에 보내기 전 입력을 정리해야 한다(MUST): Markdown 기호(제목·강조·목록·인용) 제거, 이미지 문법 전체 제거, 링크는 글자만 남기고 주소 제거, 코드 블록은 언어 이름과 앞 5줄만 유지, 연속 공백·줄바꿈을 하나로, 유니코드 정규화(NFC). 대소문자는 바꾸지 않는다.
- **FR-013**: 시스템은 정리된 입력을 공급자별 최대 글자 수로 잘라야 한다(MUST): 외부 AI 8,000자, 자체 AI 2,000자 (모두 설정값). 잘렸으면 화면에 알린다.
- **FR-014**: 정리 후 100자 미만이면 시스템은 AI를 부르지 않고 "글을 조금 더 쓴 뒤 추천받아 보세요"로 응답해야 하며(MUST), 이 요청은 하루 사용 횟수에서 빼지 않는다.
- **FR-015**: 시스템은 AI에 제목, 정리된 본문, 이미 붙인 태그(제외 대상), 기존 인기 태그(외부 AI는 공개 글 기준 상위 50개, 자체 AI는 그중 글에 실제로 나오는 것만)를 보내야 하고(MUST), 지시문에 "글에 나오지 않는 기술은 넣지 말 것"을 포함해야 한다(MUST). 인기 태그 목록은 하루 1번 갱신한다.

**공급자 선택과 전환**

- **FR-016**: 시스템은 기본으로 외부 AI(무료 등급)를 쓰고, 다음 경우에는 자체 AI로 처리해야 한다(MUST): (a) 하루 한도 소진 표시가 있음, (b) 일시 중단(60초) 표시가 있음, (c) 우리가 센 오늘 외부 AI 호출 수가 설정된 하루 한도(기본 450) 이상 — 이때는 소진 표시를 남기고 한도 초과 응답을 받기 전에 미리 전환.
- **FR-017**: 외부 AI 응답에 따라 시스템은 다음과 같이 처리해야 한다(MUST): 하루 한도 초과 → 다음 한도 초기화 시각까지 소진 표시 후 같은 요청을 자체 AI로 / 분당 한도 초과 → 60초 일시 중단 후 같은 요청을 자체 AI로 / 종류를 모르는 한도 초과 → 60초 일시 중단, 같은 날 3번 연속이면 소진 표시 / 시간 초과·서버 오류 → 60초 일시 중단, 그 요청은 실패로 응답 / 성공 → 오늘 호출 수 1 증가.
- **FR-018**: 시간 제한은 외부 AI 10초, 자체 AI 30초여야 한다(MUST) (설정값). 자체 AI로 처리 중에는 "자체 AI로 추천 중이라 조금 걸려요"를 보여준다.
- **FR-019**: 시스템은 자체 AI의 동시 처리 수를 설정값(기본 1)으로 제한하고, 넘으면 "잠시 후 다시 시도해 주세요"로 응답해야 한다(MUST).
- **FR-020**: 두 공급자가 모두 실패하거나 기능이 꺼져 있으면 시스템은 "지금은 추천할 수 없어요"만 보여줘야 하며(MUST), 글쓰기·자동 저장·발행은 영향 없이 성공해야 한다(MUST) (01 §3-5).
- **FR-021**: 외부 AI로 본문을 보내는 태그 추천은 공개(`PUBLIC`) 글에만 제공해야 한다(MUST). 비공개·친구 공개 글에서는 태그 추천을 제공하지 않고, 버튼 대신 "공개 글에서만 태그 추천을 받을 수 있어요" 안내를 보여야 한다(MUST). (clarify 2026-10-07, 사용자 확정)

**재사용(결과 저장)**

- **FR-022**: 시스템은 AI 결과를 반드시 저장해 재사용해야 한다(MUST). 두 단계로 확인한다: ① 정리된 입력이 완전히 같으면 저장된 추천을 그대로 사용(30일 보관, 사용자와 무관하게 공유), ② 같은 글의 지난번 정리된 입력과 지금 입력의 3글자 단위 유사도가 0.9 이상이면 저장된 추천을 재사용(글당 1개, 7일 보관).
- **FR-023**: 재사용 판정 기준에 이미 붙인 태그와 인기 태그 목록을 넣으면 안 된다(MUST NOT). 이미 붙인 태그는 응답할 때 뺀다. 저장은 태그를 빼기 전 결과로 한다. 프롬프트 형식이 바뀌면 프롬프트 버전을 올려 이전 저장 결과를 쓰지 않는다.
- **FR-024**: 재사용으로 응답한 요청은 하루 사용 횟수를 줄이지 않아야 하고(MUST), 응답에 재사용 여부를 표시해야 한다(MUST).
- **FR-025**: [다시 추천]은 ②(비슷한 내용) 재사용을 건너뛰어야 한다(MUST). ①(완전히 같은 내용)은 그대로 쓰되, 저장된 결과가 자체 AI가 만든 것이고 지금 외부 AI를 쓸 수 있으면 외부 AI로 다시 만들어야 한다(MUST).
- **FR-026**: 실패·빈 결과·검증에서 모두 걸러진 결과는 저장하면 안 된다(MUST NOT).
- **FR-027**: 저장 키에 글 내용 자체가 드러나면 안 된다(MUST NOT) (내용의 해시만 사용).

**사용 한도**

- **FR-028**: 시스템은 사용자당 하루 20회(설정값)까지 AI 호출을 허용하고, 넘으면 하루 한도 초과로 거부해야 한다(MUST). 재사용 응답과 100자 미만 거절은 세지 않는다.

**응답 검증**

- **FR-029**: 시스템은 두 공급자 모두에 "태그 문자열 목록, 최대 5개" 형식을 강제해야 하고(MUST), 형식에 맞지 않는 응답은 실패로 처리해야 한다(MUST).
- **FR-030**: 시스템은 추천 결과에 태그 정규화 규칙(C-TAG-1, 22 §2: 정규화·허용 문자·1~30자·중복 제거)을 적용하고, 이미 붙인 태그·금칙어(09 필터)·규칙에 맞지 않는 태그를 제거해야 한다(MUST).
- **FR-031**: 거른 뒤 0개면 "추천할 태그를 찾지 못했어요"를 보여줘야 한다(MUST).

**보안·운영**

- **FR-032**: 외부 AI 접근 키는 환경 변수로만 주입되어야 하고(MUST) 로그에 남으면 안 된다(MUST NOT). 글 내용도 로그에 남으면 안 된다(MUST NOT).
- **FR-033**: 기능 전체를 설정으로 끌 수 있어야 하며(MUST), 꺼져 있으면 버튼을 숨긴다.
- **FR-034**: 외부 AI 하루 한도·모델·시간 제한·최대 글자 수·동시 처리 수는 코드가 아닌 설정값이어야 한다(MUST) (01 §3-7).
- **FR-035**: 개인정보 처리방침에 외부 AI 서비스로의 전송과 무료 등급의 데이터 사용 방식을 추가해야 한다(MUST).

### Key Entities *(include if feature involves data)*

- **AI 전송 동의**: 회원이 AI 태그 추천을 위해 글 내용 외부 전송에 동의한 시각. 없으면 동의하지 않은 상태. 철회하면 지워지고, 회원 탈퇴 익명 처리 때도 지워진다.
- **추천 요청**: 대상 글, 지금 제목·본문, 이미 붙인 태그, [다시 추천] 여부. 저장되지 않는다.
- **추천 결과**: 태그 후보 목록(최대 5개), 만든 공급자(외부/자체), 재사용 여부, 입력 잘림 여부, 오늘 남은 횟수.
- **저장된 추천(같은 내용)**: 정리된 입력의 해시 → 추천 목록. 30일 보관, 프롬프트 버전별.
- **저장된 추천(같은 글의 비슷한 내용)**: 글 하나당 지난번 정리된 입력·추천·공급자·시각. 7일 보관.
- **공급자 상태**: 오늘 외부 AI 호출 수, 하루 한도 소진 표시(다음 초기화 시각까지), 일시 중단 표시(60초), 자체 AI 동시 처리 수.
- **사용자별 하루 사용 횟수**: 사용자당 오늘 AI를 부른 횟수(최대 20).
- **인기 태그 목록**: 공개 글 기준 상위 50개, 하루 1번 갱신.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 버튼을 누르지 않은 글쓰기·자동 저장·발행 흐름에서 추천 요청이 0건 발생한다.
- **SC-002**: 동의하지 않은 사용자에 대해 외부로 전송된 글 내용이 0건이다.
- **SC-003**: 외부 AI 한도 소진·한도 초과 상황에서 들어온 추천 요청의 100%가 자체 AI로 처리되거나 명확한 실패 안내로 끝나며, 실패 안내까지 걸리는 시간은 외부 AI 10초, 자체 AI 30초를 넘지 않는다.
- **SC-004**: 두 공급자가 모두 실패하는 동안에도 자동 저장·발행 성공률이 평소와 같다(100%).
- **SC-005**: 같은 내용으로 다시 요청하거나 태그 하나를 붙인 뒤 다시 요청하면 AI 호출이 0번 일어나고 하루 남은 횟수가 줄지 않는다.
- **SC-006**: 화면에 보이는 추천 태그 중 이미 붙인 태그·금칙어·태그 규칙 위반 태그가 0건이다.
- **SC-007**: 자체 AI 처리 시 2,000자 입력 기준 사용자가 10초 이내에 추천을 받는다 (배포 서버에서 재측정).
- **SC-008**: 서비스 로그에서 외부 AI 접근 키와 글 내용이 0건 검출된다.

## Assumptions

- Tier C 기능이다 (01 §2-3 "AI 태그 추천": 강 P2, 나 MUST, 김 3차). 세 문서 공통 원칙 "제안만, 실패해도 발행 성공"을 따른다.
- 범위는 태그 추천만이다(A-1). 주제 추천(나민서 AI-06)·제목·요약·임베딩·관련 글·티저는 개인 확장이며, 주제 추천은 같은 공급자 전환·재사용 구조를 쓰는 개인 확장으로 둔다.
- 동의 문구 버전 관리(문구가 바뀌면 다시 묻기)는 개인 확장으로 둔다.
- 외부 AI 서비스는 무료 등급이며 한도 수치가 자주 바뀌므로 하루 한도(기본 450), 모델, 시간 제한, 최대 글자 수, 자체 AI 동시 처리 수, 사용자 하루 횟수(20) 모두 설정값이다 (01 §3-7). 외부 AI 한도 초기화 시각은 구현 시 확인한다.
- 태그 정규화·허용 문자·길이·글당 상한은 C-TAG-1(22 문서) 규칙을 그대로 따른다. 34 문서의 지시문은 "영어 소문자와 하이픈만"이라고 쓰지만, 최종 거르기는 22 규칙(한글·기호 일부 허용)이 기준이다.
- 34 §9는 남의 글 요청을 403으로 적었지만, 42 권한 매트릭스 P-4·§4(403은 계정 상태만, 남의 것은 404)와 헌법 III에 따라 "찾을 수 없음"으로 통일했다.
- 이메일 인증 전 회원 거부는 42 §3 판정 순서(계정 상태 확인이 대상 확인보다 먼저)를 따른다.
- 자체 AI 성능 수치(2,000자 약 6초)는 개발 노트북 측정값이며 배포 서버에서 다시 재야 한다. 자체 AI 서버 자원(메모리 약 2~4GB), 외부 AI 키 관리 주체, 개인정보 처리방침 문구는 팀 배포 단계에서 정한다.
- 회원 탈퇴 30일 뒤 익명 처리 시 AI 전송 동의 기록을 지우는 것은 023-account-withdraw에서 다룬다.
