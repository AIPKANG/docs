## User Scenarios & Testing *(mandatory)*

### User Story 1 - 회원 팔로우·언팔로우 (Priority: P1)

로그인한 회원은 블로그 상단이나 글 상세의 작성자 영역에서 [팔로우]를 눌러 그 사람을 바로 팔로우하고(상대의 승인 없음), [팔로잉 ✓]를 다시 눌러 언팔로우한다. 버튼은 누르는 즉시 바뀐다.

**Why this priority**: 피드·새 팔로워 알림·새 글 알림이 모두 팔로우 관계에 의존한다.

**Independent Test**: 회원 A가 B의 블로그에서 [팔로우]를 누르면 B의 팔로워 수가 1 늘고 버튼이 [팔로잉 ✓]로 바뀌는지, 다시 누르면 원래대로 돌아오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원 A, B를 팔로우하지 않음, **When** B의 블로그에서 [팔로우]를 누른다, **Then** 즉시 [팔로잉 ✓]로 바뀌고 B의 팔로워 수가 1 늘어난다.
2. **Given** A가 B를 팔로우 중, **When** [팔로잉 ✓]를 누른다(마우스를 올리거나 초점을 받으면 [언팔로우]로 보임), **Then** 확인 창 없이 언팔로우되고 [팔로우]로 돌아온다.
3. **Given** A가 같은 사람에 대한 팔로우 요청을 동시에 20번 보냄, **When** 처리된다, **Then** 팔로우 관계는 하나이고 새 팔로워 사건도 한 번만 발생한다.
4. **Given** 이미 팔로우 중, **When** 다시 팔로우를 요청한다, **Then** 아무것도 바뀌지 않고 성공 응답과 현재 상태(팔로우 중, 팔로워 수)를 받는다. 팔로우하지 않은 사람을 언팔로우해도 같다.
5. **Given** 비회원, **When** [팔로우]를 누른다, **Then** 로그인 화면으로 가고 로그인 후 원래 페이지로 돌아온다.
6. **Given** 내 블로그·내 글, **When** 작성자 영역을 본다, **Then** 팔로우 버튼이 없다. 자기 자신을 팔로우하도록 요청하면 거절된다.
7. **Given** 이메일 인증 전 회원, **When** 팔로우한다, **Then** 팔로우된다(인증 불필요).
8. **Given** 요청이 실패함, **When** 버튼을 누른다, **Then** 버튼이 원래 상태로 돌아오고 "잠시 후 다시 시도해 주세요"가 보인다.

### User Story 2 - 팔로잉 피드 (Priority: P1)

로그인한 회원은 상단 메뉴의 [피드]에서 내가 팔로우한 사람들의 공개 글만 홈과 같은 카드로 최신순으로 본다. 홈 화면은 바뀌지 않는다.

**Why this priority**: 팔로우의 주된 가치는 관심 있는 사람의 새 글을 모아 보는 것이다.

**Independent Test**: A가 B·C를 팔로우하고, B의 공개 글·비공개 글·임시글·휴지통 글, C의 공개 글, 팔로우하지 않은 D의 공개 글을 만든 뒤 피드에 B·C의 공개 글만 최신순으로 나오는지 확인한다.

**Acceptance Scenarios**:

1. **Given** A가 B·C를 팔로우, **When** 피드를 연다, **Then** B·C의 공개·발행 글만 최초 공개 시각 최신순(같으면 ID 큰 순)으로 한 번에 9개 카드가 보인다.
2. **Given** 팔로우한 사람의 비공개·친구 공개·임시·휴지통 글, 또는 탈퇴 유예 중인 사람의 글, **When** 피드를 연다, **Then** 나오지 않는다.
3. **Given** 피드 글이 9개 넘게 있음, **When** [더 보기]를 반복해 누른다, **Then** 중복·누락 없이 이어 붙는다.
4. **Given** A가 B를 언팔로우, **When** 다음 피드 요청을 한다, **Then** B의 글이 빠진다. 이미 화면에 있던 카드는 그대로 남는다.
5. **Given** 팔로우한 사람이 없음, **When** 피드를 연다, **Then** "팔로우한 사람이 없어요. 홈에서 읽고 싶은 블로그를 찾아보세요 [홈]"이 보인다. 팔로우한 사람은 있지만 공개 글이 없으면 "팔로우한 사람의 공개 글이 아직 없어요".
6. **Given** 비회원, **When** 피드 주소로 들어온다, **Then** 로그인 화면으로 간다. 상단 메뉴에는 [피드]가 보이지 않는다.
7. **Given** 피드에서 카드를 눌러 글을 본 뒤, **When** 뒤로 간다, **Then** 불러온 카드와 스크롤 위치가 복원된다.
8. **Given** JS를 쓰지 않는 화면, **When** [더 보기]를 누른다, **Then** 다음 페이지 링크로 동작한다.

### User Story 3 - 팔로워·팔로잉 수와 목록 보기 (Priority: P2)

누구나(비회원 포함) 블로그 상단에서 "공개 글 24 · 팔로워 12 · 팔로잉 30"을 보고, 숫자를 눌러 팔로워·팔로잉 목록을 본다. 목록에서 다른 블로그를 발견하고 바로 팔로우할 수 있다.

**Why this priority**: 새 블로그 발견을 돕지만, 팔로우·피드 없이도 의미가 약하다.

**Independent Test**: 비회원이 팔로워 12명인 블로그의 팔로워 목록을 열어 20개씩 최근 팔로우 순으로 보이고, 탈퇴 유예 회원이 빠져 있는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** 블로그의 팔로워 수를 누른다, **Then** 팔로워 목록이 보인다(공개).
2. **Given** 팔로워 목록, **When** 본다, **Then** 각 항목에 프로필 이미지, `닉네임 @블로그주소`, 소개 첫 줄, 보는 사람 기준 팔로우 버튼이 있고, 최근에 팔로우한 순(같으면 회원 ID 큰 순)으로 20개씩 [더 보기]로 이어진다.
3. **Given** 팔로워 중 한 명이 탈퇴 신청, **When** 목록과 수를 본다, **Then** 그 회원은 빠져 있다. 복구하면 다시 나타난다.
4. **Given** 없는 블로그 또는 탈퇴 유예 중인 블로그, **When** 팔로워·팔로잉 목록이나 팔로우를 요청한다, **Then** "찾을 수 없음"(404)이다.
5. **Given** 팔로워가 없음, **When** 목록을 연다, **Then** "아직 팔로워가 없어요"(팔로잉은 "아직 팔로우한 사람이 없어요").

### User Story 4 - 탈퇴와 팔로우 관계 (Priority: P3)

회원이 탈퇴를 신청하면 유예 기간 동안 그 사람은 남의 팔로워·팔로잉 목록과 수, 피드에서 빠지고, 복구하면 그대로 돌아온다. 30일 뒤 익명 처리되면 그 회원의 팔로우 관계가 양방향 모두 지워진다.

**Why this priority**: 탈퇴(Tier C) 정책과의 연결로 핵심 흐름 뒤에 온다.

**Independent Test**: 팔로워·팔로잉이 있는 회원을 탈퇴 신청시켜 목록·수·피드에서 빠지는지, 복구 시 돌아오는지, 30일 정리 후 관계가 0건인지 확인한다.

**Acceptance Scenarios**:

1. **Given** B가 탈퇴 신청, **When** A가 자기 팔로잉 목록·피드를 본다, **Then** B와 B의 글이 보이지 않는다.
2. **Given** B가 유예 중 복구, **When** 목록을 본다, **Then** 팔로우 관계가 그대로 돌아와 있다.
3. **Given** B의 탈퇴 30일 경과, **When** 익명 처리 정리가 실행된다, **Then** B가 팔로우한 관계와 B를 팔로우한 관계가 모두 지워진다.

---

### Edge Cases

- 팔로우와 친구는 별개다: 친구는 친구 공개 글을 볼 수 있고, 팔로우는 공개 글만 피드로 받는다. 친구 공개 규격을 적용해도 친구 공개 글은 피드에 넣지 않는다.
- 팔로우 → 언팔로우 → 팔로우를 반복해도 팔로우 자체에는 제한이 없고, 알림 도배는 알림 쪽(같은 사람 7일 1번)에서 막는다.
- 언팔로우는 상대에게 알리지 않는다.
- 팔로우 버튼 상태는 색만으로 구분하지 않는다(글자와 ✓).
- 관리자가 숨긴 글은 공개 목록 공용 조건에서 빠지므로 피드에도 나오지 않는다.
- 피드를 보는 도중 이미 화면에 있는 카드의 글이 비공개·삭제되면 카드는 남고, 누르면 404다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 팔로우 대상은 회원이어야 한다(MUST, 회원 = 블로그). 블로그를 별도로 두는 개인 확장은 블로그 주인 회원으로 바꿔 같은 팔로우를 쓴다.
- **FR-002**: 팔로우는 한쪽 방향이고 상대의 승인 없이 바로 이루어져야 한다(MUST).
- **FR-003**: 로그인한 회원은 이메일 인증 여부와 관계없이 팔로우·언팔로우할 수 있어야 하며(MUST), 인원·횟수 제한을 두지 않는다. 비회원은 로그인 필요(401, 화면은 로그인 후 원래 페이지로). (42 §10-1)
- **FR-004**: 자기 자신은 팔로우할 수 없어야 한다(MUST, 400 `CANNOT_FOLLOW_SELF`). 데이터 수준에서도 막는다.
- **FR-005**: 팔로우·언팔로우는 같은 요청을 여러 번(동시 포함) 보내도 결과가 같아야 하며(MUST), 관계는 하나만 생기고 상태가 실제로 바뀐 경우에만 새 팔로워·언팔로우 사건이 한 번 발생한다. 응답에는 현재 팔로우 여부와 대상의 팔로워 수를 담는다.
- **FR-006**: 없는 블로그와 탈퇴 유예 중인 블로그에 대한 팔로우·목록 요청은 404여야 한다(MUST).
- **FR-007**: 팔로우 버튼은 비회원에게 [팔로우](누르면 로그인), 팔로우 안 함은 [팔로우], 팔로우 중은 [팔로잉 ✓](마우스를 올리거나 초점 시 [언팔로우])로 보이고, 내 블로그·내 글에서는 보이지 않아야 한다(MUST). 누르면 즉시 바뀌고 실패하면 원래대로 돌리고 "잠시 후 다시 시도해 주세요"를 보여준다.
- **FR-008**: 팔로워·팔로잉 수와 목록은 비회원을 포함해 누구나 볼 수 있어야 한다(MUST).
- **FR-009**: 팔로워·팔로잉 수는 탈퇴 유예 중인 회원을 빼고 세어야 하며(MUST), 복구하면 다시 포함된다.
- **FR-010**: 팔로워·팔로잉 목록은 프로필 이미지·`닉네임 @블로그주소`·소개 첫 줄·보는 사람 기준 팔로우 버튼을 보여주고, 최근 팔로우 순(같으면 회원 ID 큰 순)으로 20개씩 [더 보기](커서 방식)로 이어져야 하며(MUST), 탈퇴 유예 회원은 빠진다. 빈 상태 문구는 "아직 팔로워가 없어요" / "아직 팔로우한 사람이 없어요".
- **FR-011**: 팔로잉 피드는 별도 페이지로 로그인한 회원만 볼 수 있어야 하며(MUST), 상단 메뉴에 [피드]를 로그인한 경우만 보여준다. 홈 화면 구성은 바꾸지 않는다.
- **FR-012**: 피드에는 내가 팔로우한 사람의 글 중 공개·발행·휴지통 아님·작성자 탈퇴 유예 아님(공개 목록 공용 조건)인 글만 나와야 한다(MUST). 친구 공개 글은 넣지 않는다. (C-POST-4)
- **FR-013**: 피드는 홈 전체 글 목록과 같은 카드, 최초 공개 시각 최신순(같으면 ID 큰 순), 9개씩, [더 보기] 커서 방식이어야 하며(MUST), 이어 붙여도 중복·누락이 없다. (C-READ-1과 같은 규칙)
- **FR-014**: 언팔로우하면 다음 피드 요청부터 그 사람의 글이 빠져야 한다(MUST). 이미 화면에 있는 카드는 그대로 둔다.
- **FR-015**: 피드 빈 상태는 팔로우한 사람이 없을 때 "팔로우한 사람이 없어요. 홈에서 읽고 싶은 블로그를 찾아보세요 [홈]", 있지만 공개 글이 없을 때 "팔로우한 사람의 공개 글이 아직 없어요"여야 한다(MUST).
- **FR-016**: 피드에서 뒤로 가기 시 불러온 카드·스크롤이 복원되어야 하고(MUST, 전체 글 목록과 같은 규칙), JS 없이도 [더 보기]가 다음 페이지 링크로 동작해야 한다.
- **FR-017**: 피드·팔로워·팔로잉 목록을 보여줄 때 조회 횟수가 항목 수에 비례하지 않아야 한다(MUST, N+1 금지). 피드는 글 1만 건 기준 공통 응답 목표(300ms)를 만족해야 한다.
- **FR-018**: 탈퇴 유예 중에는 팔로우 관계를 지우지 않고 목록·수·피드에서만 빼야 하며(MUST), 30일 뒤 익명 처리 정리에서 그 회원의 팔로우 관계를 양방향 모두 삭제한다.
- **FR-019**: 언팔로우는 상대에게 알리지 않아야 한다(MUST). 새 팔로워 알림과 새 글 알림 규칙은 인앱 알림 명세(017)를 따른다.
- **FR-020**: 팔로우·언팔로우 요청은 공통 IP 요청 횟수 제한 기준에 포함되어야 하며, 기준값은 공통 설정을 그대로 쓴다(MUST). (clarify 2026-10-07, 사용자 확정)

### Key Entities *(include if feature involves data)*

- **팔로우 관계**: 팔로우하는 회원 → 팔로우받는 회원, 팔로우한 시각. 같은 쌍은 하나뿐이고 자기 자신과의 관계는 없다. 친구 관계와 별개다.
- **팔로잉 피드 항목**: 팔로우한 회원의 공개 글 카드(전체 글 목록 카드와 같음).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 같은 사람에 대한 팔로우 요청 20건을 동시에 보내도 팔로우 관계 1건, 새 팔로워 사건 1건이다.
- **SC-002**: 피드에 비공개·친구 공개·임시·휴지통·탈퇴 유예 작성자의 글이 나오는 경우가 0건이다.
- **SC-003**: 피드 [더 보기]를 끝까지 넘겼을 때 중복·누락이 0건이다.
- **SC-004**: 언팔로우 직후 다음 피드 요청에서 그 사람의 글이 0건이다.
- **SC-005**: 비회원이 팔로워·팔로잉 수와 목록을 100% 볼 수 있고, 탈퇴 유예 회원은 목록·수에서 빠졌다가 복구 시 돌아온다.
- **SC-006**: 탈퇴 30일 정리 후 그 회원이 포함된 팔로우 관계가 0건이다.
- **SC-007**: 글 1만 건 기준 피드 첫 페이지가 300ms 안에 응답한다.

## Assumptions

- Tier C(공통 2차 후보) "팔로우·구독 + 피드"를 공통 범위로 정의한다.
- 팔로우 대상은 회원이다(20 결정 기록, 01 Q5 회원 = 블로그). 나민서의 "블로그 구독"은 화면 문구만 다르게 쓰고 같은 팔로우 관계를 쓴다(개인 확장).
- 팔로우 버튼은 블로그 상단(10 §5)과 글 상세 작성자 영역(40)에 붙는다. 카드·커서·뒤로 가기 복원은 전체 글 목록(10) 규칙을 그대로 쓴다.
- 팔로워가 수천 명 규모가 되면 피드를 미리 만들어 두는 방식을 검토한다(지금 범위 밖).
- 그룹(강성찬)·친구 공개(06 §6)는 팔로우와 별개 개인 확장/규격이다.
- 새 팔로워·새 글 알림은 017-notification에, 익명 처리 정리 순서는 탈퇴(44)에 의존한다.
- 권한 판정 순서·응답 코드는 권한 매트릭스(42)를 따른다. 관리자는 팔로우에서 일반 회원과 같다.
