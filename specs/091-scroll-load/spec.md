# Feature Specification: 무한 스크롤은 내려갔을 때만

**Feature Branch**: `091-scroll-load` | **Created**: 2026-10-14 | **Status**: Implemented

**Scope**: **강성찬 개인 확장** (10-14 chan "무한 스크롤인데 일정 수준 내려가면 그때 불러오는 형식으로 바꿔줘").

## 바꾸기 전(067)
- `list-more.js`가 목록 끝(.list-more)을 IntersectionObserver(rootMargin 400px)로 지켜봤다. 끝이 화면 아래 400px 안에 들어오면 불렀고, 붙인 뒤 관찰을 다시 걸어 아직 400px 안이면 바로 또 불렀다.
- 그래서 화면이 긴 PC에서는 열자마자 여러 묶음을 연달아 불렀다(세로 2700px 화면에서 4묶음, 헤드리스 Chrome 측정).

## 결정
- 스크롤할 때만 확인하고(100ms에 한 번), 목록 끝이 화면 아래 반 장(innerHeight × 0.5) 안에 들어오면 한 묶음을 부른다. 동시에 하나만, 실패하면 [다시 시도]를 누를 때까지 멈춘다.
- 열 때는 첫 묶음이 화면보다 짧아 목록 끝이 이미 보일 때만 화면이 찰 때까지 부른다.
- 묶음 크기(12개), "불러오는 중…", "모든 글을 다 봤어요", 스크립트 없을 때 [더 보기] 링크는 그대로.
- 공용 로더를 쓰는 곳 모두: 홈, 피드, 탐색 [추천]/[트렌딩], 검색, 태그, 블로그 글 목록, 글 아래 "관심 있을 만한 글".

## Success Criteria
- 헤드리스 Chrome(가짜 목록 API): 2700px 화면에서 열 때 부르는 묶음 수가 화면을 채우는 만큼으로 줄고, 휴대폰·보통 PC 화면은 스크롤해 끝에 가까워질 때 한 묶음씩.
