## User Scenarios & Testing *(mandatory)*

### User Story 1 - 쓰던 글이 자동으로 저장되고 나중에 이어 쓴다 (Priority: P1)

작성자가 [새 글]을 누르면 임시글이 바로 만들어지고, 제목·본문을 쓰는 동안 자동으로 저장된다. 창을 닫았다가 다시 열거나 다른 날 다시 와도 임시글을 열어 이어 쓸 수 있다. 화면에는 저장 상태가 글자로 보인다.

**Why this priority**: C-POST-2(Tier A)의 핵심 완료 기준 "임시글을 다시 열어 이어 쓸 수 있다"다.

**Independent Test**: 새 글 → 입력 → 저장 상태 "저장됨" 확인 → 브라우저 데이터를 지우고 다른 기기에서 열어 내용이 남아 있는지 확인.

**Acceptance Scenarios**:

1. **Given** 인증된 회원, **When** [새 글]을 누르면, **Then** 임시글이 즉시 만들어진다.
2. **Given** 임시글 편집 중, **When** 입력이 1초 멈추면, **Then** 내용이 이 기기에 저장되고 "● 이 기기에 저장됨 (동기화 대기)"가 보인다.
3. **Given** 바뀐 내용이 있음, **When** 입력이 3초 멈추거나(계속 입력 중이면 최대 30초마다) 탭이 가려지거나 페이지를 떠나면, **Then** 서버로 저장되고 "✓ 저장됨 HH:MM"이 보인다.
4. **Given** 서버에 자동 저장된 임시글, **When** 1분이 지나면, **Then** 내용이 영구 저장소에 반영되어 서버 쪽 임시 보관이 사라져도 남는다.
5. **Given** 임시글, **When** 다른 날 다른 기기에서 다시 열면, **Then** 마지막으로 서버에 저장된 제목·본문으로 이어 쓸 수 있다.
6. **Given** 편집 중, **When** [저장](수동 저장)을 누르면, **Then** 즉시 영구 저장소에 반영된다.
7. **Given** 바뀐 내용이 없음, **When** 시간이 지나도, **Then** 서버로 저장 요청을 보내지 않는다.
8. **Given** 태그 입력, **When** 자동 저장이 일어나도, **Then** 태그는 자동 저장 대상이 아니다(발행할 때 확정).

### User Story 2 - 네트워크가 끊겨도 글이 사라지지 않는다 (Priority: P1)

작성 중 네트워크가 끊기거나 서버 저장이 실패해도, 내용은 이 기기에 계속 저장된다. 연결되면 자동으로 동기화된다. 동기화되지 않은 내용이 있는데 페이지를 떠나려 하면 확인창이 뜬다.

**Why this priority**: "저장했다고 믿은 내용은 사라지지 않는다"는 원칙(D-1, D-3)의 핵심이다.

**Independent Test**: 오프라인 상태에서 입력 → "오프라인" 표시 확인 → 연결 복구 → 자동 동기화 후 "저장됨" 확인.

**Acceptance Scenarios**:

1. **Given** 오프라인, **When** 입력하면, **Then** "⚠ 오프라인 — 이 기기에 저장 중, 연결되면 자동 동기화"가 보이고 내용은 이 기기에 남는다.
2. **Given** 서버 저장 실패, **When** 재시도하면, **Then** 2초 → 4초 → 8초 … 최대 60초 간격(무작위 지연 포함)으로 재시도한다.
3. **Given** 서버로 못 보낸 내용이 있음, **When** 페이지를 떠나려 하면, **Then** 확인창이 뜬다.
4. **Given** 서버로 못 보낸 내용이 이 기기에 있고 그 출발 버전이 서버 버전과 같음, **When** 에디터를 다시 열면, **Then** 충돌로 보지 않고 "이 기기에 저장되지 않은 변경을 불러왔어요" 안내 후 이어서 편집한다.
5. **Given** 서버 쪽 임시 보관소가 장애로 연결되지 않음, **When** 자동 저장하면, **Then** 영구 저장소에 바로 저장되어 손실이 없다.
6. **Given** 발행에 성공했거나 동기화 완료 상태로 에디터를 떠남, **When** 이후 확인하면, **Then** 이 기기의 임시 데이터는 지워져 있다.

### User Story 3 - 여러 탭·기기에서 같은 글을 고치면 차이를 보고 고른다 (Priority: P2)

같은 글을 다른 탭이나 기기에서 먼저 저장했다면, 서버는 어느 쪽도 몰래 덮어쓰지 않는다. 편집은 막지 않고 배너로 알린 뒤, 비교 창에서 두 내용의 차이를 보여주고 사용자가 결과가 분명한 버튼으로 고르게 한다.

**Why this priority**: 결정 기록(여러 탭·기기 편집 충돌)으로 공통 범위다. 단일 탭 사용에는 영향이 없어 P1 다음이다.

**Independent Test**: 탭 두 개에서 같은 글 편집 → 한쪽 저장 → 다른 쪽 자동 저장 시 배너·비교 창 확인 → 세 가지 선택지의 결과 확인.

**Acceptance Scenarios**:

1. **Given** 탭 A와 B가 같은 버전에서 출발, **When** A가 저장한 뒤 B가 자동 저장하면, **Then** B의 저장은 거부되고 B의 편집은 막히지 않으며 B 내용은 이 기기에 계속 저장되고, "⚠ 다른 탭이나 기기에서 이 글이 수정되었어요(시각). 지금 내용은 이 기기에만 저장되고 있어요. [비교하기]" 배너가 보인다.
2. **Given** 충돌 상태, **When** [비교하기]나 수동 저장·발행을 누르면, **Then** 저장된 내용과 편집 중인 내용을 나란히(모바일은 위아래로 합쳐) 보여주는 비교 창이 뜨고, 바뀐 줄과 줄 안의 바뀐 단어가 강조되며 지워진 부분은 `−`, 추가된 부분은 `+` 기호로도 표시된다. 제목이 다르면 제목도 비교한다.
3. **Given** 비교 창, **When** [편집 중인 내용으로 저장]을 누르면, **Then** "…에 저장된 내용이 지금 편집 중인 내용으로 바뀌어요. 정말 저장할까요?" 확인 후에만 덮어쓴다.
4. **Given** 비교 창, **When** [저장된 내용 불러오기]를 누르면, **Then** 에디터가 서버 내용으로 바뀌고 편집 중이던 내용은 이 기기에 7일 동안 백업된다는 안내가 보인다.
5. **Given** 비교 창, **When** [새 임시글로 따로 저장]을 누르면, **Then** 편집 중인 내용으로 새 임시글이 생기고 원래 글은 서버 내용 그대로다.
6. **Given** 비교 창, **When** 닫기(X)를 누르면, **Then** 편집은 계속되고 서버 전송은 멈춘 채 배너가 유지된다.
7. **Given** 이 기기에 못 보낸 내용이 있고 그 출발 버전이 서버 버전과 다름, **When** 에디터를 다시 열면, **Then** 비교 창이 바로 뜬다.
8. **Given** 서버에 버전이 없는 상태에서 두 요청이 동시에 같은 출발 버전으로 저장, **When** 처리되면, **Then** 하나만 저장되고 다른 하나는 충돌이 된다.

### User Story 4 - 발행한 글을 고치는 동안 독자는 마지막 발행본을 본다 (Priority: P2)

발행한 글을 다시 열어 고치면, 자동 저장·수동 저장 내용은 작업본에만 저장되고 독자에게는 마지막 발행본이 그대로 보인다. 작성자는 변경을 취소해 작업본을 버릴 수 있다.

**Why this priority**: 결정 기록(Q9, 발행한 글 수정 중 자동 저장)이며 C-POST-3과 맞물린다. 발행(005)이 있어야 의미가 있다.

**Independent Test**: 발행 글 편집 → 자동 저장 → 비로그인으로 상세 조회해 이전 내용 확인 → 내 글 관리 "수정 중" 표시 확인 → 변경 취소 후 작업본 삭제 확인.

**Acceptance Scenarios**:

1. **Given** 발행한 글, **When** 작성자가 고쳐서 자동·수동 저장하면, **Then** 내용은 작업본에 저장되고 독자에게는 마지막 발행본이 보인다.
2. **Given** 작업본이 있는 발행 글, **When** 작성자가 다시 열면, **Then** 작업본이 열리고 내 글 관리에는 "수정 중"으로 표시된다.
3. **Given** 작업본이 있는 발행 글, **When** [변경 취소]를 누르면, **Then** 작업본과 서버 임시 보관 내용이 삭제되고 독자가 보던 발행본은 그대로다.
4. **Given** 작업본, **When** 서버 임시 보관과 브라우저 데이터가 모두 사라져도, **Then** 작업본은 영구 저장소에 남아 있다(1분 반영 주기 이내 내용).

---

### User Story 5 - 버려진 빈 임시글이 정리된다 (Priority: P3)

[새 글]만 누르고 아무것도 쓰지 않은 임시글은 하루가 지나면 자동으로 완전 삭제되어 내 글 관리에 쌓이지 않는다.

**Why this priority**: 결정 기록(빈 임시글 정리)이지만 사용자 흐름에는 부수적이다.

**Independent Test**: 빈 임시글 생성 → 24시간 경과를 흉내 내고 정리 작업 실행 → 삭제 확인; 제목만 있는 글은 남는지 확인.

**Acceptance Scenarios**:

1. **Given** 제목·본문이 모두 비어 있고 만든 지와 마지막 수정 후 모두 24시간이 지났으며 서버 임시 보관 내용도 없는 임시글, **When** 매일 새벽 정리 작업이 돌면, **Then** 완전 삭제된다.
2. **Given** 제목이나 본문 중 하나라도 있는 임시글, **When** 정리 작업이 돌면, **Then** 삭제되지 않는다.
3. **Given** 서버 임시 보관 내용이 남아 있는 빈 임시글, **When** 정리 작업이 돌면, **Then** 삭제되지 않는다.

---

### Edge Cases

- 남의 글이나 없는 글에 자동 저장 → 404(존재 여부를 드러내지 않음). 휴지통에 있는 글도 작성자라도 404.
- 비회원의 자동·수동 저장 → 401, 이메일 인증 전 회원 → 403(이메일 미인증).
- 자동 저장 요청이 사용자당 5초에 1번을 넘음 → 429와 재시도 가능 시각. 요청 본문 1MB 초과 → 413.
- 한 탭에서는 서버 요청을 한 번에 하나만 보내 응답 순서가 뒤바뀌지 않는다.
- 영구 반영 중에 더 새 버전이 들어옴 → 옛 버전이 새 버전을 덮어쓰지 않는다.
- 서버 임시 보관소 재시작 → 최대 약 1초 손실(브라우저에 남아 있으면 그것도 복구). 메모리 부족 시 자동 저장 내용이 밀려나지 않고 쓰기가 실패해 브라우저에 남아 재시도된다.
- 브라우저 데이터 삭제 → 서버에 최대 30초 이전까지의 내용이 남아 있다.
- 업로드 대기 중인 사진 표시(`local:`)가 본문에 있어도 자동 저장은 한다(발행만 거부, 005).
- 로그아웃 → 그 사용자의 이 기기 임시 데이터와 백업 모두 삭제(001). 다른 계정의 임시 데이터와 섞이지 않는다.
- 서버를 여러 대 운영해도 영구 반영 작업은 한 번만 실행된다.

## Requirements *(mandatory)*

### Functional Requirements

**원칙**

- **FR-001**: System MUST 임시글·작업본의 원본을 영구 저장소에 둬야 하며, 서버 쪽 임시 보관소는 최근 입력의 버퍼, 브라우저 저장소는 네트워크 단절 대비 백업으로만 써야 한다. 임시글은 보관 기간과 상관없이 다시 열어 이어 쓸 수 있어야 한다. (C-POST-2)
- **FR-002**: System MUST 사용자가 직접 누른 수동 저장과 발행을 즉시 영구 저장소에 반영해야 한다. (C-POST-2)
- **FR-003**: System MUST 자동 저장 대상을 제목과 본문으로 한정해야 한다. 태그는 발행할 때 확정한다. 사진 파일은 자동 저장 경로에 넣지 않고 본문에는 주소만 남긴다.

**3단계 저장**

- **FR-004**: System MUST 입력이 1초 멈출 때마다 이 기기(브라우저)에 저장해야 한다. 브라우저 저장 내용은 회원·글별로 구분되어 다른 계정과 섞이지 않아야 하며, 인증 정보는 저장하지 않는다. (C-POST-2)
- **FR-005**: System MUST 바뀐 내용이 있을 때만 서버로 보내야 한다: 입력이 3초 멈추면, 계속 입력 중이면 최대 30초마다, 그리고 탭이 가려질 때와 페이지를 떠날 때.
- **FR-006**: System MUST 서버로 받은 자동 저장 내용을 1분마다 영구 저장소에 반영해야 하며, 서버 쪽 임시 보관은 저장할 때마다 24시간으로 갱신되는 정리용 보관 기간을 가진다. 서버가 여러 대여도 반영 작업은 한 번만 실행되어야 한다.
- **FR-007**: System MUST 영구 반영 시 임시글은 글 자체에, 발행한 글은 별도의 작업본에 반영해야 하며, 더 오래된 버전으로 새 버전을 덮어쓰지 않아야 한다. 임시글 반영 시 화면용 렌더링은 하지 않는다(발행 시 한 번).
- **FR-008**: System MUST 자동 저장 요청을 사용자당 5초에 1번, 요청 본문 1MB로 제한하고, 넘으면 각각 재시도 시각을 담은 요청 과다(429)와 본문 과대(413)로 응답해야 한다.
- **FR-009**: System MUST 한 탭에서 서버 요청을 한 번에 하나씩 보내고, 실패하면 2초부터 두 배씩 최대 60초 간격으로 무작위 지연을 섞어 재시도해야 한다. 그동안 내용은 이 기기에 남아 있어야 한다.
- **FR-010**: System MUST 서버로 보내지 못한 내용이 있는데 페이지를 떠나려 하면 확인창을 띄워야 한다.
- **FR-011**: System MUST 저장 상태를 글자와 기호로 보여줘야 하며 색만으로 구분하지 않는다: "✓ 저장됨 HH:MM"(서버 반영), "● 이 기기에 저장됨 (동기화 대기)", "⚠ 오프라인 — 이 기기에 저장 중, 연결되면 자동 동기화", "⚠ 다른 곳에서 수정됨 — 이 기기에만 저장 중 [비교하기]".
- **FR-012**: System MUST 발행에 성공했을 때, 또는 서버와 동기화된 상태로 에디터를 떠날 때 이 기기의 해당 글 임시 데이터를 지워야 한다.
- **FR-013**: System MUST 서버 쪽 임시 보관소가 연결되지 않으면 자동 저장을 영구 저장소에 바로 쓰도록 전환하고, 이때도 같은 버전 확인을 해야 한다. 임시 보관소는 재시작 시 손실이 약 1초 이내여야 하고 메모리가 부족해도 자동 저장 내용을 밀어내지 않아야 한다.

**권한**

- **FR-014**: System MUST 자동·수동 저장을 글 작성자만 할 수 있게 하고, 남의 글·없는 글·휴지통 글은 404로 응답해야 한다. 비회원은 401, 이메일 인증 전 회원은 403(이메일 미인증)이다. (C-OWN-1, 42 §5-2)
- **FR-015**: System MUST [새 글]을 누르면 편집 버전 0인 임시글을 즉시 만들어 글 식별자를 돌려줘야 한다. 새 글의 공개 범위는 회원의 기본 공개 범위로 시작한다. (C-POST-2, C-POST-4)

**편집 버전과 충돌**

- **FR-016**: System MUST 글마다 서버가 매기는 편집 버전을 두고, 저장 요청의 출발 버전이 현재 버전과 같을 때만 저장하고 버전을 1 올려야 한다. 확인과 저장은 원자적이어야 하며, 동시에 같은 출발 버전으로 온 두 요청 중 하나만 성공해야 한다. (C-POST-2)
- **FR-017**: System MUST 출발 버전이 다르면 저장하지 않고 상태 충돌(409)과 함께 서버 쪽 제목·본문·버전·저장 시각을 돌려줘야 한다. 서버는 어느 쪽 내용도 몰래 덮어쓰지 않는다. 수동 저장도 같은 규칙이다.
- **FR-018**: System MUST 자동 저장 충돌 시 편집을 막지 않고(타이핑 중 창을 띄우지 않음) 서버 전송만 멈추며, 내용은 이 기기에 계속 저장하고 충돌 배너와 [비교하기]를 보여줘야 한다. [비교하기]·수동 저장·발행을 누르면 비교 창을 띄운다.
- **FR-019**: System MUST 에디터를 열 때 이 기기에 못 보낸 내용이 있으면, 그 출발 버전이 서버 버전과 같으면 이어서 편집하게 안내하고, 다르면 비교 창을 바로 띄워야 한다.
- **FR-020**: System MUST 비교 창에서 저장된 내용(저장 시각·출처)과 편집 중인 내용을 줄 단위로 비교하고 바뀐 줄 안에서는 단어 단위로 강조해야 하며, 지워진 부분과 추가된 부분을 색과 기호(`−`, `+`) 모두로 구분해야 한다. 제목이 다르면 제목도 비교한다. 넓은 화면은 좌우, 모바일은 위아래로 합쳐 보여주고, 긴 글은 [이전 차이]/[다음 차이] 이동과 바뀌지 않은 긴 구간 접기를 제공한다.
- **FR-021**: System MUST 비교 창에 결과가 이름에 드러나는 세 선택지를 제공해야 한다: [편집 중인 내용으로 저장](확인 문구에 동의한 경우에만 덮어씀), [저장된 내용 불러오기](편집 중 내용을 이 기기에 7일 백업), [새 임시글로 따로 저장](원래 글은 그대로). 닫기는 편집을 계속하고 배너를 유지한다.

**발행 글 수정(작업본)**

- **FR-022**: System MUST 발행한 글의 자동·수동 저장 내용을 작업본에만 저장하고, 독자에게는 마지막 발행본을 보여줘야 한다. (C-POST-3)
- **FR-023**: System MUST 발행 글을 다시 열 때 작업본이 있으면 작업본을, 없으면 발행본을 불러와야 하며, 작업본이 있는 글은 내 글 관리에 "수정 중"으로 표시해야 한다.
- **FR-024**: System MUST [변경 취소] 시 작업본과 서버 임시 보관 내용을 삭제하고 발행본은 그대로 둬야 한다.

**정리**

- **FR-025**: System MUST 매일 새벽, 제목·본문이 모두 비어 있고 만든 지와 마지막 수정 후 모두 24시간이 지났으며 서버 임시 보관 내용도 없는 임시글을 완전 삭제해야 한다.

### Key Entities *(include if feature involves data)*

- **글(Post)**: 임시글 또는 발행 글. 작성자, 제목, 본문(Markdown 원문), 상태(임시/발행), 편집 버전, 만든 시각, 마지막 수정 시각.
- **작업본(Post Draft)**: 발행한 글 하나에 0~1개. 고치는 중인 제목·본문과 편집 버전. 다시 발행하거나 변경 취소하면 사라진다.
- **서버 자동 저장 버퍼**: 글별 최근 자동 저장 내용(소유자, 제목, 본문, 편집 버전, 저장 시각)과 아직 영구 반영하지 않은 글 목록. 24시간 정리용 보관.
- **브라우저 임시 데이터**: 회원·글별 제목·본문, 출발 버전, 미전송 여부, 업로드 대기 사진, 갱신 시각. 비교 창에서 "저장된 내용 불러오기" 시 만들어지는 7일 백업.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 임시글은 브라우저 데이터와 서버 임시 보관이 모두 사라져도 마지막 영구 반영(최대 1분 전) 시점까지의 내용으로 다시 열린다.
- **SC-002**: 네트워크 단절 상태에서 입력한 내용은 연결 복구 후 손실 0으로 서버에 동기화된다.
- **SC-003**: 브라우저 데이터가 지워진 경우 손실은 최대 30초 분량이다.
- **SC-004**: 두 탭·두 기기의 동시 편집에서 사용자가 확인하지 않은 덮어쓰기는 0건이다.
- **SC-005**: 발행 글의 작업본을 저장하는 동안 비로그인 독자가 본 내용은 100% 마지막 발행본과 같다.
- **SC-006**: 동시에 같은 출발 버전으로 온 저장 요청 20건 중 성공은 정확히 1건이다.
- **SC-007**: 서버 임시 보관소가 장애인 동안에도 자동 저장 성공률이 정상 시와 같다.
- **SC-008**: 남의 글에 대한 자동·수동 저장 요청은 100% 404이고 글 내용·편집 버전이 바뀌지 않는다.
- **SC-009**: 정리 조건을 만족한 빈 임시글은 다음 정리 실행 후 0건 남고, 조건을 하나라도 벗어난 글은 삭제 0건이다.

## Assumptions

- Tier A(공통 필수): C-POST-2. 결정 기록 2026-10-02의 "임시저장 방식(브라우저 → 서버 임시 보관 → 영구 저장 3단계, 서버 단독 24시간 보관안 기각)", "발행한 글 수정 중 자동 저장(Q9, 작업본)", "여러 탭·기기 편집 충돌", "빈 임시글 정리", "자동 저장 범위", "공용 PC" 결정을 따른다.
- 사진 업로드(Presigned URL, 썸네일, 업로드 대기 사진 처리, 버려진 사진 정리)는 008 명세의 범위다. 이 명세는 "본문에는 사진 주소만 들어간다", "업로드 대기 표시가 있어도 자동 저장은 한다"는 연결점만 다룬다.
- 발행 처리 자체(검증·렌더링·멱등성)는 005 명세의 범위이며, 이 명세의 편집 버전·작업본·충돌 비교 창을 공유한다.
- 사용자가 직접 글을 삭제할 때 빈 임시글을 바로 삭제하는 규칙과 휴지통은 글 삭제 기능(C-POST-5)의 범위다.
- 저장 간격·반영 주기·보관 기간·요청 제한·백업 기간은 설정값(초기값은 원문 §2-1)이다.
- 발행 이력·되돌리기는 김민서 개인 확장이다.
