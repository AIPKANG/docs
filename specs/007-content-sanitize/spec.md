**Feature Branch**: `007-content-sanitize`

**Created**: 2026-10-07

**Status**: Draft

**Input**: docs/ 원문 문서에서 변환: docs/12-content-sanitize.md (연관: docs/01-common-requirements.md §2·§4, docs/05-publish.md §7, docs/10-post-list.md §2-1, docs/23-image.md §5-2)

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 본문의 스크립트는 절대 실행되지 않는다 (Priority: P1)

작성자가 본문이나 제목에 어떤 문자열을 넣어 발행하더라도, 그 글을 읽는 독자의 브라우저에서 스크립트가 실행되지 않는다. 본문에 직접 쓴 HTML은 글자 그대로 보이고, 위험한 링크 주소는 제거되며, 혹시 정화를 뚫더라도 브라우저 보안 정책이 실행을 막는다.

**Why this priority**: C-POST-1의 공통 완료 기준 "본문의 스크립트는 실행되지 않는다"이며, 실패하면 모든 독자가 위험해진다.

**Independent Test**: 검증된 XSS 공격 문자열 32개를 본문·제목에 넣어 발행한 뒤, 결과 HTML에 실행 가능한 스크립트가 없는지 자동 검사하고 브라우저 E2E에서 알림창이 뜨지 않는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 본문에 `<script>alert(1)</script>`, `<img src=x onerror=alert(1)>`, `<svg onload=…>` 등 직접 쓴 태그, **When** 발행하고 상세를 열면, **Then** 그 태그는 글자로 보이고 스크립트는 실행되지 않는다.
2. **Given** `[클릭](javascript:alert(1))`과 대소문자 섞기·HTML 엔티티·퍼센트 인코딩·앞 공백·참조형 링크로 숨긴 위험 주소, **When** 발행하면, **Then** 링크가 제거되거나 무해한 주소가 된다.
3. **Given** 링크·이미지 주소에 따옴표로 속성 탈출을 시도한 입력, **When** 발행하면, **Then** 새 속성이 추가되지 않는다.
4. **Given** 코드 블록·표 칸·체크리스트·제목 안에 넣은 `<script>`, `<img onerror>`, **When** 발행하면, **Then** 글자로 표시된다.
5. **Given** 아무 페이지, **When** 응답을 받으면, **Then** 인라인·외부 스크립트 실행 금지, 외부 이미지 차단, 다른 사이트의 iframe 삽입 금지, 콘텐츠 형식 추측 금지, 리퍼러 제한 보안 헤더가 붙어 있다.

### User Story 2 - Markdown으로 쓴 글이 의도대로 보인다 (Priority: P1)

작성자는 Markdown(CommonMark + GFM)으로 제목, 강조, 목록, 체크리스트, 표, 코드 블록, 링크, 이미지를 쓰고, 독자는 의도한 서식대로 읽는다. 외부 링크는 새 탭에서 안전하게 열리고, 외부 이미지는 링크로 바뀐다.

**Why this priority**: 글 작성의 기본 가치이며 C-POST-1 완료 기준 #2~#4에 해당한다.

**Independent Test**: 지원 문법 13가지 샘플을 발행해 기대 HTML 구조와 비교한다.

**Acceptance Scenarios**:

1. **Given** 본문 `# 원인`, **When** 발행하면, **Then** 본문 제목은 한 단계 낮춰 2단계 제목으로 보이고 본문 어디에도 1단계 제목이 없으며, 제목 앵커는 `h-원인`처럼 접두어가 붙는다.
2. **Given** 같은 이름의 본문 제목 두 개, **When** 발행하면, **Then** 앵커가 `-1`, `-2`처럼 겹치지 않게 붙는다.
3. **Given** 굵게·기울임·취소선·인라인 코드·목록·번호 목록·인용·구분선·표(정렬 포함)·체크리스트·언어 표시 코드 블록, **When** 발행하면, **Then** 각각 의도한 서식으로 보이고 체크리스트는 항상 읽기 전용이다.
4. **Given** 외부 사이트 링크, **When** 독자가 누르면, **Then** 새 탭으로 열리고 원래 탭을 바꿔치기할 수 없으며 검색 순위 효과가 없는 링크로 표시된다.
5. **Given** 우리 사이트 링크(상대 경로), **When** 누르면, **Then** 같은 탭에서 열린다.
6. **Given** 우리 저장소에 올린 이미지, **When** 발행하면, **Then** 이미지로 보이고 지연 로딩되며 최대 너비가 본문 폭이다.
7. **Given** 외부 이미지 주소 `![외부 배지](https://img.shields.io/…)`, **When** 발행하면, **Then** 이미지 대신 새 탭으로 열리는 "[이미지] 외부 배지" 링크가 보이고, 대체글이 없으면 주소가 보인다.
8. **Given** 코드 블록이 있는 글, **When** 브라우저에서 스크립트가 꺼져 있어도, **Then** 코드는 이스케이프된 글자로 읽힌다(강조만 빠짐).

### User Story 3 - 미리보기가 발행 결과와 같다 (Priority: P2)

작성자는 에디터에서 서버 렌더러가 만든 미리보기를 보고, 발행했을 때도 똑같은 결과를 얻는다.

**Why this priority**: 에디터 종류는 팀원마다 자유라 에디터 자체 미리보기는 참고용이다. 최종 결과를 미리 확인할 수 있어야 신뢰할 수 있다.

**Independent Test**: 같은 Markdown을 미리보기와 발행에 각각 넣어 결과 HTML이 같은지 비교한다.

**Acceptance Scenarios**:

1. **Given** 로그인한 작성자, **When** 입력이 0.5초 멈추면, **Then** 서버 미리보기 결과가 갱신된다.
2. **Given** 같은 본문, **When** 미리보기 결과와 발행 결과를 비교하면, **Then** 같다.
3. **Given** 1분에 60번을 넘는 미리보기 요청, **When** 요청하면, **Then** 요청 제한으로 거부된다.
4. **Given** 비회원, **When** 미리보기를 요청하면, **Then** 로그인이 필요하다는 응답을 받는다.

---

### User Story 4 - 너무 복잡한 본문은 발행되지 않는다 (Priority: P2)

목록·인용이 지나치게 깊거나 렌더링에 너무 오래 걸리는 본문은 서버를 멈추게 하지 않도록 발행이 거부되고 작성자에게 이유가 안내된다.

**Why this priority**: 렌더링 부하 공격으로 서비스 전체가 느려지는 것을 막는다(C-POST-1 완료 기준 #6).

**Independent Test**: 인용 25단계·목록 25단계 본문은 거부, 인용 15단계는 허용, 10만 자 본문은 정상 발행됨을 확인한다.

**Acceptance Scenarios**:

1. **Given** 목록 또는 인용이 20단계를 넘는 본문, **When** 발행하면, **Then** "글 구조가 너무 복잡해요 (목록·인용은 20단계까지)" 오류로 발행되지 않는다.
2. **Given** 렌더링에 1초를 넘게 걸리는 본문, **When** 발행하면, **Then** 같은 오류로 거부된다.
3. **Given** 인용 15단계 본문, **When** 발행하면, **Then** 정상 발행된다.

---

### User Story 5 - 글 제목의 숨은 문자 정리 (Priority: P2)

작성자가 입력한 제목에서 보이지 않는 글자·방향 뒤집기 문자·제어 문자가 제거되고, 제목은 글자로만 표시된다.

**Why this priority**: 방향 뒤집기 문자로 제목을 위장하거나 보이지 않는 글자로 같은 제목을 만드는 일을 막는다.

**Independent Test**: U+202E·폭 0 문자·NFD 한글이 섞인 제목을 저장해 정리 결과를 확인한다.

**Acceptance Scenarios**:

1. **Given** U+202E(방향 뒤집기)와 폭 0 문자가 섞인 제목, **When** 저장하면, **Then** 해당 문자가 제거된다.
2. **Given** 자모가 분리된(NFD) 한글 제목, **When** 저장하면, **Then** 완성형(NFC)으로 정규화된다.
3. **Given** 정리 후 비어 있거나 100자를 넘는 제목, **When** 발행하면, **Then** 거부된다.
4. **Given** `<b>` 등 태그가 든 제목, **When** 화면에 표시하면, **Then** 글자로 보인다.

---

### User Story 6 - 정화 규칙을 바꾸면 기존 글도 다시 정화된다 (Priority: P3)

운영자가 렌더러나 정화 규칙을 바꾸면 이미 발행된 글도 새 규칙으로 다시 렌더링되고, 작성자의 "수정됨" 표시나 편집 버전은 바뀌지 않는다.

**Why this priority**: 새로운 공격 기법이 발견됐을 때 과거 글까지 보호하기 위함이다. 평소에는 동작하지 않는 운영 기능이다.

**Independent Test**: 렌더링 버전을 올린 뒤 배치를 실행해 기존 발행 글의 본문 HTML·요약이 새 규칙으로 바뀌고 "수정됨"·편집 버전은 그대로인지 확인한다.

**Acceptance Scenarios**:

1. **Given** 이전 렌더링 버전으로 발행된 글들, **When** 렌더링 버전을 올리고 다시 렌더링을 실행하면, **Then** 그 글들의 본문 HTML과 요약이 새 규칙 결과로 바뀐다.
2. **Given** 다시 렌더링된 글, **When** 상세를 보면, **Then** "수정됨" 표시와 편집 버전은 그대로다.

---

### Edge Cases

- 정상 문법만으로 이뤄진 안전한 HTML을 위험으로 잘못 판정해 제거하지 않아야 한다(한글 제목 앵커 `h-원인` 유지 등).
- 내부 링크의 `@`가 인코딩되어 저장돼도 브라우저에서는 정상 주소로 동작해야 한다.
- 이미지 대체글 안에 `onerror` 같은 문자열이 있어도 대체글 값 안의 글자로만 남는다.
- `data:`, `vbscript:`, `javascript:` 이미지·링크 주소는 링크로 바뀌거나 제거된다.
- 요약이 비는 글(코드만 있는 글)도 정상 발행된다.
- WYSIWYG 에디터에서 쓴 글자 색·가운데 정렬처럼 Markdown에 없는 서식은 저장되지 않는다.
- 브라우저가 만든 HTML을 보내도 서버는 받지 않고 Markdown 원문만 받는다.
- 본문은 최대 100,000자다.
- 임시글은 렌더링하지 않는다(발행할 때 한 번 렌더링).
- 본문 안 GIF 이미지는 첫 장면 + ▶로 보이게 변환된다(이미지 업로드 기능에서 규칙 추가, 허용 목록은 바뀌지 않음).

## Requirements *(mandatory)*

### Functional Requirements

**저장과 처리 흐름**

- **FR-001**: 시스템은 글 본문을 Markdown 원문으로 MUST 저장해야 하며, 화면에 보일 HTML은 서버가 만들어 저장한다. 브라우저가 만든 HTML은 MUST NOT 받아야 한다. (C-POST-1)
- **FR-002**: 본문 HTML은 발행할 때 한 번만 MUST 만들어지고, 상세 조회 때는 저장된 결과를 그대로 써야 한다. 임시글은 렌더링하지 않는다. (C-POST-1, C-POST-3)
- **FR-003**: 본문 HTML 생성은 시스템 안의 단일 렌더러 한곳에서만 MUST 이뤄져야 하며, 발행·미리보기·다시 렌더링이 모두 같은 렌더러를 쓴다. (C-POST-1)
- **FR-004**: 처리 순서는 ① Markdown 해석(CommonMark + GFM) → ② 구조 변환(제목 단계 낮추기, 외부 이미지 → 링크, 중첩 깊이 검사) → ③ HTML 생성(직접 쓴 HTML 글자화, 주소 정화, 외부 링크 속성, 이미지 지연 로딩) → ④ 허용 목록 정화여야 MUST 하며, ③에 결함이 있어도 ④가 한 번 더 막는 이중 방어여야 한다. (C-POST-1)
- **FR-005**: 본문은 최대 100,000자로 MUST 제한되어야 한다. (C-POST-1)

**지원 문법**

- **FR-006**: 시스템은 CommonMark + GFM(표, 취소선, 체크리스트, 주소 자동 링크)을 MUST 지원해야 한다. 각주·수식·Mermaid·임베드는 공통 범위가 아니다. (C-POST-1)
- **FR-007**: 본문 제목은 한 단계씩 MUST 낮춰야 한다(`#` → 2단계, `######` → 6단계). 본문에는 1단계 제목이 없어야 한다. (C-POST-1)
- **FR-008**: 본문 제목 앵커는 `h-` 접두어 + 제목 글자로 MUST 만들고, 같은 이름은 `-1`, `-2`…를 붙여 겹치지 않게 한다. 앵커는 글자·숫자·`_`·`-`로 1~100자만 허용한다.
- **FR-009**: 체크리스트는 항상 읽기 전용 체크박스로 MUST 표시되어야 한다.
- **FR-010**: 코드 블록은 내용을 이스케이프하고 언어 표시(`language-` + 영문 소문자·숫자·`+#-` 1~20자)만 MUST 허용해야 한다. 코드 강조는 브라우저에서 하며 스크립트가 없어도 코드는 읽혀야 한다.
- **FR-011**: 본문에 직접 쓴 HTML은 전부 글자로 MUST 표시되어야 한다(예: `<b>`가 글자로 보임). (C-POST-1)

**허용 목록 정화**

- **FR-012**: 정화 단계는 다음 태그만 MUST 남겨야 한다: 문단, 줄바꿈, 구분선, 인용, 2~6단계 제목, 굵게, 기울임, 취소선, 목록(순서 없음/있음), 목록 항목, 체크박스, 코드, 코드 블록, 표 관련 태그(표·머리·몸통·행·머리 칸·칸), 링크, 이미지. 그 외(스크립트, 스타일, iframe, object, embed, form, svg, math, div, span 등)는 전부 제거한다. (C-POST-1)
- **FR-013**: 정화 단계는 허용 속성만 MUST 남겨야 한다: 제목 앵커(FR-008 형식), 번호 목록 시작 번호(숫자 1~6자리), 체크박스의 유형·체크됨·비활성, 코드 언어 표시(FR-010 형식), 표 칸 정렬(left/center/right), 링크의 주소·제목·새 탭·정해진 rel 값, 이미지의 주소(우리 저장소 주소로 시작할 때만)·대체글·제목·지연 로딩·비동기 디코딩. 이벤트 속성(`on…`)·`style`·다른 값의 `class`/`id`는 전부 제거한다.

**링크**

- **FR-014**: 링크 주소는 `http:`, `https:`, `mailto:`, `/`로 시작하는 상대 경로만 MUST 허용해야 하며, 그 밖의 프로토콜(`javascript:`, `data:`, `vbscript:` 등)은 대소문자 섞기, HTML 엔티티, 퍼센트 인코딩, 앞 공백, 참조형 링크로 숨겨도 제거되어야 한다. (C-POST-1)
- **FR-015**: 외부 링크는 새 탭 + `rel="noopener noreferrer nofollow ugc"`로 MUST 열려야 하고, 우리 사이트 링크는 같은 탭·rel 없이 열려야 한다. (C-POST-1)

**이미지**

- **FR-016**: 우리 저장소 이미지만 이미지로 MUST 표시되고(지연 로딩·비동기 디코딩, 최대 너비 = 본문 폭), 외부 이미지 주소는 `[이미지] 대체글` 외부 링크로 바뀌어야 한다. 대체글이 없으면 주소를 글자로 보여준다. (C-POST-1)
- **FR-017**: 외부 이미지 허용 도메인을 추가하는 개인 확장은 구조 변환·정화·브라우저 보안 정책 세 곳을 함께 바꿔야 MUST 한다.

**제목 정리**

- **FR-018**: 글 제목은 NFC로 정규화한 뒤 보이지 않는 글자(U+200B~U+200F, U+2060~U+2069, U+FEFF), 방향 제어 문자(U+202A~U+202E), 제어 문자를 제거하고 앞뒤 공백을 지운 다음 1~100자인지 MUST 검사해야 한다. 화면에서는 글자로만(이스케이프) 표시한다. (C-POST-1)

**부하 제한**

- **FR-019**: 목록·인용 중첩이 20단계를 넘거나 처리 전체가 1초를 넘으면 발행을 MUST 거부하고 "글 구조가 너무 복잡해요 (목록·인용은 20단계까지)"를 안내해야 한다(400 계열 오류). (C-POST-1)

**미리보기**

- **FR-020**: 로그인한 회원은 서버 렌더러와 같은 결과의 미리보기를 MUST 받을 수 있어야 한다. 입력이 0.5초 멈추면 호출하고, 사용자당 1분에 60번으로 제한한다. 최종 결과의 기준은 서버 렌더러다. (C-POST-1)

**다시 렌더링**

- **FR-021**: 각 발행 글은 어느 렌더링 규칙 버전으로 만들어졌는지 MUST 기록해야 한다. 렌더러·정화 규칙을 바꿔 버전을 올리면, 이전 버전 발행 글을 100개씩 다시 렌더링해 본문 HTML과 요약을 갱신해야 하고, "수정됨" 시각과 편집 버전은 MUST NOT 바뀌어야 한다. (C-POST-1)

**보안 헤더 (2차 방어)**

- **FR-022**: 모든 응답에 브라우저 보안 정책을 MUST 붙여야 한다: 스크립트는 우리 출처만(인라인 금지), 이미지는 우리 출처·우리 저장소·`data:`만, object 금지, 다른 사이트의 프레임 삽입 금지, base 주소 변경 금지, 폼 전송은 우리 출처만, 스타일은 우리 출처와 인라인 허용. 그리고 콘텐츠 형식 추측 금지(`nosniff`), 리퍼러 정책(`strict-origin-when-cross-origin`)을 붙인다. (C-POST-1)

**에디터**

- **FR-023**: 에디터 종류는 팀원마다 자유지만, WYSIWYG 에디터는 Markdown으로 내보내야 MUST 하며 Markdown에 없는 서식은 저장되지 않는다.

### Key Entities *(include if feature involves data)*

- **글 본문**: Markdown 원문, 정화된 본문 HTML, 요약(목록 카드용, 코드·이미지·표 제외 200자), 렌더링 규칙 버전.
- **글 제목**: 정리된 1~100자 글자.
- **정화 허용 목록**: 허용 태그·속성·주소 프로토콜·이미지 출처의 집합. 바꾸면 렌더링 규칙 버전이 오른다.
- **미리보기 요청**: 로그인 회원의 Markdown 입력과 그에 대한 서버 렌더링 결과. 사용자별 요청 횟수 제한 대상.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 검증된 XSS 공격 문자열 32개 전부를 본문·제목에 넣어 발행해도 실행 가능한 스크립트가 0건이고, 브라우저 E2E에서 알림창이 0번 뜬다.
- **SC-002**: 정상 문법 샘플 13개가 100% 기대한 구조로 표시되고, 본문의 1단계 제목은 0건이다.
- **SC-003**: 같은 입력의 미리보기 결과와 발행 결과가 100% 일치한다.
- **SC-004**: 10만 자 본문이 1초 안에 처리되어 발행되고, 20단계를 넘는 중첩 본문은 100% 거부된다.
- **SC-005**: 모든 응답의 100%에 보안 헤더 세 가지(브라우저 보안 정책, 형식 추측 금지, 리퍼러 정책)가 있다.
- **SC-006**: 렌더링 버전을 올린 뒤 다시 렌더링이 끝나면 이전 버전으로 남은 발행 글이 0건이고, "수정됨" 시각이 바뀐 글도 0건이다.
- **SC-007**: 위험 HTML 검사기는 위험 샘플 6개를 모두 잡고 안전 샘플 3개를 위험으로 잘못 판정하지 않는다.

## Assumptions

- **Tier**: C-POST-1은 Tier A(공통 필수).
- **결정 기록에서 가져온 사항(2026-10-02)**: CommonMark + GFM(각주·수식·Mermaid·임베드는 개인 확장), 직접 쓴 HTML 글자화 + 허용 목록 정화 이중 방어, 링크 프로토콜 제한·외부 링크 새 탭 + rel, 우리 저장소 이미지만 표시, 제목 단계 낮추기·`h-` 접두어·중첩 20단계·1초 제한·렌더링 버전, 보안 헤더 3종, 글 제목 정리, 본문 최대 100,000자.
- **저장소**: "우리 저장소" 이미지 주소는 MinIO 공개 주소 또는 그 앞의 CDN 주소다(결정 기록 2026-10-06). 정확한 공개 주소는 운영 배포 전 확인 항목이다.
- **설정값**: 중첩 한도 20, 처리 시간 1초, 미리보기 1분 60번·0.5초 대기, 다시 렌더링 100개 단위는 설정값으로 둔다.
- **개인 확장**: 임베드(`youtube-nocookie.com` + sandbox만), 외부 배지 이미지 허용 도메인, 코드 복사 버튼(김민서), 목차 화면은 개인 확장이다.
- **범위 밖**: 댓글은 Markdown 없이 글자만(줄바꿈 유지)이며 댓글 명세에서 확정한다. 요약 생성의 세부 규칙은 목록 명세(009)·발행 명세에서 다룬다. GIF 표시 규칙은 이미지 업로드 명세(008)가 구조 변환에 추가하며 허용 목록·보안 정책은 바꾸지 않는다.
- 렌더러·정화 라이브러리의 버전은 팀 확정 사항이며 계획 단계에서 따른다(source-notes.md).
