## User Scenarios & Testing *(mandatory)*

### User Story 1 - 닉네임·소개를 한 번에 저장한다 (Priority: P1)

로그인한 회원이 설정 화면에서 닉네임과 소개를 고치고 [저장]을 누른다. 모든 값이 검사를 통과해야 저장되고, 하나라도 실패하면 아무것도 바뀌지 않으며 실패한 칸마다 이유가 보인다. 블로그 주소와 이메일은 읽기 전용이다.

**Why this priority**: C-AUTH-2(Tier A)의 핵심 동작이다. 프로필 이미지 없이도 독립적으로 가치가 있다.

**Independent Test**: 정상 저장 → 목록·글 상세·댓글에 즉시 반영 확인; 소개 201자 + 정상 닉네임으로 저장 → 닉네임도 바뀌지 않음 확인.

**Acceptance Scenarios**:

1. **Given** 로그인한 회원, **When** 규칙에 맞는 닉네임과 소개로 저장하면, **Then** 둘 다 저장되고 목록·글 상세·댓글에 즉시 반영된다.
2. **Given** 로그인한 회원, **When** 정상 닉네임과 201자 소개를 함께 저장하면, **Then** 어떤 값도 바뀌지 않고 소개 칸에 "소개는 200자까지 쓸 수 있어요"(`BIO_TOO_LONG`)가 보인다.
3. **Given** 여러 칸이 동시에 규칙 위반, **When** 저장하면, **Then** 실패한 칸이 모두 한 번에 돌아온다.
4. **Given** 소개에 `<script>alert(1)</script>`, **When** 저장 후 블로그 상단을 보면, **Then** 스크립트가 실행되지 않고 글자 그대로 보인다.
5. **Given** 소개에 5줄 이상, **When** 저장하면, **Then** "소개는 4줄까지 쓸 수 있어요"(`BIO_TOO_MANY_LINES`)로 거부된다. 빈 줄이 연달아 있으면 하나로 줄인 뒤 센다.
6. **Given** 소개에 금칙어, **When** 저장하면, **Then** "사용할 수 없는 단어가 들어 있어요"(`BIO_BANNED_WORD`)로 거부된다.
7. **Given** 닉네임 30일 변경 제한 중인 회원, **When** 닉네임 변경 없이 소개만 저장하면, **Then** 소개는 저장된다. 같은 요청에 닉네임 변경이 들어 있으면 전체가 실패한다.
8. **Given** 비회원, **When** 설정 화면에 들어오면, **Then** 로그인 화면으로 이동한다.
9. **Given** 회원, **When** 블로그 주소·이메일을 바꾸려 하면, **Then** 바꿀 수 없고 화면에는 "변경할 수 없어요"로 읽기 전용 표시된다.

### User Story 2 - 프로필 이미지를 올리거나 기본 이미지로 되돌린다 (Priority: P1)

회원이 사진을 골라 정사각형으로 자르면 256×256 이미지로 바뀌어 올라가고, [저장]을 눌러야 프로필에 연결된다. 이미지가 없으면 닉네임 첫 글자가 들어간 동그란 기본 아이콘이 보인다. 연결된 프로필 이미지는 사진 정리 작업이 지우지 않는다.

**Why this priority**: C-AUTH-2의 공통 완료 기준에 포함되며, 사진 정리 배치가 프로필 이미지를 지우는 문제(R-7)를 막아야 한다.

**Independent Test**: 이미지 업로드 → 저장 → 정리 작업 실행 후에도 이미지 유지 확인; 이미지 교체 → 이전 이미지가 7일 뒤 삭제 확인; 남의 이미지·글용 이미지 연결 시도 거부 확인.

**Acceptance Scenarios**:

1. **Given** 인증된 회원, **When** jpg·png·gif·webp 10MB 이하 사진을 골라 정사각형으로 잘라 올리고 저장하면, **Then** 256×256 이미지가 프로필에 연결되고 촬영 위치 등 메타데이터는 남지 않는다.
2. **Given** 업로드만 하고 [저장]을 누르지 않은 이미지, **When** 24시간이 지나면, **Then** 그 이미지는 정리되어 사라진다.
3. **Given** 프로필에 연결된 이미지, **When** 정리 작업이 돌면, **Then** 삭제되지 않는다.
4. **Given** 프로필 이미지를 새 이미지로 바꾸거나 [기본 이미지로]를 누름, **When** 7일이 지나면, **Then** 이전 이미지는 삭제된다.
5. **Given** 정확히 256×256이 아니거나 1MB를 넘는 이미지, **When** 업로드 완료를 요청하면, **Then** 거부된다.
6. **Given** 다른 회원이 올린 이미지, 글용 이미지, 또는 삭제된 이미지, **When** 프로필에 연결하려 하면, **Then** `INVALID_PROFILE_IMAGE`로 거부되고 프로필은 바뀌지 않는다.
7. **Given** 이미지가 없는 회원, **When** 프로필이 표시되면, **Then** 닉네임 첫 글자(영문은 대문자)가 들어간 동그란 아이콘이 블로그 주소로 정해진 색 배경으로 보인다.
8. **Given** 이메일 인증 전 회원, **When** 프로필 이미지를 올리려 하면, **Then** 이메일 미인증으로 거부된다(닉네임·소개 수정은 가능).

### User Story 3 - 소셜 가입 때 소셜 프로필 사진을 가져온다 (Priority: P2)

Google·GitHub로 가입하는 사람은 가입 마무리 화면에서 "프로필 사진 사용"(기본 체크)을 선택할 수 있다. 계정이 만들어진 직후 브라우저가 소셜 사진을 받아 256×256으로 바꿔 우리 저장소에 복사해 연결한다. 소셜 사진 주소 자체는 저장하지 않는다.

**Why this priority**: 결정 기록(소셜 프로필 사진)으로 공통 범위이지만, 가입(001)과 이미지 업로드(US2)가 먼저 있어야 한다.

**Independent Test**: 사진 사용을 켠 채 소셜 가입 → 프로필 이미지 주소가 우리 저장소 주소인지 확인; 가져오기 실패를 흉내 내 기본 이미지와 안내 문구 확인.

**Acceptance Scenarios**:

1. **Given** "프로필 사진 사용"이 체크된 소셜 가입, **When** 가입을 완료하면, **Then** 소셜 사진의 복사본이 우리 저장소에 저장되어 프로필에 연결되고, 저장된 주소는 소셜 서비스 주소가 아니다.
2. **Given** 체크를 끈 소셜 가입, **When** 가입을 완료하면, **Then** 기본 이미지가 보인다.
3. **Given** 소셜 사진을 5초 안에 받지 못하는 등 가져오기 실패, **When** 가입을 완료하면, **Then** 가입은 성공하고 기본 이미지로 두며 "소셜 사진을 가져오지 못했어요. 설정에서 직접 올릴 수 있어요"가 보인다.
4. **Given** 허용된 소셜 사진 호스트(Google·GitHub 공식 사진 호스트)가 아니거나 HTTPS가 아닌 사진 주소, **When** 가입 마무리 화면을 열면, **Then** 그 주소는 화면에 전달되지 않는다.
5. **Given** 가입 후 소셜 쪽 사진을 바꿈, **When** 우리 프로필을 보면, **Then** 가입 때 복사한 사진 그대로다.

### User Story 4 - 비밀번호를 바꾸고 새 글 기본 공개 범위를 정한다 (Priority: P2)

이메일 가입 회원은 현재 비밀번호를 확인한 뒤 새 비밀번호로 바꿀 수 있다. 바꾸면 지금 기기는 로그인을 유지하고 다른 기기는 모두 로그아웃되며 알림 메일이 간다. 모든 회원은 새 글의 기본 공개 범위를 정할 수 있다.

**Why this priority**: 비밀번호 변경은 결정 기록(2026-10-02)으로 공통에 추가됐지만 프로필 수정보다는 덜 자주 쓰인다.

**Independent Test**: 두 기기 로그인 → 한 기기에서 비밀번호 변경 → 다른 기기 로그아웃·현재 기기 유지·메일 발송 확인; 소셜 계정의 변경 시도 거부 확인.

**Acceptance Scenarios**:

1. **Given** 이메일 가입 회원이 두 기기에 로그인, **When** 한 기기에서 올바른 현재 비밀번호와 규칙에 맞는 새 비밀번호로 변경하면, **Then** 다른 기기는 로그아웃되고, 지금 기기는 새 세션으로 로그인이 유지되며, "본인이 아니라면 [비밀번호 재설정]" 알림 메일이 간다.
2. **Given** 현재 비밀번호를 틀림, **When** 변경하면, **Then** `CURRENT_PASSWORD_MISMATCH`로 거부되고, 5회 연속 틀리면 15분 동안 잠긴다.
3. **Given** 새 비밀번호가 현재와 같음, **When** 변경하면, **Then** `PASSWORD_SAME_AS_CURRENT`로 거부된다.
4. **Given** 새 비밀번호가 규칙(8~16자, 영문·숫자·특수문자 각 1개 이상, 금지 목록) 위반, **When** 변경하면, **Then** 거부된다.
5. **Given** 소셜 가입 회원, **When** 설정 화면을 보면, **Then** [비밀번호 변경] 버튼이 없고, 직접 요청해도 `PASSWORD_NOT_SUPPORTED`로 거부된다.
6. **Given** 회원, **When** 새 글 기본 공개 범위를 "나만 보기"로 바꾸면, **Then** 이후 새로 만드는 글은 비공개로 시작한다.

---

### Edge Cases

- 두 기기에서 프로필을 동시에 수정 → 나중에 저장한 쪽이 반영된다(비교 창 없음).
- 보내지 않은 칸은 바뀌지 않는다. 이미지 값을 비움으로 보내면 기본 이미지로 돌아간다.
- 소개 0자(비움) → 허용.
- 소개에 이모지 → 허용. 주소 텍스트 → 링크로 바뀌지 않고 글자로 보인다.
- 소개 앞뒤 공백 → 제거, NFD 한글 → NFC로 정리.
- GIF를 프로필 이미지로 → 첫 장면의 정지 이미지가 된다.
- 소셜 사진이 없는 계정 → 소셜 서비스가 주는 기본 사진(이름 첫 글자·기본 무늬)을 그대로 가져온다.
- 남의 프로필을 수정할 경로 자체가 없다(요청 주소에 회원 식별자가 없음).
- 정지 회원은 로그인할 수 없으므로 정지 기간에 프로필·비밀번호를 바꿀 수 없다.
- 사진 업로드 요청은 사용자당 1분에 20장으로 제한된다.
- 기본 이미지 배경색은 라이트·다크 모드 모두 글자와 명도 대비 4.5:1 이상이다.

## Requirements *(mandatory)*

### Functional Requirements

**접근·대상**

- **FR-001**: System MUST 설정 화면을 로그인한 회원에게만 열고, 비회원은 로그인 화면으로 보내야 한다. (C-AUTH-2)
- **FR-002**: System MUST 프로필 수정 대상을 로그인 정보로만 정하고, 요청에 다른 회원의 식별자를 받는 경로를 두지 않아야 한다. 닉네임·소개·프로필 이미지는 본인만 바꿀 수 있다. (C-AUTH-2, C-OWN-1)
- **FR-003**: System MUST 블로그 주소와 이메일을 읽기 전용으로 보여주고 바꿀 수 없게 해야 하며, 로그인 수단도 읽기 전용으로 보여줘야 한다. (C-AUTH-2)

**저장**

- **FR-004**: System MUST 닉네임·소개·프로필 이미지를 [저장] 한 번에 반영하되, 보낸 칸만 바꿔야 한다. (C-AUTH-2)
- **FR-005**: System MUST 보낸 모든 칸을 검사하고, 하나라도 실패하면 아무것도 저장하지 않으며 실패한 칸과 이유를 모두 돌려줘야 한다. (C-AUTH-2)
- **FR-006**: System MUST 닉네임은 002 기능의 규칙(형식·예약어·금칙어·중복·30일 변경 제한)으로 검사해야 하며, 30일 제한 중 닉네임 변경이 포함된 요청은 전체를 실패시켜야 한다.
- **FR-007**: System MUST 동시 수정 시 나중에 저장한 쪽을 반영해야 한다.
- **FR-008**: System MUST 저장한 프로필을 목록·글 상세·댓글에 즉시 반영해야 한다.

**소개**

- **FR-009**: System MUST 소개를 0~200자의 글자로만 다뤄야 한다(HTML·Markdown 불가, 표시할 때 이스케이프). 앞뒤 공백 제거와 NFC 정규화 후 검사한다. (C-AUTH-2)
- **FR-010**: System MUST 소개의 줄바꿈을 최대 4줄까지 허용하고 연속된 빈 줄은 하나로 줄여야 하며, 이모지를 허용하고, 주소를 자동 링크로 바꾸지 않아야 한다.
- **FR-011**: System MUST 소개에 닉네임과 같은 금칙어 필터를 적용해야 한다(예약어 검사는 제외). 오류는 `BIO_TOO_LONG`, `BIO_TOO_MANY_LINES`, `BIO_BANNED_WORD`와 지정 문구로 알려준다.

**프로필 이미지**

- **FR-012**: System MUST 프로필 이미지로 jpg·png·gif·webp 10MB 이하 파일을 받아, 사용자가 위치·확대를 조정해 정사각형으로 자른 256×256 이미지 한 가지로 만들고 메타데이터(EXIF)를 제거해야 한다. GIF는 첫 장면의 정지 이미지로 만든다. (C-AUTH-2, C-IMG-1)
- **FR-013**: System MUST 프로필 이미지 업로드 완료 시 형식·실제 파일 내용(위장 여부)·정확히 256×256·1MB 이하를 서버에서 검사해야 하며, 프로필 용도 이미지는 목록용 썸네일을 만들지 않는다.
- **FR-014**: System MUST 프로필 이미지 연결 시 본인이 올렸고, 프로필 용도이며, 삭제되지 않은 이미지인지 검사하고, 아니면 `INVALID_PROFILE_IMAGE`로 거부해야 한다. (C-AUTH-2 기준 4)
- **FR-015**: System MUST 업로드만 되고 [저장]으로 연결되지 않은 프로필 이미지는 임시 상태로 두어 24시간 뒤 정리해야 한다.
- **FR-016**: System MUST 프로필에 연결된 이미지는 사진 정리 작업이 지우지 않게 하고, 교체되거나 [기본 이미지로]로 연결이 끊긴 이전 이미지는 7일 뒤 지워야 한다. 연결·연결 해제·이전 이미지 표시는 하나의 원자적 작업으로 처리한다. (C-AUTH-2 기준 5)
- **FR-017**: System MUST 이메일 인증 전 회원의 프로필 이미지 업로드를 거부해야 한다(닉네임·소개 수정은 허용). 사진 업로드는 사용자당 1분에 20장으로 제한한다. (42 §9)
- **FR-018**: System MUST 이미지가 없으면 닉네임 첫 글자(영문은 대문자)가 들어간 동그란 기본 아이콘을 화면에서 그려 보여줘야 하며(파일 저장 없음), 배경색은 블로그 주소로 정해지는 8가지 색 중 하나로 사람마다 다르고 항상 같으며 라이트·다크 모드 모두 글자와 명도 대비 4.5:1 이상이어야 한다.

**소셜 프로필 사진**

- **FR-019**: System MUST 소셜 가입 마무리 화면에 "프로필 사진 사용"(기본 체크)과 미리보기를 제공해야 한다.
- **FR-020**: System MUST 소셜 사진 주소를 Google·GitHub의 공식 사진 호스트이고 HTTPS인 경우에만 화면에 전달하고, 256 크기로 요청해야 한다.
- **FR-021**: System MUST 소셜 사진을 서버가 직접 내려받지 않고, 계정 생성 직후 브라우저가 받아 가운데를 정사각형으로 잘라 256×256으로 만든 뒤 일반 프로필 이미지와 같은 흐름으로 우리 저장소에 복사해 연결해야 한다. 소셜 사진 주소는 저장하지 않는다. (C-AUTH-2 기준 6)
- **FR-022**: System MUST 소셜 사진 가져오기가 실패하거나 5초 안에 끝나지 않으면 가입을 성공시키고 기본 이미지로 두며 "소셜 사진을 가져오지 못했어요. 설정에서 직접 올릴 수 있어요"를 안내해야 한다.
- **FR-023**: System MUST 소셜 사진을 가입할 때 한 번만 복사하고, 이후 소셜 쪽 사진 변경을 따라가지 않아야 한다.

**비밀번호 변경**

- **FR-024**: System MUST 이메일 가입 계정만 비밀번호를 바꿀 수 있게 하고, 소셜 계정에는 버튼을 보이지 않으며 요청도 `PASSWORD_NOT_SUPPORTED`로 거부해야 한다. (C-AUTH-2 기준 7)
- **FR-025**: System MUST 비밀번호 변경 시 현재 비밀번호를 확인하고, 새 비밀번호는 001 기능의 규칙(8~16자, 영문·숫자·특수문자 각 1개 이상, 금지 목록)을 따르며, 새 비밀번호 확인 값이 일치해야 하고, 현재와 같으면 `PASSWORD_SAME_AS_CURRENT`로 거부해야 한다.
- **FR-026**: System MUST 현재 비밀번호가 틀리면 `CURRENT_PASSWORD_MISMATCH`로 거부하고, 5회 연속 틀리면 15분 동안 비밀번호 변경을 잠가야 한다.
- **FR-027**: System MUST 비밀번호 변경 후 다른 기기의 세션을 모두 끊고, 지금 기기는 세션 식별자를 새로 발급해 로그인을 유지하며, "비밀번호가 변경됐어요. 본인이 아니라면 [비밀번호 재설정]" 알림 메일을 보내야 한다. (C-AUTH-2 기준 7)

**계정 설정**

- **FR-028**: System MUST 회원이 새 글 기본 공개 범위를 `PUBLIC`(전체 공개) 또는 `PRIVATE`(나만 보기)로 정할 수 있게 해야 하며(친구 공개 구현자는 `FRIENDS` 추가), 기본값은 `PUBLIC`이다. 새 글은 이 값으로 시작한다. (C-POST-4)
- **FR-029**: System MUST 설정 화면에 회원 탈퇴 진입점을 보여줘야 한다(탈퇴 처리는 회원 탈퇴 기능의 범위).

### Key Entities *(include if feature involves data)*

- **회원 프로필**: 닉네임, 소개(0~200자 글자), 프로필 이미지 연결(없으면 기본 아이콘), 목록에서 바로 쓰는 프로필 이미지 주소, 새 글 기본 공개 범위. 블로그 주소·이메일은 읽기 전용.
- **이미지(용도 구분)**: 업로드한 사람, 용도(글용 / 프로필용), 상태(임시 / 연결됨), 연결 해제 시각. 정리 작업은 임시 24시간, 연결 해제 7일 규칙을 프로필 이미지에도 똑같이 적용한다.
- **로그인 수단**: 이메일 가입인지 소셜인지(비밀번호 변경 가능 여부 판단), 비밀번호.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 여러 칸 중 하나라도 검사에 실패한 저장 요청에서 프로필 값이 바뀐 경우가 0건이다.
- **SC-002**: 소개에 넣은 HTML·스크립트 공격 문자열이 블로그 상단에서 실행되는 경우가 0건이고 글자로 보인다.
- **SC-003**: 256×256이 아닌 이미지, 남의 이미지, 글용 이미지, 삭제된 이미지의 프로필 연결 시도가 100% 거부된다.
- **SC-004**: 연결된 프로필 이미지는 정리 작업을 몇 번 돌려도 삭제되지 않고, 연결이 끊긴 이전 이미지는 7일이 지난 뒤 첫 정리에서 삭제된다.
- **SC-005**: 소셜 사진을 가져온 계정의 프로필 이미지 주소가 소셜 서비스 주소인 경우가 0건이다.
- **SC-006**: 비밀번호 변경 후 다른 기기 세션은 100% 로그인 필요 상태가 되고, 변경한 기기는 로그인이 유지된다. 소셜 계정의 비밀번호 변경 성공은 0건이다.
- **SC-007**: 저장한 프로필은 다음 페이지 조회부터 목록·글 상세·댓글 모두에 반영된다.
- **SC-008**: 회원이 설정 화면에서 닉네임·소개를 고쳐 저장하는 데 1분 이내가 걸린다.

## Assumptions

- Tier A(공통 필수): C-AUTH-2. 결정 기록 2026-10-02의 "소개", "프로필 이미지", "소셜 프로필 사진", "프로필 저장", "비밀번호 변경", "닉네임 변경", "기본 공개 범위" 결정을 따른다.
- 소개에 외부 링크 칸을 두는 것은 김민서 개인 확장이다(R-2). 친구 공개(`FRIENDS`)는 공통 규격·선택 구현이다.
- 사진 업로드 일반 흐름(사전 발급 주소로 직접 업로드, 완료 검사, 정리 작업)은 사진 업로드 기능(C-IMG-1, 04 §4·23)을 재사용하고, 이 기능은 프로필 용도의 차이만 정한다. 파일 저장소 제품은 결정 기록(2026-10-06)을 따른다.
- Google·GitHub 사진 서버가 다른 사이트의 브라우저 읽기를 허용함을 2026-10-02에 확인했다는 전제에 의존한다.
- 수치(소개 길이·줄 수, 이미지 크기, 정리 기간, 잠금 횟수·시간, 업로드 제한)는 설정값이다.
- 닉네임 규칙 자체는 002, 비밀번호 규칙과 재설정은 001, 회원 탈퇴는 13·44 기능의 범위다.
- 이메일 변경은 지원하지 않는다(R-9).
