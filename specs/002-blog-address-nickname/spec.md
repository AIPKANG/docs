## User Scenarios & Testing *(mandatory)*

### User Story 1 - 가입할 때 블로그 주소를 정한다 (Priority: P1)

가입하는 사람에게 블로그 주소(`/@주소`)가 이메일 앞부분으로 미리 채워진다. 이메일을 드러내고 싶지 않으면 가입할 때 한 번 직접 고칠 수 있고, 가입 후에는 바꿀 수 없다. 소셜 가입은 `go-`(Google)·`gi-`(GitHub) 접두어가 고정으로 붙어 이메일 가입 주소와 겹치지 않는다.

**Why this priority**: 블로그 주소는 개인 블로그 `/@주소`(C-BLOG-1)와 바꿀 수 없는 신원(C-AUTH-2)의 기준이다. 가입(001)에 꼭 필요하다.

**Independent Test**: 같은 이메일 앞부분으로 이메일·Google·GitHub 가입을 차례로 해서 미리 채워진 주소가 서로 다르고 규칙대로임을 확인하고, 가입 후 주소 변경 시도가 모두 실패함을 확인한다.

**Acceptance Scenarios**:

1. **Given** `kim755030@naver.com`으로 이메일 가입 중, **When** 이메일을 입력하면, **Then** 블로그 주소 칸에 `kim755030`이 채워지고 "이메일 앞부분으로 미리 채웠어요… 가입 후 바꿀 수 없어요" 안내가 보인다.
2. **Given** `kim755030`이 이미 있음, **When** `kim755030@daum.net`으로 가입하면, **Then** `kim755030_2`가 미리 채워진다.
3. **Given** `kim755030@gmail.com`의 Google 계정과 `kim755030@naver.com`의 GitHub 계정, **When** 각각 소셜 가입하면, **Then** `go-kim755030`, `gi-kim755030`이 미리 채워지고 접두어는 고칠 수 없다.
4. **Given** 이메일 `Kim.Min-Seo+blog@naver.com`, **When** 주소를 미리 채우면, **Then** `kim_min_seo`가 된다(대문자 없음, `-` 없음).
5. **Given** 사용자가 주소 칸을 직접 고침, **When** 이후 이메일을 다시 바꾸면, **Then** 주소 칸은 자동으로 바뀌지 않는다.
6. **Given** 두 사람이 같은 주소로 동시에 가입, **When** 둘 다 완료하면, **Then** 한 명만 그 주소를 갖고, 늦은 쪽에는 "방금 다른 분이 이 주소를 사용했어요. `…_2`는 어떠세요?"가 보인다.
7. **Given** 가입한 회원, **When** 프로필 수정 등 어떤 경로로든 블로그 주소 변경을 시도하면, **Then** 바뀌지 않는다(프로필 화면에서는 읽기 전용).

### User Story 2 - 닉네임을 정하고 규칙에 맞게 검사받는다 (Priority: P1)

가입할 때 닉네임을 정한다(이메일 가입은 직접 입력, 소셜 가입은 소셜 이름을 정리해 미리 채움). 닉네임은 2~10자의 한글·영문·숫자이고, 대소문자를 무시한 중복·금칙어·예약어가 거부된다. 거부 이유는 알려주되 어떤 금칙어에 걸렸는지는 알려주지 않는다.

**Why this priority**: 가입 필수 입력이며 C-AUTH-2 공통 완료 기준에 닉네임 규칙이 들어 있다.

**Independent Test**: 형식 위반·자음/모음만·숫자만·대소문자 중복·금칙어 변형·예약어 포함 닉네임 각각으로 가입·수정을 시도해 지정된 오류 코드로 거부되는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 닉네임 입력, **When** `ㅋㅋ`, `김 민서`, `kim!`, 이모지, `12345`, 1자 또는 11자 닉네임을 내면, **Then** 각각 형식 오류(`NICKNAME_INVALID_FORMAT`) 또는 글자 포함 오류(`NICKNAME_LETTER_REQUIRED`)로 거부된다.
2. **Given** macOS에서 복사한 분리형(NFD) `김민서`, **When** 닉네임으로 내면, **Then** 정상 닉네임 `김민서`(NFC)로 저장된다.
3. **Given** `Kim`을 쓰는 회원이 있음, **When** `kim`이나 `KIM`으로 가입하면, **Then** `NICKNAME_DUPLICATE`로 거부되고 `KIM2`는 허용된다.
4. **Given** 금칙어 목록에 있는 단어, **When** 숫자를 끼워 넣거나(`시1발`), 숫자로 글자를 바꾸거나(`sh1t`), `1`을 `l` 대신 써서 내면, **Then** `NICKNAME_BANNED_WORD`로 거부되고 메시지에 어떤 단어인지 나오지 않는다.
5. **Given** 예외 목록 단어(`시발점`), **When** 닉네임으로 내면, **Then** 허용된다.
6. **Given** 예약어를 포함한 닉네임(`관리자김`, `admin123`, `Official`, `운영팀장`), **When** 내면, **Then** `NICKNAME_RESERVED`로 거부된다.
7. **Given** 두 사람이 같은 닉네임(대소문자만 다름 포함)으로 동시에 가입·변경, **When** 둘 다 요청하면, **Then** 한 명만 성공하고 진 쪽에는 "방금 다른 분이 이 닉네임을 사용했어요"가 보인다.
8. **Given** 소셜 이름 `Kim Min-seo` / `김민서 (Minseo)` / `Christopher Columbus` / `A`, **When** 가입 마무리 화면을 열면, **Then** 닉네임이 각각 `KimMinseo` / `김민서Minseo` / `Christophe` / 빈칸("닉네임을 입력해 주세요")으로 채워진다.

### User Story 3 - 닉네임을 바꾸고 30일 동안은 다시 못 바꾼다 (Priority: P2)

회원은 자기 닉네임을 바꿀 수 있다. 바꾸면 30일 동안 다시 바꿀 수 없고, 이전 닉네임은 즉시 다른 사람이 쓸 수 있다. 닉네임이 바뀌어도 독자는 함께 표시되는 `@블로그주소`로 같은 사람임을 알 수 있다.

**Why this priority**: C-AUTH-2 기준이지만 가입보다 뒤에 쓰이며, 프로필 수정 화면(003)에서 노출된다.

**Independent Test**: 닉네임 변경 → 바로 재변경 시도(거부) → 이전 닉네임으로 다른 회원 가입(허용) → 30일 경과 후 변경(허용)을 확인한다.

**Acceptance Scenarios**:

1. **Given** 가입 후 닉네임을 한 번도 바꾸지 않은 회원, **When** 닉네임을 바꾸면, **Then** 바로 바뀐다(가입 때 정한 닉네임은 변경으로 세지 않음).
2. **Given** 닉네임을 바꾼 지 30일이 안 된 회원, **When** 다시 바꾸려 하면, **Then** 입력칸이 비활성화되어 "다음 변경 가능일"이 보이고, 서버도 너무 이른 변경(`NICKNAME_CHANGE_TOO_SOON`, 상태 충돌)으로 거부한다.
3. **Given** 회원이 `kim`에서 다른 닉네임으로 바꿈, **When** 다른 회원이 곧바로 `kim`을 쓰려 하면, **Then** 허용된다.
4. **Given** 같은 닉네임으로 다시 저장, **When** 저장하면, **Then** 아무것도 바뀌지 않고 30일 제한도 시작되지 않는다.
5. **Given** `kim` → `Kim`처럼 대소문자만 바꿈, **When** 저장하면, **Then** 변경으로 처리되어 30일 제한이 시작되며, 중복 검사에서 자기 자신은 제외된다.

### User Story 4 - 블로그 주소와 닉네임이 일관되게 보이고 찾아진다 (Priority: P2)

독자는 `/@주소`로 블로그에 들어간다. 대문자로 입력해도 소문자 주소로 이동하고, 없는 주소는 404다. 글 상세 작성자 영역·댓글·블로그 상단에는 `닉네임 @블로그주소`가 함께 표시된다.

**Why this priority**: 주소·닉네임 표시는 C-BLOG-1과 사칭 방지(N-9)의 기반이지만, 목록·상세 기능과 함께 완성된다.

**Independent Test**: `/@Kim755030` 접속 시 `/@kim755030`으로 영구 이동, 없는 주소 404, 글 상세·댓글의 표시 형식 확인.

**Acceptance Scenarios**:

1. **Given** `kim755030` 회원, **When** `/@Kim755030`으로 접속하면, **Then** `/@kim755030`으로 영구 리다이렉트(301)된다.
2. **Given** 없는 주소, **When** `/@없는주소`로 접속하면, **Then** 404다.
3. **Given** 탈퇴 후 익명 처리된 회원의 주소, **When** 다른 사람이 그 주소로 가입하려 하면, **Then** 사용할 수 없다.
4. **Given** 닉네임 `김민서`, 주소 `kim755030`, **When** 글 상세 작성자 영역·댓글·블로그 상단을 보면, **Then** `김민서 @kim755030`이 보이고, 글 카드에는 닉네임만 보인다.

---

### Edge Cases

- 이메일 앞부분에 영문·숫자가 없거나(`김민서@…`) 3자 미만(`ab@…`) → `user_` + 6자리 난수로 채운다(소셜이면 접두어 포함, 예: `go-user_483920`).
- 이메일 앞부분에 `+` → `+` 뒤는 버린다(`12345678+octocat@…` → `gi-12345678`).
- 처음·끝·연속 `_` → 연속은 하나로, 처음·끝은 제거(`_kim__min_` → `kim_min`).
- 30자를 넘는 앞부분 → 30자로 자르고 끝의 `_`도 제거.
- 예약어와 같은 주소(`admin`) → `admin_2`처럼 비어 있는 첫 번호를 붙인다. 예약어는 접두어를 뺀 본문 기준이므로 `go-admin`도 막힌다.
- 주소에 대문자 입력 → 입력 즉시 소문자로 바뀌어 보인다. 한글 자판 상태여도 영문으로 입력된다.
- 사용자가 주소에 `-` 입력 → 입력할 수 없다(접두어 전용).
- 접두어와 가입 수단이 맞지 않음(이메일 가입인데 `go-`) → 가입 시 거부.
- 주소 중복 확인을 같은 IP에서 1분에 30번 넘게 요청 → 제한된다. 닉네임 중복 확인도 같다.
- 화면 확인에서 "사용 가능"이었지만 가입 버튼을 누를 때 이미 쓰임 → 서버가 다시 검사해 거부하고 대안을 제안한다.
- 공백·특수문자로 금칙어를 우회(`시 발`, `시.발`)하거나 자음·모음 우회(`ㅅㅂ`) → 형식 규칙에서 이미 거부된다.
- `f4ck`처럼 숫자→영문 치환 결과(`fack`)가 원래 금칙어와 다른 경우 → 변형 표기(`fack`)가 목록에 있어야 잡힌다.
- 탈퇴 유예 30일 동안 닉네임·블로그 주소는 묶여 다른 사람이 쓸 수 없다. 익명 처리 후 닉네임은 해제되고 블로그 주소는 영구 보존된다.
- 탈퇴한 사람은 닉네임 대신 "탈퇴한 사용자"로 표시된다.

## Requirements *(mandatory)*

### Functional Requirements

**블로그 주소 형식**

- **FR-001**: System MUST 블로그 주소를 `[접두어-]본문` 형식으로 제한해야 한다. 접두어는 없음(이메일 가입)·`go-`(Google)·`gi-`(GitHub)뿐이고, 본문은 영문 소문자·숫자·`_`로 된 3~36자이며 처음과 끝은 영문 소문자나 숫자여야 한다(전체 최대 39자). (C-BLOG-1)
- **FR-002**: System MUST 블로그 주소를 전부 소문자로 관리하고, `-`는 소셜 접두어에만 쓰게 해야 한다. 이메일에서 만든 주소에는 대문자와 `-`가 없어야 한다.
- **FR-003**: System MUST 접두어가 가입 수단과 일치하는지(이메일 가입은 접두어 없음, Google `go-`, GitHub `gi-`) 가입 시 검사해야 한다.
- **FR-004**: System MUST 블로그 주소 예약어 목록(admin, administrator, root, system, official, support, help, about, terms, privacy, api, login, logout, signup, settings, me, write, search, tag, tags, notifications, manage, static, assets, images, mail, www, blog, user, users, null, undefined, devlog, teamblog 및 확정될 서비스 이름)을 설정으로 관리하고, 접두어를 뺀 본문 기준으로 거부해야 한다.
- **FR-005**: System MUST 블로그 주소에도 닉네임과 같은 금칙어 필터(FR-016)를 적용해야 한다.

**블로그 주소 생성·확정**

- **FR-006**: System MUST 가입 시 블로그 주소를 이메일로 미리 채워야 한다: `@` 앞부분 → `+` 뒤 버림 → 소문자 → `.`·`-`를 `_`로 → 허용 외 문자 제거 → 연속 `_` 하나로·처음/끝 `_` 제거 → 30자로 자름(끝 `_` 제거) → 3자 미만이면 `user_` + 6자리 난수 → 수단 접두어 부착 → 예약어이거나 이미 있으면 `_2`, `_3` … 중 비어 있는 첫 번호 부착.
- **FR-007**: System MUST 이메일 입력 중 주소를 자동으로 채우되, 사용자가 주소 칸을 직접 고친 뒤에는 자동으로 바꾸지 않아야 한다. 소셜 가입의 접두어는 고정 글자로 보여주고 고칠 수 없게 해야 한다.
- **FR-008**: System MUST 주소 입력 시 대문자를 소문자로 바꿔 보여주고, `-`는 입력할 수 없게 해야 한다.
- **FR-009**: System MUST 입력이 0.5초 멈추면 주소 사용 가능 여부(사용 가능 여부, 이유, 대안 제안)를 알려줘야 하며, 같은 IP에서 1분에 30번으로 제한해야 한다. 이 확인은 주소의 사용 여부만 알려준다.
- **FR-010**: System MUST 가입 요청을 받을 때 주소를 서버에서 다시 검사해야 하며, 같은 주소로 동시에 가입해도 한 명만 그 주소를 가져야 한다. 진 쪽에는 대안 주소를 제안해야 한다. (C-AUTH-2)
- **FR-011**: System MUST 블로그 주소를 가입할 때 한 번만 정할 수 있게 하고, 가입 후에는 어떤 경로로도 바꿀 수 없어야 한다. 프로필 화면에서는 읽기 전용으로 보여준다. (C-AUTH-2)
- **FR-012**: System MUST 대문자가 섞인 주소로 접속하면 소문자 주소로 영구 리다이렉트(301)하고, 없는 주소는 404를 줘야 한다. (C-BLOG-1)
- **FR-013**: System MUST 탈퇴한 계정의 블로그 주소를 영구 보존하고 다른 사람이 다시 쓸 수 없게 해야 한다. (13 D-9)

**닉네임 형식·검사**

- **FR-014**: System MUST 닉네임을 검사 전에 앞뒤 공백 제거와 유니코드 NFC 정규화를 하고, 정규화한 값을 저장해야 한다. (C-AUTH-2)
- **FR-015**: System MUST 닉네임을 완성형 한글(`가`~`힣`)·영문 대소문자·숫자로 된 2~10자(글자 수 기준)로 제한하고, 한글 또는 영문을 1자 이상 포함하게 해야 한다. 자음·모음만, 공백, 특수문자, 이모지, 숫자만은 거부한다. (C-AUTH-2)
- **FR-016**: System MUST 금칙어 필터를 적용해야 한다: 입력을 소문자로 바꾼 뒤 4가지 변형(그대로 / 숫자 제거 / 숫자→영문 치환 0→o·1→i·3→e·4→a·5→s·7→t / 1→l) 중 하나라도 금칙어를 포함하면 거부하고, 각 변형에서 예외 단어를 먼저 지운다. 금칙어·예외 목록은 팀이 검토한 설정 목록으로 관리한다. (C-AUTH-2)
- **FR-017**: System MUST 예약어(관리자, 운영자, 운영진, 운영팀, 고객센터, 공식, 매니저, 스태프, admin, administrator, official, staff, manager, system, root 및 확정될 서비스 이름)를 대소문자 무시·금칙어와 같은 4가지 변형으로 검사해 포함만 돼도 거부해야 한다.
- **FR-018**: System MUST 대소문자를 무시해 닉네임 중복을 거부하되 화면에는 입력한 대로 보여줘야 하며, 동시에 같은 닉네임을 요청해도 한 명만 성공해야 한다. (C-AUTH-2)
- **FR-019**: System MUST 검사를 정리 → 형식 → 글자 포함 → 예약어 → 금칙어 → 중복 순서로 하고, 단계별 오류 코드와 문구(`NICKNAME_INVALID_FORMAT`, `NICKNAME_LETTER_REQUIRED`, `NICKNAME_RESERVED`, `NICKNAME_BANNED_WORD`, `NICKNAME_DUPLICATE`)를 돌려줘야 한다. 금칙어 거부 메시지는 어떤 단어에 걸렸는지 알려주지 않는다.
- **FR-020**: System MUST 이메일 가입·소셜 가입·프로필 수정이 같은 닉네임 정책 하나를 쓰고, 서버가 요청마다 다시 검사해야 한다.
- **FR-021**: System MUST 입력이 0.5초 멈추면 닉네임 사용 가능 여부와 이유 코드를 알려줘야 하며, 같은 IP에서 1분에 30번으로 제한해야 한다.
- **FR-022**: System MUST 소셜 가입 시 소셜 이름에서 허용되지 않는 문자를 지우고 10자로 잘라 닉네임을 미리 채우고, 그 값이 검사를 통과하지 못하면 빈칸으로 두고 "닉네임을 입력해 주세요"를 보여줘야 한다. 이메일 가입은 미리 채우지 않는다.

**닉네임 변경**

- **FR-023**: System MUST 닉네임 변경을 본인만 할 수 있게 하고, 바꾼 뒤 30일 동안 다시 바꿀 수 없게 해야 한다(그 전에는 입력칸 비활성화 + 다음 변경 가능일 표시, 서버는 `NICKNAME_CHANGE_TOO_SOON` 상태 충돌로 거부). (C-AUTH-2)
- **FR-024**: System MUST 가입 때 정한 닉네임은 변경으로 세지 않아야 하고, 같은 닉네임으로 다시 저장하면 아무것도 바꾸지 않고 30일 제한도 시작하지 않아야 한다. 대소문자만 바꾸는 것은 변경으로 보며, 이때 중복 검사에서 자기 자신은 제외한다.
- **FR-025**: System MUST 바꾼 이전 닉네임을 즉시 해제해 다른 사람이 쓸 수 있게 해야 한다.
- **FR-026**: System MUST 탈퇴 유예 30일 동안은 탈퇴자의 닉네임을 묶어 두고, 익명 처리할 때 해제해야 한다. (13 D-8)

**표시**

- **FR-027**: System MUST 글 상세 작성자 영역, 댓글, 블로그 페이지 상단에 `닉네임 @블로그주소`를 함께 표시하고, 글 카드에는 닉네임만 표시해야 한다. 탈퇴한 사람은 "탈퇴한 사용자"로 표시한다.

### Key Entities *(include if feature involves data)*

- **회원(Member)**: 블로그 주소(유일, 가입 후 불변, 탈퇴 후에도 영구 보존), 닉네임(대소문자 무시 유일, 익명 처리된 탈퇴 회원만 비어 있음), 닉네임 마지막 변경 시각(가입 시에는 비어 있음)을 가진다.
- **블로그 주소 예약어 목록**: 운영자·서비스로 오해받을 수 있는 주소 본문 목록. 설정으로 관리.
- **닉네임 예약어 목록**: 포함만 돼도 거부되는 단어 목록. 설정으로 관리.
- **금칙어 목록·예외 목록**: 팀이 검토한 비속어 목록(흔한 변형 표기 포함)과 금칙어를 포함하지만 정상인 단어 목록. 닉네임·블로그 주소·소개(003)가 함께 쓴다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 08 §3의 12개 예시(이메일·Google·GitHub, 중복·예약어·3자 미만·한글 이메일·`+` 포함 등)가 모두 문서와 똑같은 주소로 미리 채워진다.
- **SC-002**: 같은 이메일 앞부분으로 이메일·Google·GitHub 가입을 해도 주소가 겹치는 경우가 0건이다.
- **SC-003**: 같은 주소 또는 같은 닉네임(대소문자만 다름 포함)으로 동시 20건 가입해도 성공은 정확히 1건이다.
- **SC-004**: 가입 후 블로그 주소를 바꾸는 모든 경로의 시도가 100% 실패하고, 대문자 주소 접속은 100% 소문자 주소로 이동한다.
- **SC-005**: 09 §2~§8의 닉네임 예시(형식 위반·NFD 한글·대소문자 중복·금칙어 변형·예외 단어·예약어·소셜 이름 미리 채우기)가 모두 문서의 결과와 같다.
- **SC-006**: 어떤 거부 메시지에도 걸린 금칙어 자체가 나타나지 않는다.
- **SC-007**: 닉네임을 바꾼 회원은 30일이 지나기 전까지 재변경 성공 0건이다.
- **SC-008**: 사용 가능 여부 확인 결과가 입력을 멈춘 뒤 1초 안에 보인다.

## Assumptions

- Tier A(공통 필수): C-AUTH-2(주소 변경 불가·닉네임 규칙), C-BLOG-1(`/@주소`). 결정 기록 2026-10-02의 "블로그 주소 형식", "블로그 주소 수정", "닉네임 형식", "닉네임 중복·필터", "닉네임 변경" 결정을 따른다.
- 공통은 회원 = 블로그(01 Q5)다. 블로그를 별도로 두는 것은 나민서 개인 확장이다.
- 이전 닉네임을 일정 기간 묶어 두는 기능은 개인 확장이다(N-8).
- 예약어·금칙어·예외 목록, 30일 변경 제한, 중복 확인 요청 제한은 설정값이다. 서비스 이름이 확정되면 두 예약어 목록에 추가한다.
- 예약어는 운영자 계정에만 허용하는 것, 금칙어 목록을 운영자 화면에서 관리하는 것은 Tier C다. 댓글·글 본문 금칙어 필터는 공통 범위 밖이다.
- 새 소셜 로그인이 추가되면 접두어(예: `na-`, `ka-`)를 늘리는 방식으로 확장한다(이번 범위 아님).
- 가입 흐름 자체(약관·인증 등)는 001, 프로필 화면에서의 닉네임 수정 저장은 003에서 다룬다. 탈퇴 처리 자체는 회원 탈퇴 기능(13·44)의 범위다.
