**Created**: 2026-10-07

**Status**: Draft

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 남의 글에 좋아요 누르고 취소하기 (Priority: P1)

이메일 인증을 마친 회원은 읽을 수 있는 남의 발행 글에 좋아요를 누르고, 다시 눌러 취소한다. 누르는 즉시 ♡/♥와 숫자가 바뀌고, 최종 숫자는 서버 결과로 맞춰진다. 한 사람은 한 글에 좋아요를 한 번만 남길 수 있다.

**Why this priority**: C-LIKE-1(Tier B)의 핵심. 좋아요 수는 목록 카드와 트렌딩 점수의 재료다.

**Independent Test**: 인증된 회원으로 남의 공개 글에 좋아요 → 취소를 하고, 화면 표시·좋아요 수·실제 좋아요 기록 수가 매번 일치하는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 인증된 회원과 좋아요 12개인 남의 공개 글, **When** ♡를 누르면, **Then** 즉시 ♥ 13으로 바뀌고 서버도 좋아요 상태와 13을 돌려준다.
2. **Given** 이미 좋아요한 글, **When** ♥를 누르면, **Then** 취소되어 ♡ 12가 된다.
3. **Given** 이미 좋아요한 상태, **When** "좋아요 상태로" 요청을 다시 보내면, **Then** 성공 응답이고 수는 바뀌지 않는다 (취소도 같음).
4. **Given** 서버 처리가 실패, **When** 누른 직후, **Then** 화면이 원래 상태로 되돌아가고 "좋아요를 반영하지 못했어요"가 보인다.
5. **Given** 글 상세를 처음 열 때, **When** 내가 이미 좋아요한 글이면, **Then** ♥ 상태로 보인다.

---

### User Story 2 - 누를 수 없는 사람·글은 막기 (Priority: P1)

비회원은 버튼을 볼 수 있지만 누르면 로그인 안내를 받는다. 이메일 인증 전 회원은 인증 안내를 받는다. 작성자는 자기 글에 좋아요를 누를 수 없고 버튼 대신 개수만 본다. 볼 수 없는 글에 대한 요청은 항상 404다.

**Why this priority**: 인증하지 않은 계정·자기 글 좋아요로 인기 글·트렌딩을 조작하는 것을 막는다. 존재를 드러내지 않는 404 원칙도 함께 지켜야 한다.

**Independent Test**: 비회원·인증 전 회원·작성자·회원으로 각 글 상태(공개·비공개·임시·휴지통·숨김·탈퇴 신청 작성자)에 요청을 보내 응답과 좋아요 수 변화를 확인한다.

**Acceptance Scenarios**:

1. **Given** 비회원, **When** ♡를 누르면, **Then** 서버는 401이고 화면은 "로그인하고 좋아요를 눌러 보세요 [로그인]"을 보이며, 로그인 후 원래 글로 돌아오되 좋아요가 자동으로 눌리지 않는다.
2. **Given** 이메일 인증 전 회원, **When** 좋아요를 요청하면, **Then** 403 `EMAIL_NOT_VERIFIED`와 "이메일 인증 후 누를 수 있어요"이고 수는 바뀌지 않는다.
3. **Given** 내 글, **When** 글 상세를 보면, **Then** 좋아요 버튼 없이 ♥ 개수만 보이고, 직접 요청을 보내도 400 `CANNOT_LIKE_OWN_POST`이며 수는 바뀌지 않는다.
4. **Given** 임시글·휴지통 글·남의 비공개 글·관리자 숨김 글·탈퇴 신청한 작성자의 글·없는 글, **When** 회원이 좋아요·취소를 요청하면, **Then** 모두 404이고 수는 바뀌지 않는다.
5. **Given** 이메일 인증 전 회원, **When** 볼 수 없는 글에 좋아요를 요청하면, **Then** 403 `EMAIL_NOT_VERIFIED`다 (계정 상태를 먼저 판정).

### User Story 3 - 동시·반복 요청에도 정확한 수 (Priority: P1)

더블클릭, 네트워크 재시도, 여러 탭에서 동시에 눌러도 좋아요는 1건이고, 좋아요 수는 항상 실제 좋아요 기록 수와 같다.

**Why this priority**: "동시에 여러 번 눌러도 1건"은 C-LIKE-1 공통 완료 기준이다.

**Independent Test**: 같은 사람이 좋아요 요청 20번을 동시에 보내고, 좋아요·취소를 섞어 동시에 보내고, 여러 사람이 동시에 누르는 시나리오에서 수와 실제 기록 수를 비교한다.

**Acceptance Scenarios**:

1. **Given** 같은 회원, **When** 같은 글에 좋아요 요청 20번을 동시에 보내면, **Then** 좋아요 기록은 1건이고 수도 1이다.
2. **Given** 같은 회원, **When** 좋아요 20번과 취소 20번을 동시에 섞어 보내면, **Then** 결과가 어떻든 수는 실제 기록 수와 같다.
3. **Given** 서로 다른 50명, **When** 같은 글에 동시에 좋아요를 누르면, **Then** 수는 50이다.
4. **Given** 50명이 동시에 취소하고 다른 8명이 동시에 누름, **When** 끝나면, **Then** 수는 8이다.
5. **Given** 화면에서 버튼을 빠르게 여러 번 연타, **When** 0.3초 동안 추가 입력이 없으면, **Then** 마지막 상태 하나만 서버에 보낸다.

---

### User Story 4 - 남용 방지와 수 보정 (Priority: P2)

한 사용자가 짧은 시간에 너무 많이 누르면 잠시 막는다. 실제로 상태가 바뀐 경우에만 "좋아요됨/취소됨" 사건을 남겨 알림·트렌딩이 흔들리지 않게 한다. 매일 한 번 좋아요 수를 실제 기록 수와 대조해 어긋난 것을 고친다.

**Why this priority**: 정확성·남용 방지의 2차 안전장치. 기본 흐름(P1)이 먼저다.

**Independent Test**: 1분에 61번 요청해 429를 확인하고, 이미 그 상태인 요청에서 사건이 생기지 않는지, 일부러 수를 틀리게 한 뒤 보정 작업이 고치는지 확인한다.

**Acceptance Scenarios**:

1. **Given** 한 사용자가 1분 안에 좋아요·취소를 합쳐 60번 요청, **When** 61번째를 보내면, **Then** 429와 다시 시도할 시간을 받는다.
2. **Given** 이미 좋아요한 글, **When** 다시 좋아요 요청을 보내면, **Then** "좋아요됨" 사건이 생기지 않는다.
3. **Given** 좋아요하지 않은 글에서 좋아요가 실제로 생김, **When** 처리가 확정되면, **Then** 글·누른 사람·작성자·시각을 담은 "좋아요됨" 사건이 한 번 생긴다 (취소도 실제로 지워졌을 때만 "취소됨").
4. **Given** 정상 상태, **When** 매일 보정 작업이 돌면, **Then** 고친 글이 0건이다.
5. **Given** 어떤 글의 수가 실제 기록 수와 다름, **When** 보정 작업이 돌면, **Then** 실제 기록 수로 고쳐지고, 고친 건수가 0이 아니면 경고가 남는다.

---

### User Story 5 - 좋아요 수 표시 (Priority: P3)

목록 카드와 글 상세에서 좋아요 수를 읽기 쉽게 보여준다. 화면 낭독기와 키보드로도 쓸 수 있다.

**Why this priority**: 표시 형식·접근성. 기능 동작과 독립적으로 검증 가능하다.

**Independent Test**: 좋아요 수가 0, 1,234, 12,345인 글의 카드·상세 표시와 버튼의 접근성 속성을 확인한다.

**Acceptance Scenarios**:

1. **Given** 좋아요 1,234개, **When** 보면, **Then** `1,234`로 보인다.
2. **Given** 좋아요 12,345개, **When** 보면, **Then** 소수 첫째 자리에서 내림한 `1.2만`으로 보인다.
3. **Given** 목록 카드, **When** 보면, **Then** 좋아요 수만 보이고 내가 눌렀는지는 표시되지 않는다.
4. **Given** 화면 낭독기 사용자, **When** 버튼에 초점을 두면, **Then** 눌림 상태와 "좋아요 (13)" / "좋아요 취소 (13)" 이름이 읽히고, Enter·Space로 누를 수 있으며 ♡/♥ 모양이 달라 색 없이도 구분된다.

---

### Edge Cases

- 글이 비공개·친구 공개로 바뀌거나 관리자가 숨기면 좋아요는 지우지 않고, 글을 볼 수 없는 사람에게는 수와 버튼이 함께 보이지 않는다. 다시 공개·숨김 해제하면 그대로 돌아온다.
- 글이 휴지통에 가면 좋아요는 보존되고 복구하면 그대로다. 완전 삭제되면 함께 삭제된다.
- 누른 사람이 탈퇴 신청(유예 중)이면 좋아요와 수는 그대로다. 탈퇴 30일 뒤 익명 처리 때 수를 줄이고 기록을 지운다 (처리 주체는 spec 023).
- 글을 수정·다시 발행해도 좋아요는 그대로다.
- 응답의 좋아요 수는 그 사이 다른 사람이 누른 것까지 반영한 최신 값이다.
- 상태 지정 방식이라 연타 요청의 순서가 섞여 도착해도 마지막으로 보낸 상태가 결과가 된다.
- 같은 사람이 같은 글에 눌렀다 취소하고 다시 눌러도 작성자 알림은 한 번만 간다 (중복 판정은 알림 쪽 책임, spec 017).
- 관리자도 남의 글에는 회원과 같이 좋아요를 누를 수 있다.

## Requirements *(mandatory)*

### Functional Requirements

**누를 수 있는 사람과 글**

- **FR-001**: 좋아요 누르기·취소는 이메일 인증을 마친 로그인 회원(관리자 포함)만 할 수 있어야 한다(MUST). 비회원은 401, 인증 전 회원은 403 `EMAIL_NOT_VERIFIED`여야 한다(MUST). (C-LIKE-1)
- **FR-002**: 좋아요 대상은 요청자가 읽을 수 있는 발행 글이어야 한다(MUST). 임시글·휴지통 글·볼 수 없는 공개 범위의 글·관리자 숨김 글·탈퇴 신청한 작성자의 글·없는 글은 모두 같은 404여야 한다(MUST).
- **FR-003**: 작성자는 자기 글에 좋아요를 누를 수 없어야 하며, 요청 시 400 `CANNOT_LIKE_OWN_POST`여야 한다(MUST).
- **FR-004**: 판정은 공통 권한 순서(spec 012)를 따라 ① 로그인 → ② 계정 상태(이메일 인증) → ③ 글을 볼 수 있나 → ④ 자기 글 여부 → ⑤ 요청 횟수 → 처리 순서로 해야 한다(MUST).
- **FR-005**: 거부된 요청은 좋아요 수와 기록을 바꾸지 않아야 한다(MUST).

**동작과 정확성**

- **FR-006**: 좋아요는 뒤집기(토글)가 아니라 "좋아요 상태로" / "취소 상태로" 상태를 지정하는 방식이어야 하며, 이미 그 상태여도 성공으로 응답하고 수는 바꾸지 않아야 한다(MUST). 같은 요청을 여러 번 보내도 한 번 보낸 것과 결과가 같아야 한다(MUST).
- **FR-007**: 한 회원은 한 글에 좋아요 기록을 최대 1건만 가질 수 있어야 하며, 동시에 여러 번 요청해도 1건이어야 한다(MUST). (C-LIKE-1)
- **FR-008**: 좋아요 수는 실제로 기록이 생겼을 때만 1 늘고 실제로 지워졌을 때만 1 줄어야 하며, 기록 변경과 수 변경은 함께 되거나 함께 안 되어야 한다(MUST).
- **FR-009**: 성공 응답은 현재 좋아요 상태와 그 시점의 최신 좋아요 수를 돌려줘야 한다(MUST).
- **FR-010**: 시스템은 매일 한 번 좋아요 수를 실제 기록 수와 대조해 다른 글을 고치고, 고친 건수가 0이 아니면 경고를 남겨야 한다(MUST). 여러 서버가 있어도 한 곳에서만 실행되어야 한다(MUST).

**남용 방지와 사건**

- **FR-011**: 좋아요·취소 요청은 합산해 사용자당 1분에 60번으로 제한하고, 넘으면 429와 다시 시도할 시간을 알려줘야 한다(MUST).
- **FR-012**: 실제로 기록이 생겼을 때만 "좋아요됨" 사건(글, 누른 사람, 글 작성자, 시각)을, 실제로 지워졌을 때만 "취소됨" 사건(글, 누른 사람)을 처리가 확정된 뒤에 남겨야 한다(MUST). 이미 그 상태였던 요청은 사건을 남기지 않아야 한다(MUST).

**화면**

- **FR-013**: 비회원과 인증 전 회원에게도 남의 글의 좋아요 버튼은 보여야 하며(MUST), 비회원이 누르면 "로그인하고 좋아요를 눌러 보세요 [로그인]"을 보이고 로그인 후 원래 글로 돌아오되 자동으로 누르지 않아야 한다(MUST). 인증 전 회원이 누르면 인증 안내를 보여야 한다(MUST).
- **FR-014**: 내 글에는 버튼 대신 좋아요 수만 보여야 한다(MUST).
- **FR-015**: 누르면 서버 응답을 기다리지 않고 ♡/♥와 숫자를 바로 바꾸고, 실패하면 되돌리며 "좋아요를 반영하지 못했어요"를 보여야 한다(MUST). 최종 숫자는 서버 응답으로 맞춰야 한다(MUST).
- **FR-016**: 연타는 0.3초 동안 추가 입력이 없을 때 마지막 상태 하나만 보내야 한다(MUST).
- **FR-017**: 좋아요 수는 0~9,999는 쉼표 형식(`1,234`), 1만 이상은 소수 첫째 자리까지 내림한 `1.2만` 형식으로 보여야 한다(MUST).
- **FR-018**: 글 상세는 처음 열 때 내가 좋아요했는지를 함께 보여야 한다(MUST). 목록 카드는 좋아요 수만 보이고 내가 눌렀는지는 보이지 않아야 한다(MUST).
- **FR-019**: 버튼은 눌림 상태와 "좋아요 (N)" / "좋아요 취소 (N)" 이름을 보조 기술에 알리고, 키보드(Enter·Space)로 누를 수 있으며, 색이 아닌 모양(♡/♥)으로도 구분되어야 한다(MUST).
- **FR-020**: 스크립트가 없는 화면에서도 같은 규칙으로 좋아요·취소를 하고 글 상세로 돌아와야 한다(MUST).

**다른 상태와의 관계**

- **FR-021**: 글이 비공개·친구 공개로 바뀌거나 관리자가 숨기거나 휴지통으로 가면 좋아요 기록과 수를 지우지 않아야 하며, 글을 볼 수 없는 사람에게는 수와 버튼이 보이지 않아야 한다(MUST). 원래대로 돌아오면 그대로 보여야 한다(MUST).
- **FR-022**: 글이 완전 삭제되면 좋아요 기록도 함께 삭제되어야 한다(MUST). 글 수정·다시 발행은 좋아요에 영향을 주지 않아야 한다(MUST).
- **FR-023**: 누른 사람이 탈퇴 신청(유예 중)이어도 좋아요와 수는 유지되어야 한다(MUST).

### Key Entities

- **좋아요(Post Like)**: 한 회원이 한 글에 남긴 좋아요. 글과 회원의 쌍이 고유하며 누른 시각을 가진다(나중에 "최근 반응" 기준 점수에 쓸 수 있게 보존).
- **글의 좋아요 수**: 글마다 미리 계산해 둔 좋아요 수. 항상 실제 좋아요 기록 수와 같아야 하며, 목록 카드·글 상세·트렌딩이 쓴다.
- **좋아요 사건**: "좋아요됨"(글, 누른 사람, 글 작성자, 시각)과 "취소됨"(글, 누른 사람). 실제 상태 변화가 확정될 때만 생기며 알림·트렌딩이 구독한다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 같은 사람이 같은 글에 동시에 20번 요청해도 좋아요는 1건이다.
- **SC-002**: 좋아요·취소를 동시에 섞어 보내는 모든 테스트(같은 사람 20+20번 3회, 50명 동시, 50명 취소 + 8명 누름)에서 좋아요 수가 실제 기록 수와 100% 일치한다.
- **SC-003**: 같은 상태 지정 요청을 여러 번 보낸 결과가 한 번 보낸 결과와 다른 경우가 0건이다.
- **SC-004**: 비회원(401)·인증 전 회원(403)·자기 글(400)·볼 수 없는 글(404) 요청에서 좋아요 수가 바뀌는 경우가 0건이다.
- **SC-005**: 이미 그 상태인 요청에서 좋아요 사건이 생기는 경우가 0건이고, 실제로 바뀐 요청은 사건이 정확히 1번 생긴다.
- **SC-006**: 1분에 61번째 요청은 100% 거부(429)된다.
- **SC-007**: 정상 운영 중 매일 보정 작업이 고친 글이 0건이다.
- **SC-008**: 사용자가 누른 뒤 화면의 ♡/♥ 변화가 서버 응답을 기다리지 않고 즉시 보인다.

## Assumptions

- Tier: 글 좋아요(C-LIKE-1)는 **Tier B 공통 권장**이며 공통 범위에 포함하기로 했다(01 Q7 제안). 01 C-LIKE-1 완료 기준은 30 문서 §9로 바꾸기로 했다.
- **원문 간 충돌 해소**: 30 문서는 자기 글 좋아요를 403 `CANNOT_LIKE_OWN_POST`로, 판정 순서를 "로그인 → 글을 볼 수 있나 → 이메일 인증 → 자기 글"로 적었다. 권한 매트릭스(42 문서, 2026-10-06 수정)는 모든 기능의 기준이며 "403은 계정 상태에만"(P-3·P-9)과 "계정 상태 → 볼 수 있나" 순서를 결정했으므로, 이 명세는 **자기 글 400**, **인증 전 회원은 볼 수 없는 글에도 403**으로 42를 따른다. 2026-10-07 결정: 자기 글 좋아요는 400 `CANNOT_LIKE_OWN_POST`로 확정한다. 409는 다시 시도하면 해결될 수 있는 상태 충돌에만 쓰므로 쓰지 않는다. 30 문서는 이 기준으로 고쳐 달라고 김민서 담당에게 요청한다.
- 결정 사항(30 결정 기록 2026-10-05): 자기 글 불가, 비회원·이메일 인증 전 불가, 상태 지정 방식, 실제 변경 시에만 증감 + 매일 보정, 즉시 반영·연타는 마지막 상태만, 1만 이상 `1.2만`, 카드는 수만, 1분 60번, 실제 변경 시에만 사건.
- 요청 제한(1분 60번), 연타 대기(0.3초), 보정 주기(매일)는 설정값으로 둔다. 글이 많아지면 보정 대상을 최근 7일 안에 바뀐 글로 줄일 수 있다.
- 좋아요 누른 사람 목록, 내가 좋아요한 글 목록, 댓글 좋아요는 **개인 확장**이며 공통에서 제외한다.
- 좋아요 알림(같은 사람·같은 글은 1번)은 spec 017, 트렌딩 점수 사용은 spec 019, 관리자 숨김은 spec 022, 탈퇴 후 정리는 spec 023이 맡는다. 글 상세에서 버튼 위치는 spec 010에서 정한다.
