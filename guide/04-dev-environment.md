# 4. 어떤 환경에서 만들었나

## 도구
| 도구 | 쓰임 |
|---|---|
| **Claude Code** (Anthropic, Mac 데스크톱 앱) | 명세 쓰기, 코드 작성·수정, 테스트 실행, 커밋·push·PR, 배포 확인까지 대부분의 작업 |
| **Claude 프로젝트(하네스)** | 대화방 하나에 조율 역할 Claude와 스레드별 작업 Claude가 있음. 요청 하나가 스레드 하나가 되고, 스레드 Claude가 이 Mac에서 원격으로 작업. 프로젝트 메모리 파일에 결정·규칙을 적어 다음 세션이 이어받음 |
| **GitHub Spec Kit** | 기능마다 명세(spec) → 계획(plan) → 작업(tasks) → 구현 순서. 결과는 문서 저장소 `specs/` |
| Claude Code 플러그인 | superpowers(브레인스토밍·테스트 먼저·완료 전 검증 같은 작업 순서), ponytail(필요한 만큼만 만드는 규칙) |
| MCP 연결 | Crowfoot(ERD 문서·DB 발급), 내장 브라우저(로컬·운영 화면을 직접 눌러 확인) |
| 개발 환경 | macOS, JDK 21, Gradle 9.8(Kotlin DSL), Docker(Colima) |

## 사람과 AI의 역할
- **사람(강성찬)**: 무엇을 만들지 정하고(요청·디자인 참고 이미지), 팀 공통 요구사항을 맞추고, 계정·비밀값(Google·GitHub OAuth, Gmail, 서버 SSH, Crowfoot DB)을 만들고, 결과를 검토
- **Claude**: 요청을 명세로 옮기고, 애매한 부분은 기본값을 골라 명세의 결정 기록에 남기고, 구현·테스트·배포·확인. 계정 생성·비밀값 입력·되돌릴 수 없는 일은 하지 않고 사람에게 넘김

## 품질을 지키는 장치
- 기능마다 통합 테스트를 같이 씀(현재 656개). 화면 JS는 Node 자체 검사
- GitHub Actions가 PR과 배포 전에 전체 테스트
- 바뀐 화면은 Claude가 로컬 브라우저에서 넓은·좁은 화면으로 직접 눌러 확인한 뒤 배포
- 명세·결정·릴리스 노트가 남아서 "왜 이렇게 만들었는지"를 나중에 설명할 수 있음
