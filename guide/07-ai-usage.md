# 7. AI: 왜, 어디에, 얼마나

## 원칙
1. **규칙으로 되는 일에는 AI를 쓰지 않는다.** AI가 없어도 모든 기능이 돈다. 지금 운영 서버에는 Gemini 키를 넣지 않았고, 그래도 사이트는 정상이다
2. **사용자가 누를 때만 부른다.** 화면을 열 때 자동으로 부르지 않는다
3. **무료 등급 안에서.** 하루 한도·사람당 한도·결과 캐시로 호출 수를 막는다
4. **동의한 사람의 전체 공개 글만** AI에 보낸다(설정에서 철회 가능). AI는 제안만 하고 저장은 사람이 고른 것만

## 어디에 쓰나
| 기능 | AI가 하는 것 | AI 없을 때(지금 운영) | 비용 막는 장치 |
|---|---|---|---|
| 021 태그 추천 | 글을 읽고 태그 5개 제안 | Ollama(자체 서버, 작은 모델)로 넘어가고, 그것도 없으면 직접 태그를 씀 | 100자 이상 글만, 사람당 하루 20번, 전체 하루 450번, 60초 간격, 같은 글 30일·비슷한 글 7일 캐시 |
| 035 한 줄 소개(티저) | 카드에 쓸 소개 문장 제안 | 직접 쓰기 | 태그 추천과 같은 연결·같은 동의, 누를 때만 |
| 057 오늘의 미션 주제 | 하루 주제 3개 | 내장 주제 120개에서 고름 | 하루 한 번 |
| 056 태그 아이콘 | 새 태그에 어울리는 아이콘 고르기 | 규칙(키워드)으로 41개 중 고름 | 새 태그만 |
| 059 글 다듬기 | 고른 문장을 다듬기·맞춤법·짧게·쉽게 | 메뉴가 안 보임 | 사람당 하루 30번 |

연결 순서: **Gemini 무료 등급**(`gemini-flash-lite-latest`) → 한도·장애 때 **Ollama**(자체 서버의 작은 모델) → 둘 다 없으면 규칙·내장 데이터. 어떤 실패도 글쓰기·저장·발행을 막지 않는다.

## 왜 이 기술인가
- **Gemini 무료 등급**: 키만 있으면 비용 없이 시작, 가벼운 모델(flash-lite)이라 빠르고 한도가 넉넉함
- **Ollama**: 무료 한도가 끝나도 돈이 안 나가게 자체 서버에서 돌리는 대안. 다만 4GB 서버에는 무거워서 학교 서버에서는 쓰지 않음
- **규칙 기반 대안**: 태그 아이콘(키워드 규칙), 미션 주제(내장 목록)처럼 결과가 단순한 일은 AI 없이도 품질이 충분

## AI를 안 써도 되는 곳 (안 쓰는 이유)
- 맞춤법 정도는 브라우저 맞춤법 검사로도 됨 → 글 다듬기는 키가 없으면 감춤
- 태그 아이콘·미션 주제는 규칙·목록으로 충분 → AI는 있으면 쓰는 덤
- 검색·트렌딩·추천 글은 AI 없이 점수 공식(좋아요·댓글·조회수·시간)으로 계산

## 만드는 데 쓴 AI
개발은 Claude Code로 했다(→ [04-dev-environment.md](04-dev-environment.md)). 서비스 안의 AI(위 표)와는 별개로, 사용자 데이터가 개발 도구로 가지 않는다.
