# 이미지 업로드: 남은 결정

> 작성일 2026-10-04 · 작성 강성찬 · 관련 요구사항: C-IMG-1(이미지 업로드). 연관: [04 임시저장·사진](./04-draft-and-image.md) §4·§6, [10 목록](./10-post-list.md) §6, [11 프로필](./11-profile.md) §4, [12 본문 정화](./12-content-sanitize.md) §4·§6
> **이미 정해진 것은 다시 적지 않는다**: 업로드 흐름(브라우저 압축·EXIF 제거·640px 썸네일 → presign → 직접 업로드 → complete 서버 재검사), 저장 키 `images/{yyyy}/{MM}/{uuid}.{ext}`, 캐시 1년, 1분 20장, 오프라인 대기열(`local:`), 정리 배치(TEMP 24시간·연결 끊긴 지 7일), 비공개 글 사진은 주소를 알면 보임, 프로필 256×256.
> 이 문서는 남은 네 가지만 정한다: **저장소 제품, 사용자별 용량 한도, 대체글, GIF.**

## 1. 결정 사항

| # | 안건 | 결정 | 이유 |
|---|---|---|---|
| I-1 | 저장소 제품 (01 Q11, 04 §6) | **RustFS**, 이미지 버전 **`1.0.1` 고정** | MinIO와 사용법이 거의 같아(환경 변수·관리 콘솔) 자료를 찾기 쉽다. Apache-2.0, 2026년 9월 1.0 정식 출시. 04 §6-1 Presigned 검증을 통과했다(1.0.0) |
| I-2 | 사용자별 용량 | **1인 1GB + 하루 200장** (설정값) | 압축 후 사진 1장이 약 0.3~0.5MB라 2,000장 이상. 한 사람이 저장소를 채우는 것을 막는다 |
| I-3 | 대체글(alt) | **권유만 한다.** 비우면 빈 대체글(`alt=""`). **원래 파일 이름은 쓰지 않는다** | 강제하면 글쓰기가 번거롭다. 파일 이름(`IMG_2931`, `김민서_신분증`)은 도움이 안 되거나 개인 정보다 |
| I-4 | GIF | **변환 없이 그대로 올리고, 본문에서는 첫 장면 + ▶로 보여주다가 누르면 재생** | 데이터를 아끼고, 계속 움직이는 화면을 줄인다(접근성). 움직임은 그대로 살린다 |

## 2. 저장소: RustFS (I-1)

### 2-1. 선택과 위험 관리

| 항목 | 내용 |
|---|---|
| 제품 | RustFS (`rustfs/rustfs:1.0.1`, 2026-10-03 배포) |
| 04 문서와의 관계 | 04 §6은 SeaweedFS를 **제안**했고 Q11은 팀 확정 대기였다. 이 문서는 RustFS를 제안한다 → **화요일에 팀 확정** (PR 설명에 적음) |
| 위험 | 1.0이 나온 지 한 달 정도 된 젊은 프로젝트다 |
| 대응 1 | **버전 고정.** `latest`를 쓰지 않는다. 올릴 때는 아래 §2-3 검증을 다시 한다 |
| 대응 2 | 앱은 S3 API만 쓴다 (04 §4-1). 문제가 생기면 **설정(endpoint, 키)만 바꿔** SeaweedFS·관리형 S3로 옮긴다 |
| 대응 3 | 팀 검증은 1.0.0으로 했다. **1.0.1에서 §2-3을 다시 통과**한 뒤 확정한다 |

### 2-2. 설정

```yaml
# compose.yaml (개발용 예시 — 환경 변수 이름은 RustFS 1.0.1 문서로 다시 확인)
services:
  storage:
    image: rustfs/rustfs:1.0.1
    ports: ["9000:9000"]            # S3 API만 연다. 관리 콘솔 포트는 외부에 열지 않는다
    environment:
      RUSTFS_ACCESS_KEY: ${STORAGE_ACCESS_KEY}
      RUSTFS_SECRET_KEY: ${STORAGE_SECRET_KEY}
    volumes:
      - storage-data:/data
volumes:
  storage-data:
```

| 항목 | 규칙 | 이유 |
|---|---|---|
| 키 | 기본 계정을 쓰지 않는다. 앱 전용 키는 환경 변수로만 (02 §5 비밀값) | |
| 버킷 읽기 | **파일 하나 읽기(`GetObject`)만 익명 허용**, `images/*` 경로만 | 04 결정 2(주소를 알면 볼 수 있음) |
| 버킷 목록 | **익명 목록 조회(`ListBucket`) 금지** | 목록이 열리면 비공개 글의 사진 주소까지 모두 드러난다. "주소는 UUID라 추측할 수 없다"(04 결정 2)는 목록이 닫혀 있어야 성립한다 |
| 업로드 | Presigned PUT만 (익명 쓰기 금지) | |
| CORS | 우리 사이트 출처(origin)에서 `PUT`만, 헤더는 `Content-Type` | 브라우저 직접 업로드 |
| 관리 콘솔 | 외부에 열지 않는다 | |
| 백업 | 데이터 볼륨 백업 주기는 배포 담당이 정한다 (공통 범위 밖) | |

## 3. 사용자별 용량 (I-2)

| 항목 | 규칙 |
|---|---|
| 한도 | **1GB** (`blog.image.quota-bytes`), **하루 200장** (`blog.image.daily-limit`, 한국 시간 0시 기준) |
| 세는 것 | 그 사람이 올린 **모든 이미지 행**의 원본 + 썸네일 크기 (`TEMP`, 연결됨, 연결이 끊겨 정리를 기다리는 것 모두). 프로필 이미지 포함 |
| 돌아오는 시점 | 정리 배치가 파일을 **실제로 지울 때** (TEMP 24시간, 연결 끊긴 지 7일, 04 §4-4). 글을 지워도 바로 돌아오지 않는다 |
| 검사 시점 | `POST /api/images/presign`에서 "지금 사용량 + 이번에 올릴 크기(원본 + 썸네일)" |
| 넘으면 | `409 STORAGE_QUOTA_EXCEEDED` / 하루 200장을 넘으면 `429 DAILY_UPLOAD_LIMIT` |
| 동시 요청 | presign 트랜잭션에서 **회원 행을 잠그고**(`SELECT … FROM member WHERE id = :me FOR UPDATE`) 합계를 구한 뒤 TEMP 행을 신고한 크기로 넣는다. 그래서 여러 장을 동시에 요청해도 한도를 넘지 않는다 |
| 실제 크기 | complete에서 실제 크기를 기록한다. 신고한 크기보다 크면 04 §4-1 ⑤ 규칙대로 거부·삭제 |
| 하루 장수 | Redis `img:daily:{memberId}:{yyyyMMdd}` `INCR`, TTL 2일. presign에서 센다 (실패한 업로드도 1장으로 센다 — 반복 요청 방지) |

```sql
-- presign: 지금 사용량 (ix_image_uploader 사용)
SELECT coalesce(sum(size_bytes + coalesce(thumb_size_bytes, 0)), 0)
FROM image WHERE uploader_id = :me;
```

## 4. 대체글 (I-3)

| 항목 | 규칙 |
|---|---|
| 넣을 때 | 에디터가 `![](주소)`로 넣는다. **대체글 자리를 비워 둔다.** 원래 파일 이름을 넣지 않는다 |
| 발행 설정 창 | 대체글이 빈 사진이 있으면 안내: "대체글이 없는 사진이 2장 있어요 [대체글 넣기]" → 사진마다 작은 미리보기 + 입력칸. 입력하면 본문 Markdown의 `![…]`에 반영 |
| 강제 여부 | **발행을 막지 않는다** |
| 빈 대체글 | `alt=""`로 그린다 → 화면 낭독기가 꾸밈 이미지로 보고 건너뛴다 (`alt` 속성을 아예 빼면 낭독기가 파일 주소를 읽는다) |
| 길이 | 권장 125자 이내 (넘어도 거부하지 않음, 안내만) |
| 글 카드 썸네일 | `alt` = 글 제목 (10 §2 그대로) |
| 프로필 이미지 | 바로 옆에 닉네임이 있으므로 `alt=""` |
| 안내 문구 | 입력칸 아래 "사진을 볼 수 없는 분께 읽어 줄 설명이에요. 예: 'fetch join 전후 쿼리 수 비교 그래프'" |

`original_name`은 저장 키에 쓰지 않는 것(04 §4-2)에 더해 **화면 어디에도 보여주지 않는다.**

## 5. GIF (I-4)

### 5-1. 업로드

| 항목 | 규칙 |
|---|---|
| 변환 | 원본은 **압축·크기 조정·변환 없이 그대로** (04 ② 그대로). 썸네일은 첫 장면 640px WebP (10 §6 그대로) |
| 크기 | 10MB 이하 (공통) |
| 해상도 | **가로·세로 각 1920px 이하.** 브라우저에서 움직이는 GIF를 줄일 수 없으므로, 넘으면 고르는 순간 "GIF는 가로·세로 1920px까지 올릴 수 있어요" |
| 프레임 수 | **300장 이하** |
| 서버 검사 (complete) | 위 해상도·프레임 수를 다시 확인한다. 파일 전체를 디코딩하지 않고 머리말과 프레임 구분만 읽는다(`ImageReader.getNumImages`). 넘으면 거부·삭제 |
| 움직이는 다른 형식 | 움직이는 WebP·PNG(APNG)는 브라우저 압축 과정(캔버스)에서 **첫 장면만 남는다.** 움직임을 살리는 형식은 GIF뿐이다 (업로드 화면에 안내) |
| 메타데이터 | GIF에는 사진의 촬영 위치(EXIF)가 들어가지 않는다. 그 밖의 메타데이터(XMP)는 서버가 파일을 고치지 않으므로 남을 수 있다 (알려진 한계) |

### 5-2. 본문에서 보여주기

```
처음:  [첫 장면 정지 이미지]  ▶ GIF          ← 썸네일(640px)을 원래 크기로 표시
누름:  [원본 GIF가 움직임]
JS 없음: 정지 이미지를 누르면 원본 GIF가 새 탭에서 열림
```

12 §2 ② AST 변환에 **GIF 규칙 하나를 추가**한다 (12 §4 허용 목록은 바꾸지 않음).

```html
<!-- 입력: ![로딩 화면](https://cdn…/images/2026/10/7f3e….gif) -->
<a href="https://cdn…/images/2026/10/7f3e….gif" title="움직이는 이미지 재생"
   target="_blank" rel="noopener noreferrer nofollow ugc">
  <img src="https://cdn…/images/2026/10/7f3e…_thumb.webp" alt="로딩 화면" loading="lazy" decoding="async">
</a>
```

| 항목 | 규칙 |
|---|---|
| 판별 | 우리 저장소 주소이고 `.gif`로 끝나는 이미지. 썸네일 주소는 저장 키 규칙(`{uuid}_thumb.webp`, 10 §6)으로 만든다 |
| 재생 | 우리 서버의 `/js/gif-play.js` (CSP `script-src 'self'`를 지킴): `a[href$=".gif"] > img`를 찾아 ▶ 표시를 붙이고, 누르면 기본 동작(새 탭)을 막고 `img.src`를 원본 GIF로 바꾼다. 다시 누르면 정지 장면으로 |
| ▶ 표시 | CSS `a[href$=".gif"]::after` (class를 쓰지 않음 → 정화 허용 목록을 바꿀 필요가 없다) |
| 접근성 | 링크 이름은 대체글, 대체글이 비었으면 `title`("움직이는 이미지 재생"). 키보드 Enter로 재생 |
| 글 카드 썸네일 | 첫 장면 (10 §6 그대로) |
| 링크 미리보기(OG) | 원본 GIF (10 §6 "OG는 원본" 그대로) |

## 7. ERD 변경 제안

| # | 변경 | 이유 |
|---|---|---|
| 1 | `image.thumb_size_bytes integer` 추가 (nullable, 썸네일이 없으면 null) | 용량에 썸네일도 센다 (§3). complete에서 이미 두 파일의 크기를 확인하므로(04 ⑤) 저장만 하면 된다 |

```sql
ALTER TABLE image ADD COLUMN thumb_size_bytes integer
    CONSTRAINT ck_image_thumb_size CHECK (thumb_size_bytes IS NULL OR (thumb_size_bytes > 0 AND thumb_size_bytes <= 1048576));
```

사용량 합계는 기존 `ix_image_uploader (uploader_id, created_at DESC)`로 충분하다. 회원 행에 사용량 컬럼을 따로 두지 않는다 (합계와 어긋날 위험).
